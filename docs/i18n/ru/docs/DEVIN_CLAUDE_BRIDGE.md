`devin-cli-agentic` позволяет реальной среде выполнения Claude Code использовать локальную
конечную точку Anthropic Messages от OmniRoute, в то время как официальный Devin CLI
предоставляет ответы модели через ACP stdio. Он не изменяет существующие провайдеры
Anthropic, Claude OAuth, Claude Web или `devin-cli`.

Для вызовов инструментов, выполняемых клиентом, используйте `devin-cli-agentic` (псевдоним `dva`) —
поддерживающий инструменты провайдер в формате Claude. Устаревший исполнитель ACP `devin-cli`
(`dv`) поддерживает только текст: он запускает суммаризатор Devin без инструментов и не может
возвращать вызовы инструментов. Метаданные его модели помечены соответствующим образом, поэтому
комбинированная маршрутизация, требующая инструментов, будет избегать его.

> **Текущее состояние: закреплена версия Claude Code `2.1.258`; последняя офлайн- и онлайн-проверка
> зарегистрирована для `2.1.220`.** Закреплённая версия `2.1.220` успешно прошла три изолированных
> сценария через Devin CLI `3000.2.17` и модель `swe-1-7-lightning`; этот финальный онлайн-запуск
> подтвердил выполнение клиентом операций `Read`, `Edit` и `Bash`, успешные результаты `npm test`,
> обнаружение команд и навыков проекта, маршрутизацию исключительно через Devin и полное отсутствие
> исходящего трафика к Claude. Затем закреплённая версия была повышена до `2.1.258` (поколения CLI,
> под которое OmniRoute имитирует идентичность Claude, и первой линейки с нативной поддержкой уровня
> Fable 5.1). Для новой закреплённой версии на закреплённом базовом образе были проверены слой установки
> и `claude --version`, а также успешно проходят модульный набор тестов моста, `compose config` и
> статическая проверка изоляции, однако офлайн-сценарий с имитацией и онлайн-набор из трёх сценариев
> ещё не запускались повторно. Запустите их повторно (см. «Обновление закреплённых инструментов»),
> прежде чем полагаться на мост с этой закреплённой версией.

## Архитектура

```text
Claude Code 2.1.258 (изолированный Linux-контейнер без прав root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (провайдер в формате Claude без аутентификации)
  -> devin acp --agent-type summarizer (официальный ACP stdio без инструментов Devin)
  -> учётная запись Devin в выделенном томе devin-auth
```

Стандартный ACP-агент официального CLI может выполнять собственные инструменты, поэтому этот мост
его не использует. Он запускает фиксированный ACP-агент `summarizer`, официальный режим CLI которого
не имеет инструментов, и оформляет сериализованный запрос Anthropic как трассировку выполнения.
Когда требуется очередное действие, выполняемое Claude, ответ должен содержать ровно одну клиентскую
оболочку инструмента. Любой ACP `tool_call` или `tool_call_update` отклоняется до того, как ответ
может быть признан успешным.

Сериализатор в `open-sse/executors/devin-agentic/serializer.ts` сохраняет `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` и инструменты,
предоставленные Claude Code. Изображения и неизвестные блоки вызывают явную ошибку. Для больших
результатов инструментов используется видимый маркер усечения.

Парсер принимает одну самостоятельную оболочку `<tool>{...}</tool>` за один ход модели. Он сверяет
имя со списком инструментов запроса, проверяет аргументы по JSON Schema этого инструмента,
отклоняет смешение повествования и действий и допускает одну ограниченную попытку исправления.
Затем Claude Code локально выполняет полученный Anthropic `tool_use` и отправляет `tool_result`
обратно через OmniRoute.

## Автоматическая маршрутизация

Провайдер может участвовать в пулах кандидатов OmniRoute `auto/*`, если он не заблокирован.
Допуск к кандидатам не гарантирует выбор: стратегия маршрутизации комбинации (например,
последний успешно работавший вариант) может предпочесть другого провайдера. Используйте
`dva/<model>` или комбинацию с приоритетом Devin, если требуется, чтобы каждый запрос проходил
через Devin.

## Изоляция и модель угроз

Установка, учётная запись и конфигурация Claude на хосте не входят в область рассмотрения и считаются
запрещёнными. Сервисы Compose:

- работают с UID/GID `10001:10001`, корневой файловой системой только для чтения, сброшенными возможностями и
  `no-new-privileges`;
- используют приватный `/home/bridge`, выделенный том конфигурации Claude, изолированные данные OmniRoute
  и отдельный том `devin-auth`;
- монтируют только одноразовые рабочие пространства и доказательства `.sandbox`;
- не монтируют домашний каталог хоста, Keychain, учётные данные SSH и облачных сервисов или сокет Docker;
- формируют явно заданные окружения и удаляют переменные API/OAuth/маршрутизации Anthropic;
- направляют запросы Claude Code только в `http://omniroute:20128`, используя ключ исключительно для локального доступа.

Офлайн-профиль использует внутреннюю сеть. В активном профиле OmniRoute обращается к
официальным конечным точкам Devin только через `network-guard`; обращения к посторонним адресам запрещены.
Claude Code использует отдельный фильтр исходящего трафика, запрещающий все подключения, и может обращаться только к локальному сервису OmniRoute
через `NO_PROXY`. Файлы аудита фильтров монтируются только в соответствующие процессы фильтрации.
Перед экспортом доказательств, не содержащих токенов, скрипты проверяют владельца файла, режим доступа, количество ссылок
и каждое принятое решение.

Запустите проверку изоляции отдельно:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Она проверяет топологию, именованные точки монтирования, настройки запуска не от имени root и режима только для чтения, явно заданную локальную маршрутизацию,
отсутствие конфиденциальных переменных окружения и сокета Docker, блокировку доступа к
`api.anthropic.com` и `claude.ai`, выбор только провайдера Devin, а также явное завершение с ошибкой,
когда бэкенд ACP недоступен.

## Первоначальная настройка и обычное использование

Соберите образ с зафиксированными версиями:

```bash
./scripts/devin-bridge/build
```

Выполните аутентификацию только для изолированного тома Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Команда входа использует официальный процесс с ручным вводом токена, предназначенный для удалённых и контейнерных
сред. Значение вводится непосредственно в приглашение CLI; оно не передаётся как аргумент
процесса, не записывается в Git и не копируется с хоста.

Запустите изолированную среду выполнения Claude Code:

```bash
./scripts/devin-bridge/launch
```

Перед запуском контейнеризированного Claude Code команда `launch` повторно проверяет изоляцию, аутентификацию Devin
и обнаружение моделей. Она никогда не запускает исполняемый файл Claude с хоста. Псевдонимы моделей можно
задать в `.env.devin-bridge`; каждое настроенное значение должно сохранять префикс
`devin-cli-agentic/`.

## Команды проверки

Воспроизводимый офлайн-сценарий не требует учётной записи Devin и не использует Интернет во время выполнения:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Активный сценарий с аутентификацией, запускаемый только при явном согласии:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Между сценариями средство запуска активных тестов выдерживает паузу, чтобы не открывать сеансы ACP сериями, и
проверяет структурированные события потока Claude, а не полагается на текстовые утверждения. Три
сценария подтверждают:

1. прямое чтение файлов проекта и анализ дефектов;
2. реальный вызов `Edit`, принадлежащий клиенту вызов `Bash` с `npm test` и итоговый результат;
3. обнаружение `/bridge-check` и `bridge-proof`, чтение файлов проекта, ещё один успешный,
   принадлежащий клиенту вызов `npm test` и завершение без ожидающей работы.

Итоговая проверка также анализирует сетевой аудит Devin и требует, чтобы аудит исходящего трафика Claude
оставался пустым.

## Обновление закреплённых инструментов

Образ закрепляет версии Node, Claude Code и Devin CLI в
`docker/devin-bridge/Dockerfile`. Чтобы обновить их:

1. измените явно указанные версии;
2. замените контрольные суммы архивов Devin для обеих архитектур значениями для официального
   артефакта;
3. пересоберите образ и выполните все команды автономной проверки;
4. подтвердите версии внутри образа;
5. повторно запустите аутентифицированный набор из трёх сценариев в реальной среде.

Не устанавливайте ни один из этих CLI глобально на хосте и не заменяйте проверку контрольной суммы
непроверенной загрузкой.

## Диагностика и очистка

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  показывает локальную маршрутизацию и санитизированные ошибки исполнителя.
- `.sandbox/evidence/mock-acp.jsonl` содержит детерминированные действия имитации ACP.
- `.sandbox/evidence/claude-stream.jsonl` содержит результаты реального автономного запуска Claude Code.
- `.sandbox/evidence/live-*.jsonl` содержит три проверенных потока из реальной среды.
- `.sandbox/evidence/egress.jsonl` и `.sandbox/evidence/claude-egress.jsonl` — это проверенные,
  не содержащие токенов копии аудитов исходящего трафика защитного механизма.

Остановите принадлежащие мосту контейнеры и сети, сохранив тома входа и конфигурации:

```bash
./scripts/devin-bridge/clean
```

Удалите всю среду, принадлежащую мосту, включая именованные тома:

```bash
./scripts/devin-bridge/clean --all
```

## Ограничения

- Мост использует фиксированную роль `summarizer` без инструментов, поскольку Devin CLI `3000.2.17`
  не предоставляет нейтрального ACP-агента без инструментов. Адаптер компенсирует промежуточные
  ответы в форме сводки, однако одна ограниченная попытка исправления всё равно может завершиться явной ошибкой.
- Реальные вызовы ACP могут возвращать временные ответы `502`/`504`. Средство тестирования выдерживает
  интервалы между сценариями; при постоянном сбое система остаётся закрытой и никогда не выбирает другого провайдера.
- Контекст ACP реконструируется из каждого запроса Anthropic; привязка к процессу или сеансу
  отсутствует.
- Для каждого ответа модели поддерживается один вызов инструмента; параллельные вызовы отклоняются.
- Изображения явно не поддерживаются. Возможности компьютерного зрения, вывод процесса размышления,
  управление уровнем усилий и окно контекста в 1M не заявлены.
- SSE использует допустимые события жизненного цикла Anthropic, но отправляется после завершения
  ограниченного хода ACP; фрагменты ACP не пересылаются по мере поступления.
