OmniRoute ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ 5-ପଦକ୍ଷେପ ବିଶିଷ୍ଟ ଫଲ୍ବ୍ୟାକ୍ ଶୃଙ୍ଖଳା ମାଧ୍ୟମରେ ଏହାର SQLite ଡ୍ରାଇଭର୍ ସମାଧାନ କରେ:

1. **ବଣ୍ଡଲ୍ କରାଯାଇଥିବା `better-sqlite3`** (`package.json`ରେ `dependencies` ମାଧ୍ୟମରେ)
   — ସବୁଠାରୁ ଦ୍ରୁତ, ନେଟିଭ୍ ବାଇନାରି, ବିଲ୍ଡ ଟୁଲ୍ ଉପଲବ୍ଧ ଥିଲେ `npm install` ଦ୍ୱାରା ଇନ୍ଷ୍ଟଲ୍ ହୁଏ।

2. **ରନ୍ଟାଇମ୍ରେ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା `better-sqlite3`** (`~/.omniroute/runtime/`ରେ)
   — ପ୍ରଥମ ରନ୍ରେ ଆବଶ୍ୟକତା ଅନୁସାରେ **କିମ୍ବା** `scripts/build/postinstall.mjs → scripts/postinstall.mjs` ଦ୍ୱାରା ଇନ୍ଷ୍ଟଲ୍ ହୁଏ।
   କ୍ଷତିଗ୍ରସ୍ତ କିମ୍ବା ଭୁଲ ପ୍ଲାଟଫର୍ମର ବାଇନାରିରୁ ସୁରକ୍ଷା ପାଇବାକୁ ଲୋଡ୍ କରିବା ପୂର୍ବରୁ ନେଟିଭ୍ `.node` ମ୍ୟାଜିକ୍ ବାଇଟ୍ଗୁଡ଼ିକୁ (ELF / Mach-O / PE) ବୈଧ କରେ।

3. **`node:sqlite`** (Node ≥22.5 ମାନକ ଲାଇବ୍ରେରୀ) — କୌଣସି ନେଟିଭ୍ ବିଲ୍ଡ ଆବଶ୍ୟକ ନୁହେଁ; ଉଭୟ better-sqlite3 ପଥ ବିଫଳ ହେଲେ ବ୍ୟବହୃତ ହୁଏ। ସୀମିତ ବୈଶିଷ୍ଟ୍ୟ ସେଟ୍।

4. **`sql.js`** (WASM) — ଶେଷ ଫଲ୍ବ୍ୟାକ୍। ସବୁଠାରେ କାମ କରେ, କିନ୍ତୁ ଧୀର ଏବଂ ସମକାଳୀନ ଭାବରେ ଲେଖିବା ପରିବର୍ତ୍ତେ ନିର୍ଦ୍ଦିଷ୍ଟ ବ୍ୟବଧାନରେ ଡାଟା ଲେଖେ।

## ଏତେ ଜଟିଳତା କାହିଁକି?

- **Windows EBUSY**: ଯଦି ପୂର୍ବ ସଂସ୍କରଣର `better_sqlite3.node` କୌଣସି ଚାଲୁଥିବା ପ୍ରକ୍ରିୟା ଦ୍ୱାରା ଲକ୍ ହୋଇଥାଏ, ତେବେ `npm install -g omniroute@latest` ବିଫଳ ହୋଇପାରେ। `~/.omniroute/runtime/`ରେ ରନ୍ଟାଇମ୍ ଇନ୍ଷ୍ଟଲ୍ ଗ୍ଲୋବାଲ୍ npm କ୍ୟାଶ୍କୁ ଏଡ଼ାଇଯାଏ।
- **ବିଲ୍ଡ ଟୁଲ୍ ନାହିଁ**: କିଛି ପରିବେଶ (`VS Build Tools` ବିନା କର୍ପୋରେଟ୍ Windows, ସର୍ବନିମ୍ନ Docker ଇମେଜ୍) `better-sqlite3` କମ୍ପାଇଲ୍ କରିପାରେ ନାହିଁ। ରନ୍ଟାଇମ୍ ଇନ୍ଷ୍ଟଲର୍ npm ରେଜିଷ୍ଟ୍ରିରୁ ଏକ ପୂର୍ବରୁ ବିଲ୍ଡ ହୋଇଥିବା ବାଇନାରି ସମାଧାନ କରେ; ତାହା ବିଫଳ ହେଲେ ମଧ୍ୟ ଫଲ୍ବ୍ୟାକ୍ ଡ୍ରାଇଭର୍ଗୁଡ଼ିକ OmniRoute ବୁଟ୍ ହେବା ସୁନିଶ୍ଚିତ କରନ୍ତି।
- **ଏୟାର୍-ଗ୍ୟାପ୍ଡ ସିଷ୍ଟମ୍**: npm ରେଜିଷ୍ଟ୍ରି ଉପଲବ୍ଧ ନ ହେଲେ, `node:sqlite` କିମ୍ବା `sql.js` ମୌଳିକ କାର୍ଯ୍ୟକ୍ଷମତା ସୁନିଶ୍ଚିତ କରେ।

## ମ୍ୟାଜିକ୍-ବାଇଟ୍ ବୈଧତା ଯାଞ୍ଚ

ରନ୍ଟାଇମ୍ରେ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା `.node` ଫାଇଲ୍କୁ ଲୋଡ୍ କରିବା ପୂର୍ବରୁ, OmniRoute ପ୍ରଥମ 8ଟି ବାଇଟ୍ ପଢ଼େ ଏବଂ ସେଗୁଡ଼ିକୁ ଜଣାଶୁଣା ପ୍ଲାଟଫର୍ମ ମ୍ୟାଜିକ୍ ସହ ମେଳାଏ:

| ପ୍ଲାଟଫର୍ମ                  | ବାଇଟ୍ (ହେକ୍ସ) | ଲେବଲ୍       |
| -------------------------- | ------------- | ----------- |
| Linux                      | `7F 45 4C 46` | `elf`       |
| macOS 64-ବିଟ୍ BE           | `FE ED FA CF` | `macho`     |
| macOS 64-ବିଟ୍ LE           | `CF FA ED FE` | `macho-le`  |
| macOS ଫ୍ୟାଟ୍ (ୟୁନିଭର୍ସାଲ୍) | `CA FE BA BE` | `macho-fat` |
| Windows                    | `4D 5A` (MZ)  | `pe`        |

ମ୍ୟାଜିକ୍ ମେଳ ନ ହେଲେ → ଫାଇଲ୍ଟିକୁ ଅଣଦେଖା କରାଯାଏ ଏବଂ ଫଲ୍ବ୍ୟାକ୍ ପରବର୍ତ୍ତୀ ପଦକ୍ଷେପକୁ ଜାରି ରହେ।

## ମାନୁଆଲ୍ ନିୟନ୍ତ୍ରଣ

```bash
# ଦ୍ରୁତ CI ଇନ୍ଷ୍ଟଲ୍ ପାଇଁ postinstall ୱାର୍ମ-ଅପ୍ ଛାଡ଼ିଦିଅନ୍ତୁ
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute

# ରନ୍ଟାଇମ୍ better-sqlite3କୁ ବାଧ୍ୟତାମୂଳକ ଭାବେ ପୁନଃଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ
rm -rf ~/.omniroute/runtime
omniroute  # ପରବର୍ତ୍ତୀ ଆରମ୍ଭରେ ପୁନଃଇନ୍ଷ୍ଟଲ୍ ହେବ

# କେଉଁ ଡ୍ରାଇଭର୍ ସକ୍ରିୟ ଅଛି ଯାଞ୍ଚ କରନ୍ତୁ
omniroute config db-info  # (ଯଦି CLI କମାଣ୍ଡ ଉପଲବ୍ଧ ଅଛି)
```

## ସମକାଳୀନ ସ୍ଥଗିତତା ନିର୍ଣ୍ଣୟ କରିବା

`better-sqlite3` ସହିତ, ସମକାଳୀନ ଆଡାପ୍ଟର୍ ଟାଇମିଂକୁ ସକ୍ରିୟ କରିବା ପାଇଁ ଷ୍ଟାର୍ଟଅପ୍ ପୂର୍ବରୁ `OMNIROUTE_SQLITE_SLOW_MS=200` ସେଟ୍ କରନ୍ତୁ। ଡିଫଲ୍ଟ ଭାବେ ଏହା ବନ୍ଦ ଥାଏ। ଅତି କମରେ ସେତିକି ମିଲିସେକେଣ୍ଡ ନେଉଥିବା ଏକ ସମ୍ପୂର୍ଣ୍ଣ ଅପରେସନ୍ ପ୍ରତି ଆଡାପ୍ଟର୍ରେ ପ୍ରତି ଦଶ ସେକେଣ୍ଡରେ ସର୍ବାଧିକ ଥରେ ଏକ `[SQLITE-SLOW]` ଚେତାବନୀ ନିର୍ଗତ କରେ। ଚେତାବନୀରେ କେବଳ ଡ୍ରାଇଭର୍, ଅପରେସନ୍ ଶ୍ରେଣୀ (`prepare`, `get`, `all`, `run`, `exec`, `pragma`, ଟ୍ରାଞ୍ଜାକ୍ସନ୍ କିମ୍ବା ରକ୍ଷଣାବେକ୍ଷଣ), ଏବଂ ବିତିଥିବା ମିଲିସେକେଣ୍ଡ ରହେ: କୌଣସି SQL, ବାଇଣ୍ଡିଂ, ଧାଡ଼ି, ପଥ କିମ୍ବା ଏକ୍ସେପ୍ସନ୍ ଟେକ୍ସ୍ଟ ନୁହେଁ।

ଏହା ଏକ ଡାଇଗ୍ନୋଷ୍ଟିକ୍ ସହାୟକ, ଟାଇମ୍ଆଉଟ୍ କିମ୍ବା କ୍ୱେରି ଅପ୍ଟିମାଇଜେସନ୍ ନୁହେଁ। ଏହା କେବେ ଫେରୁ ନଥିବା ଅପରେସନ୍ ବିଷୟରେ ରିପୋର୍ଟ କରିପାରେ ନାହିଁ, CPU କାର୍ଯ୍ୟକୁ ଡିସ୍କ ଅପେକ୍ଷାରୁ ପୃଥକ କରିପାରେ ନାହିଁ, ସଠିକ୍ SQL ଚିହ୍ନଟ କରିପାରେ ନାହିଁ କିମ୍ବା କଞ୍ଚା ଡ୍ରାଇଭର୍ ହ୍ୟାଣ୍ଡଲ୍ ମାଧ୍ୟମରେ କରାଯାଇଥିବା ଅପରେସନ୍ଗୁଡ଼ିକୁ ନିରୀକ୍ଷଣ କରିପାରେ ନାହିଁ। ଅସମକାଳୀନ ବ୍ୟାକଅପ୍ ଅବଧିକୁ ଜାଣିଶୁଣି ବାଦ ଦିଆଯାଇଛି; ଅନ୍ୟ SQLite ଡ୍ରାଇଭର୍ଗୁଡ଼ିକ ଏହି ବୈକଳ୍ପିକ ସାଧନୀକରଣରେ ଅନ୍ତର୍ଭୁକ୍ତ ନୁହେଁ। ଭେରିଏବଲ୍ଟି ଅକ୍ଷମ କଲେ ଟାଇମିଂ ରାପର୍ ବିନା ମୂଳ ଆଡାପ୍ଟର୍ ପୁନଃସ୍ଥାପିତ ହୁଏ। ଡାଟାବେସ୍ ସ୍କିମା କିମ୍ବା ସଂରକ୍ଷିତ କନଫିଗରେସନ୍ରେ କୌଣସି ପରିବର୍ତ୍ତନ ହୁଏ ନାହିଁ।

`/healthz` ଲ୍ୟାଗ୍ ଚେତାବନୀ ସମଗ୍ର ଜୀବନକାଳର ହାରାହାରି ନୁହେଁ, ବରଂ ପୂର୍ବ ନମୁନା ପରଠାରୁ ଇଭେଣ୍ଟ-ଲୁପ୍ର ସର୍ବୋଚ୍ଚ ମାନ ରିପୋର୍ଟ କରେ। କୌଣସି ସ୍ଥଗିତତାକୁ SQLite କିମ୍ବା ଡିସ୍କ ବିଫଳତା ପାଇଁ ଦାୟୀ କରିବା ପୂର୍ବରୁ ଏହାର ଟାଇମ୍ଷ୍ଟାମ୍ପଗୁଡ଼ିକୁ ଧୀର ଅପରେସନ୍ ଚେତାବନୀ ଏବଂ ହୋଷ୍ଟ/ଷ୍ଟୋରେଜ୍ ମେଟ୍ରିକ୍ସ ସହ ସହସମ୍ବନ୍ଧିତ କରନ୍ତୁ।

## ଏକକ-ଲେଖକ ଟୋପୋଲୋଜି (HA ଅସମର୍ଥିତ)

ଉପରୋକ୍ତ ଡ୍ରାଇଭର୍ ଫଲ୍ବ୍ୟାକ୍ ଶୃଙ୍ଖଳା ତଥାପି **ଗୋଟିଏ ପ୍ରକ୍ରିୟା** ମଧ୍ୟରେ ଚାଲେ। ଡିଫଲ୍ଟ SQLite OmniRoute ଏକ **ଏକକ ଲେଖକ**:

- ଦୁଇଟି OmniRoute ରେପ୍ଲିକାକୁ ସମାନ `storage.sqlite` ଫାଇଲ୍ ସହ ସଂଲଗ୍ନ କରନ୍ତୁ ନାହିଁ।
- ଏକ କଣ୍ଟେନର୍ ରିଷ୍ଟାର୍ଟ, Recreate ଡିପ୍ଲୟ, OOM କିଲ୍, କିମ୍ବା HEALTHCHECK ରିଷ୍ଟାର୍ଟ ପ୍ରତ୍ୟେକ ଚାଲୁଥିବା SSE ସେସନ୍କୁ ବିଚ୍ଛିନ୍ନ କରେ। ମାନକ ପଥରେ କୌଣସି ସେସନ୍ ଡ୍ରେନ୍ ନାହିଁ।
