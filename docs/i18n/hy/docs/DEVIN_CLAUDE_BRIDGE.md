`devin-cli-agentic`-ը թույլ է տալիս իրական Claude Code գործարկման միջավայրին օգտագործել OmniRoute-ի տեղային Anthropic
Messages վերջնակետը, մինչդեռ պաշտոնական Devin CLI-ն մոդելի պատասխանները տրամադրում է ACP stdio-ի միջոցով։ Այն
չի փոփոխում գոյություն ունեցող Anthropic, Claude OAuth, Claude Web կամ `devin-cli` մատակարարները։

Հաճախորդի կողմից կառավարվող գործիքների կանչերի համար երթուղավորեք `devin-cli-agentic`-ի (կեղծանունը՝ `dva`)՝
Claude ձևաչափով գործիքներ աջակցող մատակարարի միջոցով։ Ժառանգական `devin-cli` (`dv`) ACP կատարիչը
միայն տեքստային է․ այն գործարկում է Devin-ի՝ առանց գործիքների ամփոփիչը և չի կարող վերադարձնել գործիքների կանչեր։ Դրա մոդելի
մետատվյալները համապատասխանաբար նշված են, որպեսզի գործիքներ պահանջող համակցված երթուղավորումը խուսափի դրանից։

> **Ընթացիկ կարգավիճակ․ ամրագրված է Claude Code `2.1.258`-ը․ անցանց և առցանց վավերացման վերջին գրանցումը
> կատարվել է `2.1.220`-ի վրա։** `2.1.220` ամրագրումը հաջողությամբ ավարտել է երեք մեկուսացված սցենար Devin CLI
> `3000.2.17`-ի և `swe-1-7-lightning` մոդելի միջոցով․ այդ վերջնական առցանց գործարկումը հաստատել է հաճախորդի կողմից կառավարվող `Read`,
> `Edit` և `Bash` քայլերը, `npm test`-ի հաջող արդյունքները, նախագծի հրամանների ու հմտությունների
> հայտնաբերումը, միայն Devin-ի միջոցով երթուղավորումը և Claude-ի զրոյական արտաքին տրաֆիկը։ Այնուհետև ամրագրումը բարձրացվել է մինչև `2.1.258`
> (CLI-ի այն սերունդը, որի Claude ինքնությունն է նմանակում OmniRoute-ը, և առաջին տարբերակը, որն ի սկզբանե ներառում է
> Fable 5.1 մակարդակը)։ Նոր ամրագրման դեպքում տեղադրման շերտը և `claude --version`-ը
> ստուգվել են ամրագրված բազային պատկերի վրա, իսկ կամրջի միավորային թեստերի հավաքածուն, `compose config`-ը և
> մեկուսացման ստատիկ ապացույցը հաջողությամբ անցնում են, սակայն անցանց կեղծ սցենարը և առցանց երեք սցենարից բաղկացած
> հավաքածուն դեռևս չեն վերագործարկվել։ Վերագործարկեք դրանք (տե՛ս «Ամրագրված գործիքների թարմացում» բաժինը)՝ նախքան
> այս ամրագրմամբ կամրջին ապավինելը։

## Ճարտարապետություն

```text
Claude Code 2.1.258 (մեկուսացված ոչ արմատային Linux կոնտեյներ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude ձևաչափով, նույնականացում չպահանջող մատակարար)
  -> devin acp --agent-type summarizer (պաշտոնական ACP stdio, առանց Devin գործիքների)
  -> Devin հաշիվը՝ հատուկ devin-auth հատորում
```

Պաշտոնական CLI-ի լռելյայն ACP գործակալը կարող է գործարկել իր սեփական գործիքները, ուստի այս կամուրջը չի օգտագործում
այն։ Այն գործարկում է ամրագրված `summarizer` ACP գործակալը, որի պաշտոնական CLI ռեժիմը գործիքներ չունի, և
սերիականացված Anthropic հարցումը ձևակերպում է որպես կատարման հետագիծ։ Երբ անհրաժեշտ է Claude-ի կողմից կառավարվող
մեկ այլ գործողություն, պատասխանը պետք է պարունակի ճիշտ մեկ հաճախորդային գործիքի ծրար։ Ցանկացած ACP
`tool_call` կամ `tool_call_update` մերժվում է՝ նախքան պատասխանը կարող է համարվել
հաջող։

`open-sse/executors/devin-agentic/serializer.ts`-ում գտնվող սերիականացնողը պահպանում է `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` և Claude Code-ի
տրամադրած գործիքները։ Պատկերներն ու անհայտ բլոկները բացահայտ կերպով ձախողվում են։ Գործիքների մեծ արդյունքներում
օգտագործվում է տեսանելի կրճատման նշիչ։

Վերլուծիչն ընդունում է մեկ առանձին `<tool>{...}</tool>` ծրար՝ մոդելի յուրաքանչյուր քայլի համար։ Այն ստուգում է
անունը հարցման գործիքների ցանկի համեմատ, վավերացնում է արգումենտներն այդ գործիքի JSON
Schema-ի համաձայն, մերժում է պատմողական տեքստի և գործողությունների խառնուրդը և թույլ է տալիս մեկ սահմանափակված ուղղում։ Այնուհետև Claude Code-ը
տեղային կերպով կատարում է ստացված Anthropic `tool_use`-ը և `tool_result`-ը հետ է ուղարկում
OmniRoute-ի միջոցով։

## Ինքնաերթուղավորում

Մատակարարը կարող է ընդգրկվել OmniRoute-ի `auto/*` թեկնածուների հավաքածուներում, երբ այն արգելափակված չէ։
Թեկնածու լինելու համապատասխանությունը չի երաշխավորում ընտրությունը․ համակցության երթուղավորման ռազմավարությունը (օրինակ՝
վերջին հաջողված տարբերակը) կարող է նախընտրել մեկ այլ մատակարար։ Օգտագործեք `dva/<model>` կամ Devin-ին առաջնահերթություն տվող համակցություն, երբ
պահանջվում է, որ յուրաքանչյուր հարցում անցնի Devin-ի միջոցով։

## Մեկուսացում և սպառնալիքների մոդել

Հոսթի Claude-ի տեղադրումը, հաշիվը և կազմաձևումը դիտարկման շրջանակից դուրս են և համարվում են
արգելված։ Compose ծառայությունները՝

- գործարկվում են UID/GID `10001:10001`-ով՝ միայն կարդալու համար արմատային ֆայլային համակարգով, հեռացված հնարավորություններով և
  `no-new-privileges`-ով,
- օգտագործում են մասնավոր `/home/bridge`, Claude-ի կազմաձևման հատուկ հատոր, մեկուսացված OmniRoute տվյալներ
  և առանձին `devin-auth` հատոր,
- միացնում են միայն մեկանգամյա օգտագործման `.sandbox` աշխատանքային տարածքներ/ապացույցներ,
- չեն միացնում հոսթի տնային պանակը, Keychain-ը, SSH-ը, ամպային հավատարմագրերը կամ Docker socket-ը,
- կառուցում են հստակ սահմանված միջավայրեր և հեռացնում Anthropic API/OAuth/երթուղավորման փոփոխականները,
- Claude Code-ի ինֆերենցիան ուղղորդում են միայն դեպի `http://omniroute:20128`՝ միայն տեղային բանալիով։

Անցանց պրոֆիլն օգտագործում է ներքին ցանց։ Ուղիղ պրոֆիլում OmniRoute-ը հասանելիություն է ստանում
Devin-ի պաշտոնական վերջնակետերին միայն `network-guard`-ի միջոցով․ կապը այլ նպատակակետերի հետ մերժվում է։
Claude Code-ն ունի արտահոսող ամբողջ երթևեկությունն արգելող առանձին պաշտպանիչ շերտ և `NO_PROXY`-ի միջոցով կարող է հասանելիություն ստանալ միայն տեղային OmniRoute
ծառայությանը։ Պաշտպանիչ շերտերի աուդիտի ֆայլերը միացվում են միայն համապատասխան պաշտպանիչ գործընթացի կողմից։
Սկրիպտները ստուգում են ֆայլի սեփականատիրությունը, ռեժիմը, հղումների քանակը և յուրաքանչյուր որոշում՝ նախքան
թոքեններ չպարունակող ապացույցների արտահանումը։

Մեկուսացման ապացուցման գործընթացը գործարկեք առանձին՝

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Այն ստուգում է տոպոլոգիան, անվանված միացումները, ոչ արմատային օգտատիրոջ/միայն կարդալու կարգավորումները, հստակ սահմանված տեղային երթուղավորումը,
զգայուն միջավայրի փոփոխականների բացակայությունը, Docker socket-ի բացակայությունը, դեպի
`api.anthropic.com` և `claude.ai` հասանելիության արգելափակումը, միայն Devin մատակարարի ընտրությունը և հստակ ձախողումը, երբ
ACP հետնամասը հասանելի չէ։

## Առաջին կարգավորում և սովորական օգտագործում

Կառուցեք ամրագրված պատկերը՝

```bash
./scripts/devin-bridge/build
```

Նույնականացրեք միայն մեկուսացված Devin հատորը՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Մուտքի հրամանն օգտագործում է հեռավար/կոնտեյներային միջավայրերի համար նախատեսված պաշտոնական ձեռքով թոքենի
ընթացակարգը։ Արժեքը մուտքագրվում է անմիջապես CLI-ի հուշման մեջ․ այն չի փոխանցվում որպես
գործընթացի արգումենտ, չի գրվում Git-ում և չի պատճենվում հոսթից։

Գործարկեք մեկուսացված Claude Code աշխատանքային միջավայրը՝

```bash
./scripts/devin-bridge/launch
```

`launch`-ը կրկին ստուգում է մեկուսացումը, Devin-ի նույնականացումը և մոդելների հայտնաբերումը՝ նախքան
կոնտեյներացված Claude Code-ի գործարկումը։ Այն երբեք չի գործարկում հոսթի Claude գործարկելի ֆայլը։ Մոդելների կեղծանունները կարելի է
սահմանել `.env.devin-bridge`-ում․ կազմաձևված յուրաքանչյուր արժեք պետք է պահպանի
`devin-cli-agentic/` նախածանցը։

## Վավերացման հրամաններ

Վերարտադրելի անցանց ուղին չի պահանջում Devin հաշիվ և կատարման ընթացքում չունի համացանցային հասանելիություն՝

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Նույնականացմամբ և կամընտրական միացմամբ ուղիղ ուղին հետևյալն է՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Ուղիղ գործարկիչը սպասում է սցենարների միջև՝ ACP աշխատաշրջանները միանգամից չբացելու համար, և
տեքստային պնդումներին վստահելու փոխարեն վավերացնում է Claude-ի հոսքի կառուցվածքային իրադարձությունները։ Դրա երեք
սցենարներն ապացուցում են՝

1. նախագծի ուղղակի ընթերցում և թերությունների վերլուծություն,
2. իրական `Edit`, հաճախորդի կողմից կառավարվող `Bash` `npm test` և վերջնական արդյունք,
3. `/bridge-check`՝ `bridge-proof`-ի հայտնաբերման հետ միասին, նախագծի ընթերցում, հաճախորդի կողմից կառավարվող ևս մեկ հաջող
   `npm test` և ավարտ՝ առանց առկախ աշխատանքի։

Վերջնական անցակետը նաև ստուգում է Devin-ի ցանցային աուդիտը և պահանջում, որ Claude-ի արտահոսող երթևեկության աուդիտը
մնա դատարկ։

## Ամրակցված գործիքների թարմացում

Պատկերը ամրագրում է Node-ը, Claude Code-ը և Devin CLI-ն
`docker/devin-bridge/Dockerfile`-ում։ Թարմացնելու համար՝

1. փոխեք հստակ նշված տարբերակները,
2. փոխարինեք ճարտարապետություններից յուրաքանչյուրին հատուկ Devin արխիվի երկու ստուգիչ գումարները պաշտոնական արտեֆակտի արժեքներով,
3. վերակառուցեք և գործարկեք անցանց վավերացման բոլոր հրամանները,
4. հաստատեք պատկերի ներսում տարբերակները,
5. կրկին գործարկեք վավերացմամբ երեք սցենարից բաղկացած իրական թեստային փաթեթը։

Մի տեղադրեք CLI-ներից որևէ մեկը հոսթի վրա գլոբալ կերպով և ստուգիչ գումարի վավերացումը մի փոխարինեք
չվավերացված ներբեռնմամբ։

## Ախտորոշում և մաքրում

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ցուցադրում է տեղային երթուղավորումը և կատարիչի մաքրված սխալները։
- `.sandbox/evidence/mock-acp.jsonl`-ը գրանցում է որոշարկված կեղծ ACP գործողությունները։
- `.sandbox/evidence/claude-stream.jsonl`-ը գրանցում է Claude Code-ի իրական անցանց գործարկումը։
- `.sandbox/evidence/live-*.jsonl`-ը գրանցում է վավերացված երեք իրական հոսքերը։
- `.sandbox/evidence/egress.jsonl`-ը և `.sandbox/evidence/claude-egress.jsonl`-ը պահպանակի աուդիտների վավերացված,
  տոկեններից զերծ պատճեններն են։

Կանգնեցրեք պատկանող կոնտեյներներն ու ցանցերը՝ պահպանելով մուտքի/կազմաձևման հատորները․

```bash
./scripts/devin-bridge/clean
```

Հեռացրեք կամրջին պատկանող ամբողջ միջավայրը՝ ներառյալ անվանական հատորները․

```bash
./scripts/devin-bridge/clean --all
```

## Սահմանափակումներ

- Կամուրջը հիմնվում է գործիքներ չունեցող ամրագրված `summarizer` դերի վրա, քանի որ Devin CLI `3000.2.17`-ը
  չի տրամադրում գործիքներ չունեցող չեզոք ACP գործակալ։ Ադապտերը փոխհատուցում է ամփոփման ձև ունեցող
  միջանկյալ պատասխանները, սակայն մեկ սահմանափակ վերականգնման փորձը դեռ կարող է բացահայտ կերպով ձախողվել։
- Իրական ACP կանչերը կարող են վերադարձնել ժամանակավոր `502`/`504` պատասխաններ։ Թեստային համակարգը սցենարների միջև դադարներ է պահպանում,
  իսկ շարունակական ձախողման դեպքում այն մնում է փակ ձախողման վիճակում և երբեք չի ընտրում այլ մատակարար։
- ACP համատեքստը վերակառուցվում է Anthropic-ի յուրաքանչյուր հարցումից․ գործընթացի/աշխատաշրջանի հետ
  կապվածություն չկա։
- Յուրաքանչյուր մոդելի պատասխանի համար աջակցվում է գործիքի մեկ կանչ․ զուգահեռ կանչերը մերժվում են։
- Պատկերները բացահայտորեն չեն աջակցվում։ Տեսողական հնարավորությունները, մտածողության ելքը, ջանքի կառավարման տարրերը և 1M
  համատեքստային պատուհանը չեն գովազդվում։
- SSE-ն օգտագործում է Anthropic-ի վավեր կենսացիկլի իրադարձություններ, սակայն արտածվում է սահմանափակ ACP քայլի
  հավաքագրումից հետո․ ACP հատվածները չեն փոխանցվում աստիճանաբար։
