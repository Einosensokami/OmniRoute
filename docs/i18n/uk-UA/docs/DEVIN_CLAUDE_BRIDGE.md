`devin-cli-agentic` дає змогу справжньому середовищу виконання Claude Code використовувати локальну кінцеву точку Anthropic Messages в OmniRoute, тоді як офіційний Devin CLI надає відповіді моделі через ACP stdio. Він не змінює наявні провайдери Anthropic, Claude OAuth, Claude Web або `devin-cli`.

Для викликів інструментів, якими керує клієнт, спрямовуйте запити через `devin-cli-agentic` (псевдонім `dva`) — провайдер із підтримкою інструментів у форматі Claude. Застарілий виконавець ACP `devin-cli` (`dv`) працює лише з текстом: він запускає сумаризатор Devin без інструментів і не може повертати виклики інструментів. Його метадані моделі позначено відповідним чином, тому комбінована маршрутизація, яка вимагає інструментів, оминатиме його.

> **Поточний стан: закріплено Claude Code `2.1.258`; офлайн- і онлайн-перевірку востаннє зафіксовано
> на `2.1.220`.** Для закріпленої версії `2.1.220` було завершено три ізольовані сценарії через Devin CLI
> `3000.2.17` і модель `swe-1-7-lightning`; цей фінальний онлайн-запуск підтвердив виконання керованих клієнтом операцій `Read`,
> `Edit` і `Bash`, успішні результати `npm test`, виявлення команд і навичок проєкту,
> маршрутизацію виключно через Devin та відсутність вихідного трафіку до Claude. Потім закріплену версію було підвищено до `2.1.258`
> (покоління CLI, за яке видає себе ідентичність Claude в OmniRoute, і перша лінійка з
> нативною підтримкою рівня Fable 5.1). Для нової закріпленої версії на закріпленому базовому образі було
> перевірено шар встановлення та `claude --version`, а набір модульних тестів мосту, `compose config` і
> статична перевірка ізоляції успішно проходять — однак офлайн-сценарій із макетом і
> онлайн-набір із трьох сценаріїв ще не було запущено повторно. Запустіть їх повторно (див. «Оновлення закріплених інструментів»), перш ніж покладатися на
> міст із цією закріпленою версією.

## Архітектура

```text
Claude Code 2.1.258 (ізольований Linux-контейнер без прав root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (провайдер у форматі Claude, без автентифікації)
  -> devin acp --agent-type summarizer (офіційний ACP stdio, без інструментів Devin)
  -> обліковий запис Devin у виділеному томі devin-auth
```

Стандартний агент ACP офіційного CLI може виконувати власні інструменти, тому цей міст його не використовує. Він запускає фіксований агент ACP `summarizer`, офіційний режим CLI якого не має інструментів, і оформлює серіалізований запит Anthropic як трасування виконання. Коли потрібна інша дія, якою керує Claude, відповідь має містити рівно одну клієнтську оболонку інструмента. Будь-які `tool_call` або `tool_call_update` ACP відхиляються до того, як відповідь може бути позначена як успішна.

Серіалізатор у `open-sse/executors/devin-agentic/serializer.ts` зберігає `system`, `text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` та інструменти, надані Claude Code. Зображення й невідомі блоки спричиняють явну помилку. Для великих результатів інструментів використовується видимий маркер усічення.

Парсер приймає одну окрему оболонку `<tool>{...}</tool>` на кожен хід моделі. Він звіряє ім’я зі списком інструментів запиту, перевіряє аргументи за JSON Schema цього інструмента, відхиляє змішування оповіді з діями та дозволяє одну обмежену спробу виправлення. Потім Claude Code локально виконує отриманий Anthropic `tool_use` і надсилає `tool_result` назад через OmniRoute.

## Автоматична маршрутизація

Провайдер може входити до пулів кандидатів `auto/*` в OmniRoute, якщо його не заблоковано. Відповідність критеріям кандидата не гарантує вибору: стратегія маршрутизації комбінації (наприклад,
останній відомий працездатний варіант) може віддавати перевагу іншому провайдеру. Використовуйте `dva/<model>` або комбінацію з пріоритетом Devin, якщо потрібно, щоб кожен запит проходив через Devin.

## Ізоляція та модель загроз

Встановлення, обліковий запис і конфігурація Claude на хості перебувають поза межами розгляду та вважаються забороненими. Сервіси Compose:

- запускаються з UID/GID `10001:10001`, кореневою файловою системою лише для читання, скинутими можливостями та
  `no-new-privileges`;
- використовують приватний `/home/bridge`, окремий том конфігурації Claude, ізольовані дані OmniRoute
  та окремий том `devin-auth`;
- монтують лише одноразові робочі простори/докази `.sandbox`;
- не монтують домашній каталог хоста, Keychain, облікові дані SSH і хмарних сервісів або сокет Docker;
- створюють явні середовища та видаляють змінні API/OAuth/маршрутизації Anthropic;
- спрямовують інференс Claude Code лише до `http://omniroute:20128` із ключем, призначеним тільки для локального використання.

Офлайн-профіль використовує внутрішню мережу. У профілі з доступом до мережі OmniRoute звертається до
офіційних кінцевих точок Devin лише через `network-guard`; доступ до інших адрес заборонено.
Claude Code має окремий захист вихідного трафіку із забороною всього та може звертатися лише до локального сервісу OmniRoute
через `NO_PROXY`. Файли аудиту захисту монтуються лише відповідним процесом захисту.
Скрипти перевіряють власника файлу, режим, кількість посилань і кожне рішення перед експортуванням
доказів без токенів.

Запустіть перевірку ізоляції окремо:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Вона перевіряє топологію, іменовані монтування, налаштування запуску не від root і лише для читання, явну локальну маршрутизацію,
відсутність чутливих змінних середовища, відсутність сокета Docker, блокування доступу до
`api.anthropic.com` і `claude.ai`, вибір лише провайдера Devin та явне завершення з помилкою, коли
бекенд ACP недоступний.

## Початкове налаштування та звичайне використання

Зберіть зафіксований образ:

```bash
./scripts/devin-bridge/build
```

Автентифікуйте лише ізольований том Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Команда входу використовує офіційний потік ручного введення токена, призначений для віддалених/контейнерних
середовищ. Значення вводиться безпосередньо в запит CLI; воно не передається як
аргумент процесу, не записується до Git і не копіюється з хоста.

Запустіть ізольоване середовище виконання Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` повторно перевіряє ізоляцію, автентифікацію Devin і виявлення моделей перед запуском
контейнеризованого Claude Code. Він ніколи не запускає виконуваний файл Claude із хоста. Псевдоніми моделей можна
задати у `.env.devin-bridge`; кожне налаштоване значення має зберігати префікс
`devin-cli-agentic/`.

## Команди перевірки

Відтворюваний офлайн-шлях не потребує облікового запису Devin і не має доступу до Інтернету під час виконання:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Автентифікований опціональний шлях із доступом до мережі:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Засіб запуску перевірок із доступом до мережі робить паузи між сценаріями, щоб уникнути одночасного відкриття багатьох сесій ACP, і
перевіряє структуровані потокові події Claude замість того, щоб покладатися на текстові твердження. Його три
сценарії підтверджують:

1. безпосереднє читання проєкту й аналіз дефектів;
2. справжнє `Edit`, виконання належної клієнту команди `Bash` `npm test` і кінцевий результат;
3. `/bridge-check` разом із виявленням `bridge-proof`, читання проєкту, ще одне успішне
   виконання належної клієнту команди `npm test` і завершення без незакінченої роботи.

Остаточний контрольний етап також перевіряє аудит мережі Devin і вимагає, щоб аудит вихідного трафіку Claude
залишався порожнім.

## Оновлення зафіксованих інструментів

Образ фіксує версії Node, Claude Code та Devin CLI у
`docker/devin-bridge/Dockerfile`. Щоб оновити їх:

1. змініть явно вказані версії;
2. замініть контрольні суми архівів Devin для обох архітектур на значення для офіційного
   артефакту;
3. повторно зберіть образ і виконайте всі команди офлайн-перевірки;
4. підтвердьте версії всередині образу;
5. повторно запустіть автентифікований інтерактивний набір із трьох сценаріїв.

Не встановлюйте жоден із CLI глобально на хості та не замінюйте перевірку контрольної суми
неперевіреним завантаженням.

## Діагностика та очищення

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  показує локальну маршрутизацію та очищені від конфіденційних даних помилки виконавця.
- `.sandbox/evidence/mock-acp.jsonl` містить записи детермінованих дій імітатора ACP.
- `.sandbox/evidence/claude-stream.jsonl` містить запис реального офлайн-запуску Claude Code.
- `.sandbox/evidence/live-*.jsonl` містить записи трьох перевірених інтерактивних потоків.
- `.sandbox/evidence/egress.jsonl` і `.sandbox/evidence/claude-egress.jsonl` — це перевірені
  копії журналів аудиту вихідного трафіку, що не містять токенів.

Зупиніть належні цьому середовищу контейнери та мережі, зберігши томи входу/конфігурації:

```bash
./scripts/devin-bridge/clean
```

Видаліть усе середовище, що належить мосту, включно з іменованими томами:

```bash
./scripts/devin-bridge/clean --all
```

## Обмеження

- Міст використовує фіксовану роль `summarizer` без інструментів, оскільки Devin CLI `3000.2.17`
  не надає нейтрального ACP-агента без інструментів. Адаптер компенсує проміжні відповіді
  у форматі резюме, але одна обмежена спроба виправлення все одно може завершитися явною помилкою.
- Інтерактивні виклики ACP можуть повертати тимчасові відповіді `502`/`504`. Засіб перевірки
  робить паузи між сценаріями; за постійної помилки система залишається закритою для запитів
  і ніколи не вибирає іншого провайдера.
- Контекст ACP відновлюється з кожного запиту Anthropic; прив’язки до процесу/сеансу немає.
- Підтримується один виклик інструмента на відповідь моделі; паралельні виклики відхиляються.
- Зображення явно не підтримуються. Можливості комп’ютерного зору, виведення міркувань,
  керування рівнем зусиль і контекстне вікно на 1 млн токенів не заявляються.
- SSE використовує коректні події життєвого циклу Anthropic, але надсилається після завершення
  обмеженого ходу ACP; фрагменти ACP не передаються поступово.
