Pinapayagan ng `devin-cli-agentic` ang aktuwal na Claude Code runtime na gamitin ang lokal na Anthropic
Messages endpoint ng OmniRoute habang ang opisyal na Devin CLI ang nagbibigay ng mga tugon ng modelo sa pamamagitan ng ACP stdio. Hindi nito
binabago ang mga kasalukuyang Anthropic, Claude OAuth, Claude Web, o `devin-cli` provider.

Para sa mga tool call na pag-aari ng client, idaan sa `devin-cli-agentic` (alias `dva`), ang
tool-capable provider na nasa Claude format. Ang legacy na `devin-cli` (`dv`) ACP executor ay
text-only: pinapatakbo nito ang no-tools summarizer ng Devin at hindi ito makapagbabalik ng mga tool call. Ang metadata ng modelo nito
ay minarkahan nang naaayon upang iwasan ito ng combo routing na nangangailangan ng tool.

> **Kasalukuyang katayuan: naka-pin ang Claude Code `2.1.258`; huling naitala ang offline at live na validation
> sa `2.1.220`.** Nakumpleto ng `2.1.220` pin ang tatlong nakahiwalay na scenario sa pamamagitan ng Devin CLI
> `3000.2.17` at modelong `swe-1-7-lightning`; pinatunayan ng huling live run na iyon ang mga client-owned na `Read`,
> `Edit`, at `Bash` turn, matagumpay na mga resulta ng `npm test`, pagtuklas ng project command at skill,
> routing na para lamang sa Devin, at walang Claude egress. Pagkatapos ay itinaas ang pin sa `2.1.258`
> (ang henerasyon ng CLI na ginagaya ng Claude identity ng OmniRoute, at ang unang linya na native na may kasamang
> Fable 5.1 tier). Sa bagong pin, na-verify ang install layer at `claude --version`
> sa naka-pin na base image, at pumapasa ang bridge unit suite, `compose config`, at ang
> static isolation proof — ngunit hindi pa muling pinatakbo ang offline mock scenario at ang live na three-scenario
> suite. Muling patakbuhin ang mga ito (tingnan ang "Pag-update ng mga naka-pin na tool") bago umasa sa
> bridge gamit ang pin na ito.

## Arkitektura

```text
Claude Code 2.1.258 (nakahiwalay na non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (opisyal na ACP stdio, walang Devin tools)
  -> Devin account sa nakalaang devin-auth volume
```

Maaaring magsagawa ang default na ACP agent ng opisyal na CLI ng sarili nitong mga tool, kaya hindi ito ginagamit ng bridge na ito.
Sinisimulan nito ang nakapirming `summarizer` ACP agent, na walang mga tool sa opisyal nitong CLI mode, at
binabalangkas ang serialized na Anthropic request bilang isang execution trace. Kapag kailangan ng isa pang Claude-owned na
action, dapat maglaman ang tugon ng eksaktong isang client tool envelope. Tinatanggihan ang anumang ACP
`tool_call` o `tool_call_update` bago maiulat ang isang tugon bilang
matagumpay.

Pinapanatili ng serializer sa `open-sse/executors/devin-agentic/serializer.ts` ang `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, at ang
mga tool na ibinigay ng Claude Code. Tahasang nabibigo ang mga image at hindi kilalang block. Gumagamit ang malalaking resulta ng tool
ng nakikitang truncation marker.

Tumatanggap ang parser ng isang standalone na `<tool>{...}</tool>` envelope sa bawat model turn. Sinusuri nito
ang pangalan batay sa listahan ng mga tool sa request, bina-validate ang mga argument batay sa JSON
Schema ng tool na iyon, tinatanggihan ang pinaghalong narrative/action, at pinahihintulutan ang isang bounded repair. Pagkatapos,
lokal na isinasagawa ng Claude Code ang nabuong Anthropic `tool_use` at ibinabalik ang `tool_result` sa pamamagitan ng
OmniRoute.

## Awtomatikong routing

Kuwalipikado ang provider sa mga `auto/*` candidate pool ng OmniRoute kapag hindi ito naka-block.
Hindi ginagarantiyahan ng pagiging kuwalipikado bilang candidate ang pagpili: maaaring mas piliin ng routing strategy ng combo (halimbawa,
last-known-good) ang ibang provider. Gamitin ang `dva/<model>` o isang Devin-first combo kapag
kailangan mong idaan ang bawat request sa Devin.

## Isolation at modelo ng banta

Ang pag-install, account, at configuration ng Claude sa host ay hindi saklaw at itinuturing na
ipinagbabawal. Ang mga serbisyo ng Compose ay:

- tumatakbo bilang UID/GID `10001:10001`, na may read-only na root filesystem, mga inalis na capability, at
  `no-new-privileges`;
- gumagamit ng pribadong `/home/bridge`, nakalaang Claude config volume, nakahiwalay na data ng OmniRoute,
  at hiwalay na volume na `devin-auth`;
- nagma-mount lamang ng mga disposable na `.sandbox` workspace/ebidensya;
- hindi nagma-mount ng home ng host, Keychain, mga credential ng SSH at cloud, o Docker socket;
- bumubuo ng mga tahasang environment at nag-aalis ng mga variable ng Anthropic API/OAuth/routing;
- nagdidirekta ng inference ng Claude Code sa `http://omniroute:20128` lamang gamit ang isang local-only na key.

Gumagamit ang offline na profile ng panloob na network. Sa live na profile, naaabot lamang ng OmniRoute ang
mga opisyal na endpoint ng Devin sa pamamagitan ng `network-guard`; tinatanggihan ang mga walang-kaugnayang destinasyon.
May hiwalay na deny-all na egress guard ang Claude Code at maaari lamang nitong maabot ang lokal na serbisyo ng OmniRoute
sa pamamagitan ng `NO_PROXY`. Ang mga audit file ng guard ay mina-mount lamang ng kani-kanilang proseso ng guard. Bine-verify ng
mga script ang pagmamay-ari ng file, mode, bilang ng link, at bawat desisyon bago mag-export ng
ebidensyang walang token.

Patakbuhin nang hiwalay ang patunay ng isolation:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Vina-validate nito ang topology, mga named mount, mga setting na non-root/read-only, tahasang lokal na routing,
kawalan ng mga sensitibong environment variable, kawalan ng Docker socket, naka-block na access sa
`api.anthropic.com` at `claude.ai`, pagpili ng provider na Devin-only, at tahasang pagkabigo kapag
hindi available ang ACP backend.

## Unang beses na pag-setup at karaniwang paggamit

I-build ang naka-pin na image:

```bash
./scripts/devin-bridge/build
```

I-authenticate lamang ang nakahiwalay na volume ng Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Ginagamit ng login command ang opisyal na manual-token flow na inilaan para sa mga remote/container na
environment. Direktang inilalagay ang value sa CLI prompt; hindi ito ipinapasa bilang
process argument, isinusulat sa Git, o kinokopya mula sa host.

Ilunsad ang nakahiwalay na Claude Code runtime:

```bash
./scripts/devin-bridge/launch
```

Muling sinusuri ng `launch` ang isolation, authentication ng Devin, at pagtuklas ng modelo bago simulan ang
containerized na Claude Code. Hindi nito kailanman pinapatakbo ang Claude executable ng host. Maaaring
itakda ang mga alias ng modelo sa `.env.devin-bridge`; dapat panatilihin ng bawat naka-configure na value ang
prefix na `devin-cli-agentic/`.

## Mga command sa validation

Ang reproducible na offline path ay hindi nangangailangan ng Devin account at walang runtime Internet:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Ang authenticated na opt-in live path ay:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Naghihintay ang live runner sa pagitan ng mga scenario upang maiwasang magbukas ng magkakasunod na ACP session at
vina-validate ang mga structured na Claude stream event sa halip na pagkatiwalaan ang mga textual na pahayag. Pinatutunayan ng tatlong
scenario nito ang:

1. direktang pagbabasa sa proyekto at pagsusuri ng depekto;
2. isang tunay na `Edit`, isang `Bash` `npm test` na pag-aari ng client, at isang terminal na resulta;
3. `/bridge-check` kasama ang pagtuklas sa `bridge-proof`, mga pagbabasa sa proyekto, isa pang matagumpay na
   `npm test` na pag-aari ng client, at pagkumpleto nang walang nakabinbing gawain.

Sinusuri rin ng panghuling gate ang network audit ng Devin at hinihiling na manatiling
walang laman ang egress audit ng Claude.

## Pag-update ng mga naka-pin na tool

Naka-pin sa image ang Node, Claude Code, at Devin CLI sa
`docker/devin-bridge/Dockerfile`. Para mag-update:

1. baguhin ang mga tahasang bersyon;
2. palitan ang parehong checksum ng Devin archive na partikular sa architecture gamit ang mga value para sa opisyal na artifact;
3. muling buuin at patakbuhin ang bawat offline validation command;
4. kumpirmahin ang mga bersyon sa loob ng image;
5. muling patakbuhin ang authenticated na live suite na may tatlong scenario.

Huwag i-install nang global sa host ang alinmang CLI o palitan ang checksum verification ng isang
hindi na-verify na download.

## Diagnosis at paglilinis

- Ipinapakita ng `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ang lokal na routing at mga na-sanitize na executor error.
- Itinatala ng `.sandbox/evidence/mock-acp.jsonl` ang mga deterministic na mock ACP action.
- Itinatala ng `.sandbox/evidence/claude-stream.jsonl` ang tunay na offline run ng Claude Code.
- Itinatala ng `.sandbox/evidence/live-*.jsonl` ang tatlong na-validate na live stream.
- Ang `.sandbox/evidence/egress.jsonl` at `.sandbox/evidence/claude-egress.jsonl` ay mga na-validate
  at token-free na kopya ng mga guard audit.

Ihinto ang mga pagmamay-aring container at network habang pinapanatili ang mga login/config volume:

```bash
./scripts/devin-bridge/clean
```

Alisin ang kumpletong environment na pagmamay-ari ng bridge, kabilang ang mga named volume:

```bash
./scripts/devin-bridge/clean --all
```

## Mga limitasyon

- Umaasa ang bridge sa nakapirming no-tools na `summarizer` role dahil hindi naglalantad ang Devin CLI `3000.2.17`
  ng neutral na no-tools ACP agent. Binabawi ng adapter ang mga intermediate response na anyong summary,
  ngunit maaari pa ring tahasang mabigo ang isang limitadong repair.
- Maaaring magbalik ang mga live ACP call ng pansamantalang `502`/`504` response. Nilalagyan ng pagitan ng harness ang mga scenario;
  ang patuloy na pagkabigo ay nananatiling fail-closed at hindi kailanman pumipili ng ibang provider.
- Muling binubuo ang ACP context mula sa bawat Anthropic request; walang process/session
  affinity.
- Isang tool call ang sinusuportahan sa bawat model response; tinatanggihan ang mga parallel call.
- Tahasang hindi sinusuportahan ang mga image. Hindi ina-advertise ang vision, thinking output, effort controls, at 1M
  context window.
- Gumagamit ang SSE ng mga wastong Anthropic lifecycle event ngunit inilalabas ang mga ito pagkatapos makolekta ang limitadong ACP turn;
  hindi ipinapasa nang incremental ang mga ACP chunk.
