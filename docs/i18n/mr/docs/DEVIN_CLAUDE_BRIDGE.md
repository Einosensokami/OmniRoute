`devin-cli-agentic` मुळे प्रत्यक्ष Claude Code रनटाइम OmniRoute चा स्थानिक Anthropic
Messages एंडपॉइंट वापरू शकतो, तर अधिकृत Devin CLI ACP stdio वरून मॉडेल प्रतिसाद पुरवतो. तो
विद्यमान Anthropic, Claude OAuth, Claude Web किंवा `devin-cli` प्रोव्हायडर्समध्ये बदल करत नाही.

क्लायंटच्या मालकीच्या टूल कॉल्ससाठी, Claude-स्वरूपातील टूल-सक्षम प्रोव्हायडर
`devin-cli-agentic` (उपनाव `dva`) द्वारे रूट करा. जुना `devin-cli` (`dv`) ACP एक्झिक्युटर
केवळ-मजकूर आहे: तो Devin चा टूल्स-विरहित समरायझर चालवतो आणि टूल कॉल्स परत करू शकत नाही. त्याचा मॉडेल
मेटाडेटा त्यानुसार चिन्हांकित केला आहे, त्यामुळे टूल्स आवश्यक असलेले कॉम्बो रूटिंग त्याला टाळेल.

> **सध्याची स्थिती: Claude Code `2.1.258` वर पिन केलेले; ऑफलाइन आणि लाइव्ह प्रमाणीकरणाची शेवटची नोंद
> `2.1.220` वर झाली.** `2.1.220` पिनने Devin CLI
> `3000.2.17` आणि मॉडेल `swe-1-7-lightning` द्वारे तीन विलग परिस्थिती पूर्ण केल्या; त्या अंतिम लाइव्ह रनने क्लायंटच्या मालकीच्या `Read`,
> `Edit`, आणि `Bash` टर्न्स, यशस्वी `npm test` निकाल, प्रोजेक्ट कमांड आणि स्किल
> डिस्कव्हरी, केवळ-Devin रूटिंग आणि शून्य Claude इग्रेस सिद्ध केले. त्यानंतर पिन `2.1.258` पर्यंत वाढवण्यात आला
> (OmniRoute ची Claude ओळख ज्या CLI पिढीचे अनुकरण करते आणि Fable 5.1 स्तर मूळतः पुरवणारी पहिली आवृत्ती).
> नवीन पिनवर पिन केलेल्या बेस इमेजवर इन्स्टॉल स्तर आणि `claude --version`
> सत्यापित करण्यात आले, तसेच ब्रिज युनिट संच, `compose config` आणि
> स्थिर विलगीकरण पुरावा उत्तीर्ण झाले — परंतु ऑफलाइन मॉक परिस्थिती आणि लाइव्ह तीन-परिस्थिती
> संच अद्याप पुन्हा चालवलेले नाहीत. या पिनसह ब्रिजवर अवलंबून राहण्यापूर्वी ते पुन्हा चालवा ("पिन केलेली साधने अद्ययावत करणे" पहा).

## आर्किटेक्चर

```text
Claude Code 2.1.258 (विलग नॉन-रूट Linux कंटेनर)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-स्वरूप, प्रमाणीकरण-विरहित प्रोव्हायडर)
  -> devin acp --agent-type summarizer (अधिकृत ACP stdio, Devin टूल्स नाहीत)
  -> समर्पित devin-auth व्हॉल्यूममधील Devin खाते
```

अधिकृत CLI चा डीफॉल्ट ACP एजंट स्वतःची टूल्स कार्यान्वित करू शकतो, त्यामुळे हा ब्रिज त्याचा वापर करत
नाही. तो निश्चित `summarizer` ACP एजंट सुरू करतो, ज्याच्या अधिकृत CLI मोडमध्ये टूल्स नसतात, आणि
क्रमबद्ध Anthropic विनंतीला एक्झिक्युशन ट्रेस म्हणून संरचित करतो. Claude च्या मालकीची आणखी एखादी
कृती आवश्यक असताना, प्रतिसादात नेमका एक क्लायंट टूल एन्व्हलप असणे आवश्यक आहे. कोणताही ACP
`tool_call` किंवा `tool_call_update` प्रतिसाद यशस्वी म्हणून नोंदवण्यापूर्वी नाकारला जातो.

`open-sse/executors/devin-agentic/serializer.ts` मधील सिरियलायझर `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, आणि
Claude Code ने पुरवलेली टूल्स जतन करतो. इमेजेस आणि अज्ञात ब्लॉक्स स्पष्टपणे अपयशी ठरतात. मोठ्या टूल निकालांसाठी
दृश्यमान ट्रंकेशन मार्कर वापरला जातो.

पार्सर प्रत्येक मॉडेल टर्नमध्ये एक स्वतंत्र `<tool>{...}</tool>` एन्व्हलप स्वीकारतो. तो
विनंतीच्या टूल सूचीशी नाव तपासतो, त्या टूलच्या JSON
Schema विरुद्ध आर्ग्युमेंट्सचे प्रमाणीकरण करतो, मिश्र निवेदन/कृती नाकारतो आणि एक मर्यादित दुरुस्ती अनुमत करतो. त्यानंतर Claude Code
परिणामी Anthropic `tool_use` स्थानिकरीत्या कार्यान्वित करतो आणि `tool_result` OmniRoute द्वारे
परत पाठवतो.

## स्वयंचलित रूटिंग

प्रोव्हायडर ब्लॉक केलेला नसताना तो OmniRoute च्या `auto/*` उमेदवार पूलमध्ये पात्र असतो.
उमेदवार पात्रता निवडीची हमी देत नाही: कॉम्बोची रूटिंग रणनीती (उदाहरणार्थ,
शेवटचा-ज्ञात-योग्य) इतर प्रोव्हायडरला प्राधान्य देऊ शकते. प्रत्येक विनंती Devin द्वारेच जावी
अशी आवश्यकता असल्यास `dva/<model>` किंवा Devin-प्रथम कॉम्बो वापरा.

## विलगीकरण आणि धोका मॉडेल

होस्टवरील Claude इंस्टॉलेशन, खाते आणि कॉन्फिगरेशन व्याप्तीबाहेर आहेत आणि निषिद्ध मानले जातात. Compose सेवा:

- केवळ-वाचनीय रूट फाइलसिस्टम, वगळलेल्या capabilities आणि `no-new-privileges` सह UID/GID `10001:10001` म्हणून चालतात;
- खासगी `/home/bridge`, समर्पित Claude config volume, विलग केलेला OmniRoute डेटा आणि स्वतंत्र `devin-auth` volume वापरतात;
- केवळ वापरानंतर टाकून देता येणारी `.sandbox` workspaces/evidence माउंट करतात;
- होस्टचे home, Keychain, SSH, cloud credentials किंवा Docker socket माउंट करत नाहीत;
- स्पष्ट environments तयार करतात आणि Anthropic API/OAuth/routing variables काढून टाकतात;
- Claude Code inference केवळ स्थानिक-कीसह `http://omniroute:20128` कडे निर्देशित करतात.

ऑफलाइन प्रोफाइल अंतर्गत नेटवर्क वापरते. लाइव्ह प्रोफाइलमध्ये, OmniRoute केवळ `network-guard` द्वारे अधिकृत Devin endpoints पर्यंत पोहोचते; असंबंधित destinations नाकारले जातात. Claude Code साठी स्वतंत्र deny-all egress guard आहे आणि ते केवळ `NO_PROXY` द्वारे स्थानिक OmniRoute सेवेशी संपर्क साधू शकते. Guard audit files केवळ त्यांच्या guard process द्वारे माउंट केल्या जातात. टोकन-मुक्त evidence export करण्यापूर्वी scripts फाइलची मालकी, mode, link count आणि प्रत्येक निर्णयाची पडताळणी करतात.

विलगीकरणाचा पुरावा स्वतंत्रपणे चालवा:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

हे topology, named mounts, non-root/read-only settings, स्पष्ट local routing, संवेदनशील environment variables ची अनुपस्थिती, Docker socket ची अनुपस्थिती, `api.anthropic.com` आणि `claude.ai` वरील अवरोधित प्रवेश, केवळ-Devin provider selection आणि ACP backend अनुपलब्ध असताना स्पष्ट अपयश यांची पडताळणी करते.

## प्रथमच सेटअप आणि सामान्य वापर

पिन केलेली image build करा:

```bash
./scripts/devin-bridge/build
```

केवळ विलग केलेले Devin volume प्रमाणित करा:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Login command दूरस्थ/container environments साठी असलेला अधिकृत manual-token flow वापरते. मूल्य थेट CLI prompt मध्ये प्रविष्ट केले जाते; ते process argument म्हणून दिले जात नाही, Git मध्ये लिहिले जात नाही किंवा होस्टवरून कॉपी केले जात नाही.

विलग केलेला Claude Code runtime सुरू करा:

```bash
./scripts/devin-bridge/launch
```

Containerized Claude Code सुरू करण्यापूर्वी `launch` विलगीकरण, Devin authentication आणि model discovery पुन्हा तपासते. ते होस्टचे Claude executable कधीही चालवत नाही. Model aliases `.env.devin-bridge` मध्ये सेट करता येतात; कॉन्फिगर केलेल्या प्रत्येक मूल्याने `devin-cli-agentic/` prefix कायम ठेवणे आवश्यक आहे.

## प्रमाणीकरण commands

पुनरुत्पादनीय offline path साठी Devin account आवश्यक नाही आणि त्यामध्ये runtime Internet नाही:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणित opt-in live path असा आहे:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP sessions एकाच वेळी मोठ्या संख्येने उघडणे टाळण्यासाठी live runner विविध scenarios दरम्यान प्रतीक्षा करतो आणि मजकूररूपी दाव्यांवर विश्वास ठेवण्याऐवजी संरचित Claude stream events प्रमाणित करतो. त्याची तीन scenarios पुढील बाबी सिद्ध करतात:

1. थेट project reads आणि defect analysis;
2. प्रत्यक्ष `Edit`, client-owned `Bash` `npm test` आणि terminal result;
3. `/bridge-check` तसेच `bridge-proof` discovery, project reads, आणखी एक यशस्वी client-owned `npm test` आणि कोणतेही काम प्रलंबित न ठेवता completion.

अंतिम gate Devin network audit देखील तपासते आणि Claude egress audit रिकामे राहणे आवश्यक ठरवते.

## पिन केलेली साधने अद्ययावत करणे

इमेजमध्ये Node, Claude Code आणि Devin CLI यांच्या आवृत्त्या
`docker/devin-bridge/Dockerfile` मध्ये पिन केलेल्या आहेत. अद्ययावत करण्यासाठी:

1. स्पष्टपणे नमूद केलेल्या आवृत्त्या बदला;
2. आर्किटेक्चरनुसार असलेले दोन्ही Devin संग्रह checksum अधिकृत artifact च्या मूल्यांनी बदला;
3. पुन्हा बिल्ड करा आणि प्रत्येक ऑफलाइन प्रमाणीकरण कमांड चालवा;
4. इमेजमधील आवृत्त्यांची पुष्टी करा;
5. प्रमाणीकरण केलेला तीन-परिस्थितींचा लाइव्ह संच पुन्हा चालवा.

होस्टवर कोणतेही CLI जागतिक स्तरावर इन्स्टॉल करू नका किंवा checksum पडताळणीऐवजी
पडताळणी न केलेले डाउनलोड वापरू नका.

## निदान आणि साफसफाई

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानिक राउटिंग आणि संवेदनशील माहिती काढून टाकलेल्या executor त्रुटी दाखवते.
- `.sandbox/evidence/mock-acp.jsonl` मध्ये निर्धारक mock ACP क्रियांची नोंद असते.
- `.sandbox/evidence/claude-stream.jsonl` मध्ये प्रत्यक्ष Claude Code ऑफलाइन रनची नोंद असते.
- `.sandbox/evidence/live-*.jsonl` मध्ये प्रमाणीकरण केलेल्या तीन लाइव्ह स्ट्रीमची नोंद असते.
- `.sandbox/evidence/egress.jsonl` आणि `.sandbox/evidence/claude-egress.jsonl` या guard ऑडिटच्या
  प्रमाणीकरण केलेल्या, टोकन-विरहित प्रती आहेत.

- ब्रिज निश्चित no-tools `summarizer` भूमिकेवर अवलंबून आहे, कारण Devin CLI `3000.2.17`
  तटस्थ no-tools ACP agent उपलब्ध करून देत नाही. adapter सारांशाच्या स्वरूपातील
  मध्यवर्ती प्रतिसादांची भरपाई करतो, परंतु एक मर्यादित दुरुस्ती तरीही स्पष्टपणे अयशस्वी होऊ शकते.
- लाइव्ह ACP कॉल्समधून तात्पुरते `502`/`504` प्रतिसाद मिळू शकतात. harness परिस्थितींमध्ये अंतर ठेवतो;
  सततचे अपयश fail-closed राहते आणि कधीही दुसरा provider निवडत नाही.
- प्रत्येक Anthropic विनंतीमधून ACP context पुन्हा तयार केला जातो; कोणतेही process/session
  affinity नाही.
- प्रत्येक model प्रतिसादासाठी एक tool call समर्थित आहे; समांतर calls नाकारले जातात.
- Images स्पष्टपणे असमर्थित आहेत. Vision, thinking output, effort controls आणि 1M
  context window यांची उपलब्धता दर्शवली जात नाही.
- SSE वैध Anthropic lifecycle events वापरते, परंतु मर्यादित ACP turn संकलित झाल्यानंतर ते
  उत्सर्जित केले जातात; ACP chunks वाढीव पद्धतीने पुढे पाठवले जात नाहीत.
