> Alternâncias em tempo de execução que alteram o comportamento do OmniRoute **sem uma nova implantação**.
> Todas as flags listadas aqui estão definidas em
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — a única fonte da verdade. Tanto o painel quanto a API REST leem
> esse arquivo, portanto a tabela abaixo é gerada para corresponder a ele na proporção de 1:1.

---

## O que são feature flags

Uma feature flag é uma alternância nomeada (booleana ou enum) cujo valor pode ser alterado em
tempo de execução e persistido no banco de dados, sem exigir uma nova implantação do processo. Cada
flag é descrita por uma `FeatureFlagDefinition` com uma `key`, `label`,
`description`, `category`, `defaultValue`, `type` e uma indicação `requiresRestart`.

### Ordem de resolução

O **valor efetivo** de uma flag é resolvido por
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) com esta
precedência (a mais alta prevalece):

1. **Substituição no banco de dados** — um valor armazenado na tabela `key_value` sob o
   namespace `feature_flags` (definido pelo painel ou pela API REST).
2. **Variável de ambiente** — `process.env[<KEY>]`, caso esteja definida e não esteja vazia.
3. **Valor padrão da definição** — o `defaultValue` de `featureFlagDefinitions.ts`.

Uma flag booleana é considerada **habilitada** quando seu valor efetivo é `"true"`,
`"1"` ou `"yes"` (consulte `isFeatureFlagEnabled()`).

> [!NOTE]
> A maioria das flags também possui uma variável de ambiente correspondente com o **mesmo nome**,
> documentada em [`ENVIRONMENT.md`](./ENVIRONMENT.md). A substituição da flag no banco de dados
> tem precedência sobre essa variável de ambiente. Uma flag com
> `requiresRestart: true` é persistida imediatamente, mas só é lida novamente na inicialização
> do processo — alterná-la exibe um banner **"Reiniciar servidor"** no painel.

usado quando não há uma substituição no DB nem uma variável de ambiente presente.

| `CONTENT_POLICY_REFUSAL_COMBO_STOP_ENABLED`    | boolean | `false` |                 | Quando um destino de uma combinação responde com uma recusa exata por política de conteúdo (`code`/`type` `cyber_policy` ou `content_policy_violation`), interrompe a combinação e retorna essa recusa mesmo quando os destinos restantes são modelos diferentes, em vez de avançar para o próximo destino (#15917). Desativado por padrão: a recusa nunca coloca a conta em espera nem aciona o circuit breaker do provedor; destinos restantes do mesmo modelo ainda interrompem a execução, e uma combinação heterogênea avança para o próximo destino exatamente como qualquer outro erro 400 restrito à solicitação.                                                                                                                                                         |
| `NATIVE_CODEX_REACTIVE_COMPACTION_ENABLED`     | boolean | `false` |                 | Permite que as etapas de compactação de contexto reativa (por limite) e de último recurso também reescrevam históricos de passthrough nativos do Codex (`POST /v1/responses` para o provedor `codex`) quando excederem o orçamento de contexto, usando o adaptador `input[]` de Responses. Desativado por padrão: os históricos nativos do Codex pertencem ao cliente Codex e nunca são reescritos pela compactação; solicitações grandes demais continuam falhando na verificação do orçamento de contexto exatamente como antes. Exige que a compactação global esteja ativada e que o modelo não esteja excluído.                                                                                                                                                              |
| `COOLDOWN_RETRY_SKIP_REFUSALS_ENABLED`         | boolean | `false` |                 | Quando todas as contas estão em período de espera e o período que termina primeiro foi causado por um 403 (acesso recusado) ou um 410 (recurso removido), retorna essa recusa imediatamente em vez de aguardar o término do período e reenviar a solicitação (#16305). Um 403 de cota renovável do agentrouter, restrito à conexão, é então persistido com `errorCode` 429 para continuar elegível para nova tentativa. Desativado por padrão: somente um 401 ignora a espera, e cada recusa é persistida com o status com que chegou.                                                                                                                                                                                                                                            |
| `QUOTA_WINDOW_BOUNDED_PARK`                    | boolean | `false` |                 | Permite que a política de cota por janela (limites de sessão/semanais usados pela seleção de contas) respeite o bloqueio limitado por esgotamento (#17000): assim que o prazo máximo de bloqueio tiver passado, ou a observação em cache for mais antiga que o limite do bloqueio, a janela deixa de excluir a conta até uma nova consulta de cota. Desativado por padrão: uma janela em cache continua bloqueando com base no último percentual informado até o próprio horário de redefinição.                                                                                                                                                                                                                                                                                  |
| `IMAGE_GENERATION_LONG_JOBS`                   | boolean | `false` |                 | Para geração de imagens compatível com OpenAI (#16260): usa o tempo limite da conexão (`providerSpecificData.timeoutMs`) ou, se ausente, o tempo limite central de busca no upstream (`FETCH_TIMEOUT_MS` → `REQUEST_TIMEOUT_MS` → padrão de 600 s), em vez do orçamento fixo de 120 s para imagens; responde com 499 quando o solicitante cancela; permite que o Playground receba trabalhos longos de geração de imagens como um stream SSE com sinais periódicos de keepalive. Desativado por padrão: o orçamento fixo é aplicado e o cancelamento pelo solicitante não é propagado. O prazo que abrange a leitura do corpo da resposta está sempre ativo.                                                                                                                      |

## Alternando Flags

### Dashboard

Navegue até **Dashboard → Configurações → Flags de Funcionalidade**
(`/dashboard/settings/feature-flags`). A grade
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
oferece:

- **Pesquisa** por chave ou descrição e **filtro** por categoria (além de uma visualização sintética
  **Requer Reinicialização**).
- Um **botão de alternância** para flags booleanas e uma **lista suspensa** para flags de enumeração
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Um **emblema de origem** por flag — `DB`, `ENV` ou `DEF` — que mostra de onde veio o
  valor efetivo.
- Um botão **Redefinir** (exibido somente para flags cuja origem é `DB`) para remover a sobrescrita
  e um botão **Redefinir Todas as Sobrescritas** na parte inferior.
- Um banner **Reiniciar Servidor** quando uma flag `requiresRestart` é alterada.

### API REST

Todas as operações passam por uma única rota:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Cada método exige uma sessão autenticada no dashboard (caso contrário, retorna `401`).

#### `GET /api/settings/feature-flags`

Retorna todas as flags com seus valores efetivos, origens e um resumo.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... todas as 108 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Define ou remove uma única sobrescrita. Corpo: `{ key: string; value?: string }`.
Omitir `value` remove a sobrescrita (restaurando o valor de env / padrão).

```bash
# Define uma sobrescrita no DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove a sobrescrita (sem "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A resposta retorna os novos `effectiveValue`/`source`, os valores `previousValue`/
`previousSource` e `requiresRestart`. Chaves desconhecidas e valores de enumeração
fora do intervalo são rejeitados com `400`.

#### `DELETE /api/settings/feature-flags`

Remove **todas** as sobrescritas do DB de uma só vez, restaurando cada flag para seu valor de env / padrão.
Retorna `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flags com `requiresRestart: true` só entram em vigor após a reinicialização do processo.
> O fluxo de reinicialização do dashboard chama `POST /api/restart` e, em seguida, consulta
> `GET /api/health/ping` até que o servidor esteja novamente disponível.

## Fallback Emergencial de Orçamento

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, padrão `true`) controla o
fluxo de fallback gratuito emergencial em
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Quando habilitado, as solicitações que esgotam seu orçamento são encaminhadas para um
provedor/modelo de fallback gratuito, em vez de falharem imediatamente. Defina-o como
`false` (ou `0`) — por meio da opção no painel, de uma substituição no banco de dados ou da
variável de ambiente `OMNIROUTE_EMERGENCY_FALLBACK` — para desabilitar esse comportamento
e permitir que as solicitações com orçamento esgotado falhem. (Disponibilizado como uma
opção no painel nos PRs #3741 / #3752.)

Uma resposta fornecida por esse fallback inclui
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, permitindo
que um cliente identifique que ela foi redirecionada sem precisar comparar
`X-OmniRoute-Provider` com sua solicitação. O cabeçalho não está presente em nenhuma
outra resposta.
