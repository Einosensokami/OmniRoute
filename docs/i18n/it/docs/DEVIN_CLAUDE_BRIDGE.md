`devin-cli-agentic` consente al runtime reale di Claude Code di usare l'endpoint Anthropic
Messages locale di OmniRoute, mentre la CLI ufficiale di Devin fornisce le risposte del modello tramite ACP stdio. Non
modifica i provider Anthropic, Claude OAuth, Claude Web o `devin-cli` esistenti.

Per le chiamate agli strumenti gestite dal client, usa `devin-cli-agentic` (alias `dva`),
il provider con supporto per gli strumenti in formato Claude. L'esecutore ACP legacy `devin-cli` (`dv`) è
solo testuale: esegue il riepilogatore senza strumenti di Devin e non può restituire chiamate agli strumenti. I metadati
del suo modello sono contrassegnati di conseguenza, in modo che il routing combinato che richiede strumenti lo eviti.

> **Stato attuale: Claude Code `2.1.258` bloccato; ultima convalida offline e live registrata
> sulla versione `2.1.220`.** Il blocco alla versione `2.1.220` ha completato tre scenari isolati tramite Devin CLI
> `3000.2.17` e il modello `swe-1-7-lightning`; l'esecuzione live finale ha verificato turni `Read`,
> `Edit` e `Bash` gestiti dal client, risultati positivi di `npm test`, il rilevamento dei comandi e delle skill
> del progetto, il routing esclusivamente tramite Devin e l'assenza totale di traffico in uscita verso Claude. Il blocco è stato quindi aggiornato a `2.1.258`
> (la generazione della CLI che l'identità Claude di OmniRoute impersona e la prima linea che include
> nativamente il livello Fable 5.1). Con il nuovo blocco, il livello di installazione e `claude --version` sono stati
> verificati sull'immagine di base bloccata; inoltre, la suite di unit test del bridge, `compose config` e la
> verifica statica dell'isolamento hanno esito positivo, ma lo scenario mock offline e la suite live con tre scenari
> non sono ancora stati rieseguiti. Rieseguili (vedi "Aggiornamento degli strumenti bloccati") prima di fare affidamento sul
> bridge con questa versione.

## Architettura

```text
Claude Code 2.1.258 (container Linux isolato non root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (formato Claude, provider senza autenticazione)
  -> devin acp --agent-type summarizer (ACP stdio ufficiale, senza strumenti Devin)
  -> account Devin nel volume devin-auth dedicato
```

L'agente ACP predefinito della CLI ufficiale può eseguire i propri strumenti, quindi questo bridge non lo
usa. Avvia l'agente ACP fisso `summarizer`, la cui modalità CLI ufficiale non dispone di strumenti, e
struttura la richiesta Anthropic serializzata come una traccia di esecuzione. Quando è necessaria un'altra
azione gestita da Claude, la risposta deve contenere esattamente un envelope per strumenti del client. Qualsiasi
`tool_call` o `tool_call_update` ACP viene rifiutato prima che una risposta possa essere indicata come
riuscita.

Il serializzatore in `open-sse/executors/devin-agentic/serializer.ts` conserva `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` e gli
strumenti forniti da Claude Code. Le immagini e i blocchi sconosciuti causano un errore esplicito. I risultati degli strumenti
di grandi dimensioni usano un indicatore di troncamento visibile.

Il parser accetta un solo envelope autonomo `<tool>{...}</tool>` per turno del modello. Verifica
il nome rispetto all'elenco degli strumenti della richiesta, convalida gli argomenti rispetto al JSON
Schema dello strumento, rifiuta la combinazione di testo narrativo e azioni e consente un solo tentativo di correzione limitato. Claude Code
esegue quindi localmente il `tool_use` Anthropic risultante e invia il `tool_result` a OmniRoute.

## Routing automatico

Il provider è idoneo nei pool di candidati `auto/*` di OmniRoute quando non è bloccato.
L'idoneità come candidato non garantisce la selezione: la strategia di routing della combinazione (ad esempio,
l'ultimo provider noto come funzionante) può preferire un altro provider. Usa `dva/<model>` o una combinazione con Devin
come prima scelta quando richiedi che ogni richiesta passi attraverso Devin.

## Isolamento e modello di minaccia

L'installazione, l'account e la configurazione di Claude sull'host non rientrano nell'ambito e sono considerati
vietati. I servizi Compose:

- vengono eseguiti come UID/GID `10001:10001`, con un file system root di sola lettura, capability rimosse e
  `no-new-privileges`;
- utilizzano una directory `/home/bridge` privata, un volume dedicato per la configurazione di Claude, dati OmniRoute isolati
  e un volume `devin-auth` separato;
- montano esclusivamente spazi di lavoro/prove `.sandbox` monouso;
- non montano la home dell'host, il Keychain, le credenziali SSH o cloud né il socket Docker;
- costruiscono ambienti espliciti e rimuovono le variabili API/OAuth/di instradamento di Anthropic;
- indirizzano l'inferenza di Claude Code esclusivamente a `http://omniroute:20128` con una chiave solo locale.

Il profilo offline utilizza una rete interna. Nel profilo live, OmniRoute raggiunge gli
endpoint ufficiali di Devin esclusivamente tramite `network-guard`; le destinazioni non correlate vengono negate.
Claude Code dispone di una protezione egress separata che nega tutto e può raggiungere esclusivamente il servizio OmniRoute
locale tramite `NO_PROXY`. I file di audit delle protezioni vengono montati esclusivamente dal rispettivo processo di protezione. Gli
script verificano proprietà, modalità, numero di collegamenti e ogni decisione prima di esportare
prove prive di token.

Eseguire in modo indipendente la verifica dell'isolamento:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Convalida la topologia, i mount denominati, le impostazioni non-root/sola lettura, l'instradamento locale esplicito,
l'assenza di variabili d'ambiente sensibili, l'assenza del socket Docker, l'accesso bloccato ad
`api.anthropic.com` e `claude.ai`, la selezione del provider esclusivamente Devin e l'errore esplicito quando
il backend ACP non è disponibile.

## Configurazione iniziale e utilizzo normale

Creare l'immagine con versioni fissate:

```bash
./scripts/devin-bridge/build
```

Autenticare esclusivamente il volume Devin isolato:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Il comando di accesso utilizza il flusso ufficiale con token manuale, destinato agli ambienti
remoti/container. Il valore viene inserito direttamente nel prompt della CLI; non viene passato come
argomento del processo, scritto in Git o copiato dall'host.

Avviare il runtime isolato di Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` verifica nuovamente l'isolamento, l'autenticazione Devin e il rilevamento dei modelli prima di avviare Claude Code
nel container. Non esegue mai l'eseguibile Claude dell'host. Gli alias dei modelli possono essere
impostati in `.env.devin-bridge`; ogni valore configurato deve mantenere il
prefisso `devin-cli-agentic/`.

## Comandi di convalida

Il percorso offline riproducibile non richiede alcun account Devin e non dispone di accesso a Internet durante l'esecuzione:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Il percorso live autenticato e attivabile esplicitamente è:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Il runner live attende tra gli scenari per evitare di aprire sessioni ACP in rapida successione e
convalida gli eventi strutturati del flusso Claude anziché considerare attendibili le affermazioni testuali. I suoi tre
scenari dimostrano:

1. letture dirette del progetto e analisi dei difetti;
2. un vero `Edit`, un `Bash` `npm test` di proprietà del client e un risultato terminale;
3. `/bridge-check` insieme al rilevamento di `bridge-proof`, letture del progetto, un altro
   `npm test` di proprietà del client completato correttamente e la conclusione senza attività in sospeso.

Il controllo finale verifica inoltre l'audit di rete di Devin e richiede che l'audit egress di Claude
rimanga vuoto.

## Aggiornamento degli strumenti con versione fissata

L'immagine fissa le versioni di Node, Claude Code e Devin CLI in
`docker/devin-bridge/Dockerfile`. Per aggiornarle:

1. modificare le versioni esplicite;
2. sostituire entrambi i checksum degli archivi Devin specifici per architettura con i valori dell'artefatto
   ufficiale;
3. ricostruire ed eseguire tutti i comandi di convalida offline;
4. confermare le versioni all'interno dell'immagine;
5. eseguire nuovamente la suite live autenticata con tre scenari.

Non installare globalmente nessuna delle due CLI sull'host e non sostituire la verifica del checksum con un
download non verificato.

## Diagnosi e pulizia

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  mostra il routing locale e gli errori sanitizzati dell'esecutore.
- `.sandbox/evidence/mock-acp.jsonl` registra le azioni ACP mock deterministiche.
- `.sandbox/evidence/claude-stream.jsonl` registra l'esecuzione offline reale di Claude Code.
- `.sandbox/evidence/live-*.jsonl` registra i tre flussi live convalidati.
- `.sandbox/evidence/egress.jsonl` e `.sandbox/evidence/claude-egress.jsonl` sono copie convalidate,
  prive di token, degli audit del guard.

Arrestare i container e le reti di proprietà del bridge, preservando i volumi di login/configurazione:

```bash
./scripts/devin-bridge/clean
```

Rimuovere l'intero ambiente di proprietà del bridge, inclusi i volumi denominati:

```bash
./scripts/devin-bridge/clean --all
```

## Limiti

- Il bridge si basa sul ruolo fisso senza strumenti `summarizer` perché Devin CLI `3000.2.17`
  non espone un agente ACP neutro senza strumenti. L'adapter compensa le risposte intermedie
  strutturate come riepiloghi, ma una singola riparazione limitata può comunque fallire esplicitamente.
- Le chiamate ACP live possono restituire risposte transitorie `502`/`504`. L'harness distanzia gli scenari;
  un errore persistente mantiene il comportamento fail-closed e non seleziona mai un altro provider.
- Il contesto ACP viene ricostruito da ogni richiesta Anthropic; non esiste affinità di processo/sessione.
- È supportata una sola chiamata a uno strumento per ogni risposta del modello; le chiamate parallele vengono rifiutate.
- Le immagini non sono esplicitamente supportate. Le funzionalità di visione, l'output del ragionamento, i controlli dello sforzo e una finestra di contesto da 1M
  non vengono dichiarati.
- SSE utilizza eventi validi del ciclo di vita Anthropic, ma viene emesso dopo la raccolta del turno ACP limitato;
  i chunk ACP non vengono inoltrati in modo incrementale.
