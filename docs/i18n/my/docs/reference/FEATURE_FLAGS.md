OmniRoute ၏ လုပ်ဆောင်ပုံကို **ပြန်လည်ဖြန့်ကျက်ခြင်းမရှိဘဲ** ပြောင်းလဲပေးနိုင်သော Runtime toggles များ။
ဤနေရာတွင် ဖော်ပြထားသော flag တိုင်းကို [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts) တွင် သတ်မှတ်ထားပြီး ၎င်းသည် အမှန်တရား၏ တစ်ခုတည်းသော အရင်းအမြစ်ဖြစ်သည်။ dashboard နှင့် REST API နှစ်ခုလုံးသည် ထိုဖိုင်မှ ဖတ်ယူသောကြောင့် အောက်ပါဇယားကို ၎င်းနှင့် 1:1 ကိုက်ညီစေရန် ဖန်တီးထားပါသည်။

## Feature Flags များဆိုသည်မှာ

feature flag ဆိုသည်မှာ အမည်ပေးထားသော toggle (boolean သို့မဟုတ် enum) တစ်ခုဖြစ်ပြီး ၎င်း၏တန်ဖိုးကို runtime တွင် ပြောင်းလဲနိုင်ပြီး database တွင် သိမ်းဆည်းထားနိုင်ကာ process ကို ပြန်လည်ဖြန့်ကျက်ရန် မလိုအပ်ပါ။ flag တစ်ခုစီကို `key`, `label`, `description`, `category`, `defaultValue`, `type` နှင့် `requiresRestart` hint ပါဝင်သော `FeatureFlagDefinition` ဖြင့် ဖော်ပြထားပါသည်။

### ဖြေရှင်းမှု အစီအစဉ်

flag ၏ **ထိရောက်သောတန်ဖိုး** ကို [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) မှ အောက်ပါဦးစားပေး (အမြင့်ဆုံးက အနိုင်ရသည်) ဖြင့် ဖြေရှင်းပေးပါသည်။

1.  **DB override** — `feature_flags` namespace အောက်ရှိ `key_value` table တွင် သိမ်းဆည်းထားသော တန်ဖိုး (dashboard သို့မဟုတ် REST API မှတစ်ဆင့် သတ်မှတ်သည်)။
2.  **Environment variable** — `process.env[<KEY>]`၊ သတ်မှတ်ထားပြီး ဗလာမဖြစ်ပါက။
3.  **Definition default** — `featureFlagDefinitions.ts` မှ `defaultValue`။

boolean flag တစ်ခု၏ ထိရောက်သောတန်ဖိုးသည် `"true"`, `"1"`, သို့မဟုတ် `"yes"` ဖြစ်ပါက ၎င်းကို **ဖွင့်ထားသည်** ဟု မှတ်ယူသည် ( `isFeatureFlagEnabled()` ကို ကြည့်ပါ)။

> [!NOTE]
> flag အများစုတွင် [`ENVIRONMENT.md`](./ENVIRONMENT.md) တွင် မှတ်တမ်းတင်ထားသော **တူညီသောအမည်** ရှိသော environment variable လည်း ရှိပါသည်။ flag ၏ DB override သည် ထို environment variable ထက် ဦးစားပေးပါသည်။ `requiresRestart: true` ပါသော flag ကို ချက်ချင်းသိမ်းဆည်းသော်လည်း process စတင်ချိန်တွင်သာ ပြန်လည်ဖတ်ရှုပါသည်။ ၎င်းကို toggle လုပ်ခြင်းဖြင့် dashboard တွင် **"Restart Server"** banner ပေါ်လာပါသည်။

| `CREDENTIAL_GATE_AUTH_DIAGNOSES_ONLY`     | boolean | `false` | သိမ်းဆည်းထားသော မအောင်မြင်သည့် credential probe တစ်ခု၏ ရောဂါရှာဖွေချက်က credential မမှန်ကန်ကြောင်း (`upstream_auth_error`, `auth_missing`, `token_expired`, `token_refresh_failed`, `reauth_required`, `account_deactivated`, `auth_required`) သက်သေပြသည့်အခါမှသာ connection တစ်ခုကို ပိတ်ဆို့စေရန် combo credential gate ကို ကန့်သတ်သည်။ တိကျစွာ မဆုံးဖြတ်နိုင်သော မအောင်မြင်မှုများ (အချိန်ကုန်ဆုံးမှုများ၊ နှုန်းထားကန့်သတ်ချက်များ၊ ဝန်ဆောင်မှုပြတ်တောက်မှုများ၊ ပံ့ပိုးမထားသော probe များနှင့် အမျိုးအစားမသတ်မှတ်ထားသော scheduler error များ) ကို ထို့နောက် အခြေအနေမသိဟု သတ်မှတ်ပြီး connection သည် traffic ကို ဆက်လက်လက်ခံသည်။ ပုံမှန်အားဖြင့် ပိတ်ထားသည်- သိမ်းဆည်းထားသော probe error တစ်ခုခုသည် cache TTL (၅ မိနစ်) အတွင်း connection ကို ပိတ်ဆို့သည်။ |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` နှင့် ၎င်း၏ ယခင်အမည်ဖြစ်သော
> `INJECTION_GUARD_BLOCK_THRESHOLD` တို့သည် `INJECTION_GUARD_MODE` ၏
> `block` mode ကို ချိန်ညှိပေးသော်လည်း ၎င်းတို့သည်
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts) က ဖတ်ရှုသည့် သာမန် environment variable များသာဖြစ်ပြီး
> feature flag များ မဟုတ်ပါ- ၎င်းတို့တွင် DB override နှင့် dashboard toggle မရှိပါ။ အသေးစိတ်ကို
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication) တွင် ကြည့်ပါ။

> [!NOTE]
> `Restart` column သည် `requiresRestart: true` ပါရှိသော flag များကို အမှတ်အသားပြုသည် — တန်ဖိုးကို
> ချက်ချင်း သိမ်းဆည်းထားသော်လည်း process ကို ပြန်လည်စတင်ပြီးမှသာ အကျိုးသက်ရောက်သည်။ Enum
> flag များသည် ၎င်းတို့၏ ခွင့်ပြုထားသော set ပြင်ပရှိ မည်သည့်တန်ဖိုးကိုမဆို ငြင်းပယ်သည် (server ဘက်တွင်
> `setFeatureFlagOverride()` နှင့် REST `PUT` handler နှစ်ခုလုံး၌ စစ်ဆေးအတည်ပြုသည်)။

## အလံများကို အဖွင့်/အပိတ် ပြောင်းလဲခြင်း

### ဒက်ရှ်ဘုတ်

**ဒက်ရှ်ဘုတ် → ဆက်တင်များ → လုပ်ဆောင်ချက်အလံများ**
(`/dashboard/settings/feature-flags`) သို့ သွားပါ။ ဇယားကွက်
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
သည် အောက်ပါတို့ကို ပံ့ပိုးပေးသည်-

- သော့ချက် သို့မဟုတ် ဖော်ပြချက်ဖြင့် **ရှာဖွေခြင်း** နှင့် အမျိုးအစားအလိုက် **စစ်ထုတ်ခြင်း** (ထို့အပြင် ဖန်တီးထားသော
  **ပြန်လည်စတင်ရန် လိုအပ်သည်** မြင်ကွင်း)။
- boolean အလံများအတွက် **အဖွင့်/အပိတ်ခလုတ်** နှင့် enum အလံများအတွက် **ရွေးချယ်စာရင်း**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)။
- အလံတစ်ခုစီအတွက် အကျိုးသက်ရောက်နေသော တန်ဖိုးသည် မည်သည့်နေရာမှ ရရှိကြောင်း ပြသသည့်
  **ရင်းမြစ်တံဆိပ်** — `DB`, `ENV` သို့မဟုတ် `DEF`။
- အစားထိုးသတ်မှတ်ချက်ကို ဖယ်ရှားရန် **ပြန်လည်သတ်မှတ်ရန်** ခလုတ် (`DB` မှ ရရှိသော အလံများအတွက်သာ ပြသသည်)
  နှင့် အောက်ခြေရှိ **အစားထိုးသတ်မှတ်ချက်အားလုံးကို ပြန်လည်သတ်မှတ်ရန်** ခလုတ်။
- `requiresRestart` အလံတစ်ခုကို ပြောင်းလဲသောအခါ **ဆာဗာကို ပြန်လည်စတင်ရန်** ဆိုင်းဘုတ်။

### REST API

လုပ်ဆောင်ချက်အားလုံးသည် လမ်းကြောင်းတစ်ခုတည်းမှတစ်ဆင့် လုပ်ဆောင်သည်-
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)။
နည်းလမ်းတိုင်းတွင် အထောက်အထားစိစစ်ပြီးသော ဒက်ရှ်ဘုတ် session တစ်ခု လိုအပ်သည် (မရှိပါက `401`)။

#### `GET /api/settings/feature-flags`

အလံတိုင်းကို ၎င်း၏ အကျိုးသက်ရောက်နေသော တန်ဖိုး၊ ရင်းမြစ်နှင့် အကျဉ်းချုပ်တို့နှင့်အတူ ပြန်ပေးသည်။

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... အလံ 108 ခုလုံး
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

အစားထိုးသတ်မှတ်ချက်တစ်ခုကို သတ်မှတ်ခြင်း သို့မဟုတ် ဖယ်ရှားခြင်း ပြုလုပ်ပါ။ Body: `{ key: string; value?: string }`။
`value` ကို ချန်လှပ်ထားပါက အစားထိုးသတ်မှတ်ချက်ကို ဖယ်ရှားသည် (env / မူလတန်ဖိုးသို့ ပြန်ထားသည်)။

```bash
# DB အစားထိုးသတ်မှတ်ချက်တစ်ခုကို သတ်မှတ်ရန်
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# အစားထိုးသတ်မှတ်ချက်ကို ဖယ်ရှားရန် ("value" မပါ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

တုံ့ပြန်ချက်သည် `effectiveValue`/`source` အသစ်၊ `previousValue`/
`previousSource` နှင့် `requiresRestart` တို့ကို ပြန်လည်ဖော်ပြပေးသည်။ မသိသော သော့ချက်များနှင့် သတ်မှတ်အပိုင်းအခြားပြင်ပရှိ enum
တန်ဖိုးများကို `400` ဖြင့် ငြင်းပယ်သည်။

#### `DELETE /api/settings/feature-flags`

DB အစားထိုးသတ်မှတ်ချက် **အားလုံး** ကို တစ်ကြိမ်တည်း ရှင်းလင်းပြီး အလံတိုင်းကို ၎င်း၏ env / မူလ
တန်ဖိုးသို့ ပြန်ထားသည်။ `{ cleared: <count>, message: "..." }` ကို ပြန်ပေးသည်။

> [!NOTE]
> `requiresRestart: true` ပါသော အလံများသည် process ကို ပြန်လည်တင်ပြီးနောက်မှသာ အကျိုးသက်ရောက်သည်။
> ဒက်ရှ်ဘုတ်၏ ပြန်လည်စတင်ခြင်း လုပ်ငန်းစဉ်သည် `POST /api/restart` ကို ခေါ်ဆိုပြီးနောက် ဆာဗာ ပြန်လည်အလုပ်လုပ်လာသည်အထိ
> `GET /api/health/ping` ကို ဆက်တိုက် စစ်ဆေးသည်။

## အရေးပေါ် ဘတ်ဂျက် အရန်စနစ်

`OMNIROUTE_EMERGENCY_FALLBACK` (အမျိုးအစား `runtime`၊ မူလတန်ဖိုး `true`) သည်
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ရှိ အရေးပေါ် အခမဲ့အရန်လမ်းကြောင်းကို ထိန်းချုပ်သည်။
၎င်းကို ဖွင့်ထားသည့်အခါ ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို ချက်ချင်း မအောင်မြင်စေဘဲ
အခမဲ့ အရန် provider/model သို့ လမ်းကြောင်းပြောင်းပေးသည်။ ဤလုပ်ဆောင်ချက်ကို ပိတ်ပြီး
ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို မအောင်မြင်စေရန် dashboard toggle၊ DB override
သို့မဟုတ် `OMNIROUTE_EMERGENCY_FALLBACK` environment variable မှတစ်ဆင့် ၎င်းကို
`false` (သို့မဟုတ် `0`) ဟု သတ်မှတ်ပါ။ (PRs #3741 / #3752 တွင် dashboard toggle
အဖြစ် ဖော်ပြထားသည်။)

ဤအရန်စနစ်မှ ပေးပို့သော response တွင်
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ပါဝင်သဖြင့်
client သည် `X-OmniRoute-Provider` ကို ၎င်း၏ request နှင့် နှိုင်းယှဉ်စရာမလိုဘဲ
လမ်းကြောင်းပြောင်းထားကြောင်း သိနိုင်သည်။ အခြား response အားလုံးတွင် ဤ header မပါဝင်ပါ။
