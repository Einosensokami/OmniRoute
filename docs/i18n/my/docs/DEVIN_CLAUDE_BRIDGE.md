`devin-cli-agentic` သည် တရားဝင် Devin CLI က ACP stdio မှတစ်ဆင့် မော်ဒယ်တုံ့ပြန်မှုများကို ပံ့ပိုးနေစဉ် အမှန်တကယ် Claude Code runtime ကို OmniRoute ၏ local Anthropic
Messages endpoint အသုံးပြုနိုင်စေသည်။ ၎င်းသည် ရှိပြီးသား Anthropic၊ Claude OAuth၊ Claude Web သို့မဟုတ် `devin-cli` provider များကို ပြင်ဆင်ခြင်းမရှိပါ။

Client က စီမံပိုင်ဆိုင်သော tool call များအတွက် Claude-format ဖြင့် tool အသုံးပြုနိုင်သည့် provider ဖြစ်သော `devin-cli-agentic` (အမည်ပွား `dva`) မှတစ်ဆင့် route လုပ်ပါ။ ယခင် `devin-cli` (`dv`) ACP executor သည်
စာသားသီးသန့်သာဖြစ်သည်။ ၎င်းသည် Devin ၏ tool မပါသော summarizer ကို run ပြီး tool call များကို ပြန်ပေးနိုင်ခြင်းမရှိပါ။ Tool လိုအပ်သော combo routing က ၎င်းကို ရှောင်ရှားနိုင်စေရန် ၎င်း၏ model
metadata ကိုလည်း သက်ဆိုင်သည့်အတိုင်း မှတ်သားထားသည်။

> **လက်ရှိအခြေအနေ: Claude Code `2.1.258` တွင် pin လုပ်ထားပြီး၊ offline နှင့် live validation ကို နောက်ဆုံးမှတ်တမ်းတင်ထားသည်မှာ
> `2.1.220` တွင်ဖြစ်သည်။** `2.1.220` pin သည် Devin CLI
> `3000.2.17` နှင့် model `swe-1-7-lightning` မှတစ်ဆင့် သီးခြား scenario သုံးခုကို အပြီးသတ်ခဲ့သည်။ ထိုနောက်ဆုံး live run က client ပိုင် `Read`၊
> `Edit` နှင့် `Bash` turn များ၊ အောင်မြင်သော `npm test` ရလဒ်များ၊ project command နှင့် skill
> ရှာဖွေတွေ့ရှိမှု၊ Devin-only routing နှင့် Claude egress လုံးဝမရှိခြင်းတို့ကို သက်သေပြခဲ့သည်။ ထို့နောက် pin ကို `2.1.258` သို့ မြှင့်တင်ခဲ့သည်
> (OmniRoute ၏ Claude identity က အယောင်ဆောင်သည့် CLI generation ဖြစ်ပြီး Fable 5.1 tier ကို မူလပါဝင်လာသည့် ပထမဆုံး line ဖြစ်သည်)။ Pin အသစ်တွင် pinned base image ပေါ်၌ install layer နှင့် `claude --version` ကို
> အတည်ပြုခဲ့ပြီး bridge unit suite၊ `compose config` နှင့်
> static isolation proof တို့ pass ဖြစ်သည် — သို့သော် offline mock scenario နှင့် live scenario သုံးခုပါ
> suite ကို ပြန်လည် run ရခြင်း မရှိသေးပါ။ ဤ pin ဖြင့် bridge ကို အားကိုးအသုံးမပြုမီ ၎င်းတို့ကို ပြန်လည် run ပါ ("Pinned tool များကို အပ်ဒိတ်လုပ်ခြင်း" ကိုကြည့်ပါ)။

## တည်ဆောက်ပုံ

```text
Claude Code 2.1.258 (သီးခြားခွဲထားသော root မဟုတ်သည့် Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format၊ auth မလိုသော provider)
  -> devin acp --agent-type summarizer (တရားဝင် ACP stdio၊ Devin tool များမပါ)
  -> သီးသန့် devin-auth volume ရှိ Devin account
```

တရားဝင် CLI ၏ မူလ ACP agent သည် ၎င်း၏ကိုယ်ပိုင် tool များကို လုပ်ဆောင်နိုင်သောကြောင့် ဤ bridge က
၎င်းကို အသုံးမပြုပါ။ Tool မပါသော တရားဝင် CLI mode ရှိသည့် ပုံသေ `summarizer` ACP agent ကို စတင်ပြီး
serialized Anthropic request ကို execution trace အဖြစ် frame လုပ်သည်။ Claude ပိုင် နောက်ထပ် action တစ်ခု လိုအပ်သည့်အခါ response တွင် client tool envelope တစ်ခုတည်း အတိအကျ ပါဝင်ရမည်။ ACP
`tool_call` သို့မဟုတ် `tool_call_update` မှန်သမျှကို response အောင်မြင်ကြောင်း အစီရင်ခံနိုင်ခြင်းမပြုမီ ပယ်ချသည်။

`open-sse/executors/devin-agentic/serializer.ts` ရှိ serializer သည် `system`၊
`text`၊ `tool_use`၊ `tool_result`၊ `thinking`၊ `redacted_thinking`၊ `tool_choice` နှင့် Claude Code က ပေးထားသည့်
tool များကို မပျက်မကွက် ထိန်းသိမ်းသည်။ ပုံများနှင့် အမျိုးအစားမသိသော block များသည် တိကျရှင်းလင်းစွာ fail ဖြစ်သည်။ ကြီးမားသော tool result များတွင် မြင်နိုင်သည့် ဖြတ်တောက်ထားကြောင်း အမှတ်အသားကို အသုံးပြုသည်။

Parser သည် model turn တစ်ခုလျှင် သီးခြား `<tool>{...}</tool>` envelope တစ်ခုကို လက်ခံသည်။ ၎င်းသည်
request ၏ tool စာရင်းနှင့် name ကို တိုက်ဆိုင်စစ်ဆေးပြီး ထို tool ၏ JSON
Schema နှင့်အညီ argument များကို validate လုပ်ကာ narrative/action ရောနှောမှုကို ပယ်ချပြီး အကန့်အသတ်ရှိသော repair တစ်ကြိမ်ကို ခွင့်ပြုသည်။ ထို့နောက် Claude Code က ရရှိလာသော Anthropic `tool_use` ကို local တွင် execute လုပ်ပြီး `tool_result` ကို OmniRoute မှတစ်ဆင့် ပြန်ပို့သည်။

## အလိုအလျောက် routing

Provider ကို block မလုပ်ထားပါက OmniRoute ၏ `auto/*` candidate pool များတွင် ရွေးချယ်နိုင်သည်။
Candidate အဖြစ် ရွေးချယ်နိုင်ခြင်းသည် အမှန်တကယ် ရွေးချယ်ခံရမည်ဟု အာမမခံပါ။ Combo ၏ routing strategy (ဥပမာ
last-known-good) သည် အခြား provider တစ်ခုကို ဦးစားပေးနိုင်သည်။ Request တိုင်းကို Devin မှတစ်ဆင့် ပို့ရန်လိုအပ်ပါက `dva/<model>` သို့မဟုတ် Devin-first combo ကို အသုံးပြုပါ။

## သီးခြားခွဲထားမှုနှင့် ခြိမ်းခြောက်မှု မော်ဒယ်

Host ၏ Claude တပ်ဆင်မှု၊ အကောင့်နှင့် ဖွဲ့စည်းသတ်မှတ်ချက်တို့သည် စစ်ဆေးမှုနယ်ပယ်ပြင်ပတွင်ရှိပြီး
အသုံးပြုခွင့်ပိတ်ပင်ထားသည်ဟု သတ်မှတ်ထားသည်။ Compose ဝန်ဆောင်မှုများသည်-

- UID/GID `10001:10001` ဖြင့် လုပ်ဆောင်ပြီး၊ ဖတ်ရှုရန်သာဖြစ်သော root filesystem၊ ဖယ်ရှားထားသော capabilities နှင့်
  `no-new-privileges` ကို အသုံးပြုသည်။
- သီးသန့် `/home/bridge`၊ သီးခြား Claude config volume၊ သီးခြားခွဲထားသော OmniRoute data နှင့်
  သီးခြား `devin-auth` volume ကို အသုံးပြုသည်။
- ယာယီအသုံးပြုပြီး စွန့်ပစ်နိုင်သော `.sandbox` workspaces/evidence များကိုသာ mount လုပ်သည်။
- host home၊ Keychain၊ SSH၊ cloud credentials သို့မဟုတ် Docker socket ကို mount မလုပ်ပါ။
- environment များကို တိတိကျကျ တည်ဆောက်ပြီး Anthropic API/OAuth/routing variables များကို ဖယ်ရှားသည်။
- Claude Code inference ကို local-only key ဖြင့် `http://omniroute:20128` သို့သာ တိုက်ရိုက်ပို့သည်။

Offline profile သည် internal network ကို အသုံးပြုသည်။ Live profile တွင် OmniRoute သည်
တရားဝင် Devin endpoints များကို `network-guard` မှတစ်ဆင့်သာ ဆက်သွယ်နိုင်ပြီး၊ မသက်ဆိုင်သော destinations များကို ပိတ်ပင်ထားသည်။
Claude Code တွင် သီးခြား deny-all egress guard တစ်ခုရှိပြီး `NO_PROXY` မှတစ်ဆင့် local OmniRoute
service ကိုသာ ဆက်သွယ်နိုင်သည်။ Guard audit files များကို သက်ဆိုင်ရာ guard process ကသာ mount လုပ်ထားသည်။
Scripts များသည် token-free evidence ကို export မလုပ်မီ file ownership၊ mode၊ link count နှင့် ဆုံးဖြတ်ချက်တိုင်းကို
စစ်ဆေးအတည်ပြုသည်။

သီးခြားခွဲထားမှု အထောက်အထားကို လွတ်လပ်စွာ run လုပ်ပါ-

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

၎င်းသည် topology၊ named mounts၊ non-root/read-only settings၊ explicit local routing၊
အရေးကြီး environment variables များ မရှိခြင်း၊ Docker socket မရှိခြင်း၊
`api.anthropic.com` နှင့် `claude.ai` သို့ ဝင်ရောက်မှု ပိတ်ဆို့ထားခြင်း၊ Devin-only provider selection နှင့်
ACP backend မရရှိနိုင်သည့်အခါ တိတိကျကျ ပျက်ကွက်ခြင်းတို့ကို စစ်ဆေးအတည်ပြုသည်။

## ပထမအကြိမ် စနစ်တကျပြင်ဆင်ခြင်းနှင့် ပုံမှန်အသုံးပြုခြင်း

သတ်မှတ်ထားသော image ကို build လုပ်ပါ-

```bash
./scripts/devin-bridge/build
```

သီးခြားခွဲထားသော Devin volume ကိုသာ authenticate လုပ်ပါ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Login command သည် remote/container environments များအတွက် ရည်ရွယ်ထားသော တရားဝင် manual-token flow ကို
အသုံးပြုသည်။ တန်ဖိုးကို CLI prompt ထဲသို့ တိုက်ရိုက်ထည့်သွင်းရသည်။ ၎င်းကို
process argument အဖြစ် မပေးပို့ပါ၊ Git ထဲသို့ မရေးပါ၊ သို့မဟုတ် host မှ ကူးယူခြင်း မပြုပါ။

သီးခြားခွဲထားသော Claude Code runtime ကို စတင်ပါ-

```bash
./scripts/devin-bridge/launch
```

`launch` သည် containerized Claude Code ကို မစတင်မီ သီးခြားခွဲထားမှု၊ Devin authentication နှင့် model discovery တို့ကို
ပြန်လည်စစ်ဆေးသည်။ ၎င်းသည် host ၏ Claude executable ကို မည်သည့်အခါမျှ run မလုပ်ပါ။ Model aliases များကို
`.env.devin-bridge` တွင် သတ်မှတ်နိုင်သည်။ ဖွဲ့စည်းသတ်မှတ်ထားသော တန်ဖိုးတိုင်းသည်
`devin-cli-agentic/` prefix ကို ဆက်လက်ထိန်းသိမ်းထားရမည်။

## စစ်ဆေးအတည်ပြုမှု command များ

ပြန်လည်လုပ်ဆောင်၍ တူညီသောရလဒ် ရရှိနိုင်သည့် offline လမ်းကြောင်းသည် Devin account မလိုအပ်သလို runtime Internet လည်း မလိုအပ်ပါ-

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Authenticate လုပ်ထားပြီး ရွေးချယ်၍ အသုံးပြုနိုင်သည့် live လမ်းကြောင်းမှာ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Live runner သည် ACP sessions များကို တစ်ပြိုင်နက် အများအပြား မဖွင့်မိစေရန် scenarios များကြားတွင် စောင့်ဆိုင်းပြီး
စာသားဖြင့် ဖော်ပြထားသော အဆိုများကို ယုံကြည်မည့်အစား structured Claude stream events များကို စစ်ဆေးအတည်ပြုသည်။ ၎င်း၏
scenarios သုံးခုသည် အောက်ပါတို့ကို သက်သေပြသည်-

1. project ကို တိုက်ရိုက်ဖတ်ရှုခြင်းနှင့် defect analysis၊
2. အမှန်တကယ် `Edit` တစ်ခု၊ client က ပိုင်ဆိုင်သော `Bash` `npm test` တစ်ခုနှင့် terminal result တစ်ခု၊
3. `/bridge-check` နှင့် `bridge-proof` discovery၊ project ကို ဖတ်ရှုခြင်း၊ နောက်ထပ် အောင်မြင်သော
   client က ပိုင်ဆိုင်သည့် `npm test` တစ်ခုနှင့် pending work မရှိဘဲ ပြီးဆုံးခြင်း။

နောက်ဆုံး gate သည် Devin network audit ကိုလည်း စစ်ဆေးပြီး Claude egress audit သည်
ဗလာဖြစ်နေဆဲဖြစ်ရန် လိုအပ်သည်။

## ပင်ထိုးသတ်မှတ်ထားသော ကိရိယာများကို အပ်ဒိတ်လုပ်ခြင်း

Image တွင် Node၊ Claude Code နှင့် Devin CLI တို့ကို
`docker/devin-bridge/Dockerfile` အတွင်း ပင်ထိုးသတ်မှတ်ထားသည်။ အပ်ဒိတ်လုပ်ရန်-

1. အတိအကျသတ်မှတ်ထားသော ဗားရှင်းများကို ပြောင်းပါ၊
2. architecture တစ်ခုစီအလိုက် Devin archive checksum နှစ်ခုစလုံးကို တရားဝင်
   artifact အတွက် တန်ဖိုးများဖြင့် အစားထိုးပါ၊
3. ပြန်လည်တည်ဆောက်ပြီး offline validation command အားလုံးကို လုပ်ဆောင်ပါ၊
4. image အတွင်းရှိ ဗားရှင်းများကို အတည်ပြုပါ၊
5. authentication ပြုလုပ်ထားသော scenario သုံးမျိုးပါ live suite ကို ပြန်လည်လုပ်ဆောင်ပါ။

CLI တစ်ခုခုကို host ပေါ်တွင် global အဖြစ် မတပ်ဆင်ပါနှင့်၊ checksum verification ကို
အတည်မပြုထားသော download ဖြင့် မအစားထိုးပါနှင့်။

## ပြဿနာရှာဖွေခြင်းနှင့် ရှင်းလင်းခြင်း

- `.sandbox/evidence/mock-acp.jsonl` တွင် ရလဒ်အမြဲတူညီသော mock ACP action များကို မှတ်တမ်းတင်ထားသည်။
- `.sandbox/evidence/claude-stream.jsonl` တွင် အမှန်တကယ် Claude Code offline run ကို မှတ်တမ်းတင်ထားသည်။
- `.sandbox/evidence/live-*.jsonl` တွင် အတည်ပြုထားသော live stream သုံးခုကို မှတ်တမ်းတင်ထားသည်။
- `.sandbox/evidence/egress.jsonl` နှင့် `.sandbox/evidence/claude-egress.jsonl` တို့သည် အတည်ပြုထားပြီး
  token မပါဝင်သော guard audit မိတ္တူများဖြစ်သည်။

login/config volume များကို ထိန်းသိမ်းထားစဉ် ပိုင်ဆိုင်သော container နှင့် network များကို ရပ်တန့်ရန်-

## ကန့်သတ်ချက်များ

- Devin CLI `3000.2.17` သည် ကြားနေ no-tools ACP agent တစ်ခုကို မပံ့ပိုးသောကြောင့် bridge သည် ပုံသေ no-tools `summarizer` role ကို အားကိုးသည်။ Adapter သည် summary ပုံစံရှိသော
  အလယ်အလတ် response များအတွက် ချိန်ညှိပေးသော်လည်း အကန့်အသတ်ရှိသော repair တစ်ကြိမ်သည် တိကျစွာ ဖော်ပြသည့် failure ဖြင့် မအောင်မြင်နိုင်သေးသည်။
- Live ACP call များသည် ယာယီ `502`/`504` response များ ပြန်ပေးနိုင်သည်။ Harness သည် scenario များကြား အချိန်ခြားပေးသည်၊
  ဆက်တိုက်ဖြစ်ပေါ်နေသော failure သည် fail-closed အဖြစ် ဆက်လက်ရှိပြီး အခြား provider ကို မည်သည့်အခါမျှ မရွေးချယ်ပါ။
- ACP context ကို Anthropic request တစ်ခုစီမှ ပြန်လည်တည်ဆောက်သည်၊ process/session
  affinity မရှိပါ။
- Model response တစ်ခုလျှင် tool call တစ်ခုကို ပံ့ပိုးထားပြီး parallel call များကို ငြင်းပယ်သည်။
- Image များကို ပံ့ပိုးမထားကြောင်း အတိအလင်း သတ်မှတ်ထားသည်။ Vision၊ thinking output၊ effort control များနှင့် 1M
  context window ကို ပံ့ပိုးထားသည်ဟု မကြေညာပါ။
- SSE သည် မှန်ကန်သော Anthropic lifecycle event များကို အသုံးပြုသော်လည်း အကန့်အသတ်ရှိသော ACP turn ကို
  စုဆောင်းပြီးနောက်မှ ထုတ်လွှတ်သည်၊ ACP chunk များကို တစ်ဆင့်ချင်း ချက်ချင်းမပို့ပေးပါ။
