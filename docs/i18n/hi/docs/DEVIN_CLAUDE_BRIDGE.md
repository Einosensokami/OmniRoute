`devin-cli-agentic` वास्तविक Claude Code रनटाइम को OmniRoute के स्थानीय Anthropic
Messages एंडपॉइंट का उपयोग करने देता है, जबकि आधिकारिक Devin CLI ACP stdio के माध्यम से मॉडल प्रतिक्रियाएँ प्रदान करता है। यह
मौजूदा Anthropic, Claude OAuth, Claude Web, या `devin-cli` प्रदाताओं को संशोधित नहीं करता।

क्लाइंट-स्वामित्व वाली टूल कॉल्स के लिए, Claude-फ़ॉर्मेट वाले टूल-सक्षम प्रदाता
`devin-cli-agentic` (उपनाम `dva`) के माध्यम से रूट करें। लीगेसी `devin-cli` (`dv`) ACP एक्ज़ीक्यूटर
केवल-टेक्स्ट है: यह Devin के बिना-टूल वाले समराइज़र को चलाता है और टूल कॉल्स वापस नहीं कर सकता। इसका मॉडल
मेटाडेटा इसी के अनुसार चिह्नित है, ताकि टूल-आवश्यक कॉम्बो रूटिंग इससे बचे।

> **वर्तमान स्थिति: Claude Code `2.1.258` पर पिन किया गया; ऑफ़लाइन और लाइव सत्यापन अंतिम बार
> `2.1.220` पर रिकॉर्ड किया गया था।** `2.1.220` पिन ने Devin CLI
> `3000.2.17` और मॉडल `swe-1-7-lightning` के माध्यम से तीन पृथक परिदृश्य पूरे किए; उस अंतिम लाइव रन ने क्लाइंट-स्वामित्व वाले `Read`,
> `Edit`, और `Bash` टर्न, सफल `npm test` परिणाम, प्रोजेक्ट कमांड और स्किल
> खोज, केवल-Devin रूटिंग, और शून्य Claude इग्रेस को प्रमाणित किया। इसके बाद पिन को `2.1.258`
> तक बढ़ाया गया (वह CLI जनरेशन जिसका OmniRoute की Claude पहचान प्रतिरूपण करती है, और पहली लाइन जिसमें
> Fable 5.1 टियर मूल रूप से शामिल है)। नए पिन पर पिन की गई बेस इमेज में इंस्टॉल लेयर और `claude --version` को
> सत्यापित किया गया, और ब्रिज यूनिट सुइट, `compose config` तथा
> स्टैटिक आइसोलेशन प्रमाण पास होते हैं — लेकिन ऑफ़लाइन मॉक परिदृश्य और लाइव तीन-परिदृश्य
> सुइट को अभी तक फिर से नहीं चलाया गया है। इस पिन के साथ ब्रिज पर भरोसा करने से पहले उन्हें फिर से चलाएँ
> ("Updating pinned tools" देखें)।

## आर्किटेक्चर

```text
Claude Code 2.1.258 (पृथक नॉन-रूट Linux कंटेनर)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-फ़ॉर्मेट, बिना-प्रमाणीकरण प्रदाता)
  -> devin acp --agent-type summarizer (आधिकारिक ACP stdio, कोई Devin टूल नहीं)
  -> समर्पित devin-auth वॉल्यूम में Devin खाता
```

आधिकारिक CLI का डिफ़ॉल्ट ACP एजेंट अपने टूल्स निष्पादित कर सकता है, इसलिए यह ब्रिज उसका उपयोग नहीं करता।
यह निर्धारित `summarizer` ACP एजेंट शुरू करता है, जिसके आधिकारिक CLI मोड में कोई टूल नहीं है, और
सीरियलाइज़ किए गए Anthropic अनुरोध को एक निष्पादन ट्रेस के रूप में फ़्रेम करता है। जब Claude-स्वामित्व वाली कोई अन्य
कार्रवाई आवश्यक हो, तो प्रतिक्रिया में ठीक एक क्लाइंट टूल एनवेलप होना चाहिए। किसी भी ACP
`tool_call` या `tool_call_update` को प्रतिक्रिया के सफल होने की रिपोर्ट किए जाने से पहले अस्वीकार कर दिया जाता है।

`open-sse/executors/devin-agentic/serializer.ts` में मौजूद सीरियलाइज़र `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, और Claude Code द्वारा
दिए गए टूल्स को संरक्षित रखता है। इमेज और अज्ञात ब्लॉक स्पष्ट रूप से विफल होते हैं। बड़े टूल परिणाम
दृश्यमान ट्रंकेशन मार्कर का उपयोग करते हैं।

पार्सर प्रत्येक मॉडल टर्न में एक स्वतंत्र `<tool>{...}</tool>` एनवेलप स्वीकार करता है। यह
अनुरोध की टूल सूची के विरुद्ध नाम की जाँच करता है, उस टूल के JSON
Schema के विरुद्ध आर्ग्युमेंट्स सत्यापित करता है, मिश्रित विवरण/कार्रवाइयों को अस्वीकार करता है, और एक सीमित सुधार की अनुमति देता है। इसके बाद Claude Code
परिणामी Anthropic `tool_use` को स्थानीय रूप से निष्पादित करता है और `tool_result` को OmniRoute के माध्यम से
वापस भेजता है।

## ऑटो-रूटिंग

जब प्रदाता ब्लॉक नहीं होता, तब वह OmniRoute के `auto/*` कैंडिडेट पूल्स में पात्र होता है।
कैंडिडेट पात्रता चयन की गारंटी नहीं देती: कॉम्बो की रूटिंग रणनीति (उदाहरण के लिए,
अंतिम-ज्ञात-सफल) किसी अन्य प्रदाता को प्राथमिकता दे सकती है। जब आपको प्रत्येक अनुरोध को Devin के माध्यम से
भेजना आवश्यक हो, तब `dva/<model>` या Devin-प्रथम कॉम्बो का उपयोग करें।

## पृथक्करण और खतरा मॉडल

होस्ट की Claude स्थापना, खाता और कॉन्फ़िगरेशन दायरे से बाहर हैं और उन्हें
प्रतिबंधित माना जाता है। Compose सेवाएँ:

- UID/GID `10001:10001` के रूप में, केवल-पढ़ने योग्य रूट फ़ाइल सिस्टम, हटाई गई क्षमताओं और
  `no-new-privileges` के साथ चलती हैं;
- एक निजी `/home/bridge`, एक समर्पित Claude कॉन्फ़िगरेशन वॉल्यूम, पृथक OmniRoute डेटा
  और एक अलग `devin-auth` वॉल्यूम का उपयोग करती हैं;
- केवल अस्थायी `.sandbox` कार्यक्षेत्र/साक्ष्य माउंट करती हैं;
- होस्ट होम, Keychain, SSH, क्लाउड क्रेडेंशियल या Docker सॉकेट माउंट नहीं करती हैं;
- स्पष्ट परिवेश बनाती हैं और Anthropic API/OAuth/रूटिंग वेरिएबल हटाती हैं;
- Claude Code अनुमान को केवल स्थानीय कुंजी के साथ `http://omniroute:20128` पर निर्देशित करती हैं।

ऑफ़लाइन प्रोफ़ाइल एक आंतरिक नेटवर्क का उपयोग करती है। लाइव प्रोफ़ाइल में, OmniRoute केवल
`network-guard` के माध्यम से आधिकारिक Devin एंडपॉइंट तक पहुँचता है; असंबंधित गंतव्यों को अस्वीकार किया जाता है।
Claude Code के पास एक अलग, सभी आउटबाउंड ट्रैफ़िक को अस्वीकार करने वाला गार्ड है और वह `NO_PROXY` के माध्यम से केवल स्थानीय OmniRoute
सेवा तक पहुँच सकता है। गार्ड ऑडिट फ़ाइलें केवल उनकी संबंधित गार्ड प्रक्रिया द्वारा माउंट की जाती हैं।
स्क्रिप्ट टोकन-मुक्त साक्ष्य निर्यात करने से पहले फ़ाइल स्वामित्व, मोड, लिंक संख्या और प्रत्येक निर्णय
का सत्यापन करती हैं।

पृथक्करण प्रमाण को स्वतंत्र रूप से चलाएँ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

यह टोपोलॉजी, नामित माउंट, गैर-रूट/केवल-पढ़ने योग्य सेटिंग, स्पष्ट स्थानीय रूटिंग,
संवेदनशील परिवेश वेरिएबल की अनुपस्थिति, Docker सॉकेट की अनुपस्थिति, `api.anthropic.com`
और `claude.ai` तक अवरुद्ध पहुँच, केवल-Devin प्रदाता चयन और ACP बैकएंड अनुपलब्ध होने पर
स्पष्ट विफलता को सत्यापित करता है।

## पहली बार की सेटअप प्रक्रिया और सामान्य उपयोग

पिन की गई इमेज बनाएँ:

```bash
./scripts/devin-bridge/build
```

केवल पृथक Devin वॉल्यूम को प्रमाणित करें:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लॉगिन कमांड दूरस्थ/कंटेनर परिवेशों के लिए निर्धारित आधिकारिक मैन्युअल-टोकन प्रवाह का
उपयोग करता है। मान सीधे CLI प्रॉम्प्ट में दर्ज किया जाता है; इसे प्रक्रिया आर्ग्युमेंट के
रूप में पास नहीं किया जाता, Git में नहीं लिखा जाता और होस्ट से कॉपी नहीं किया जाता।

पृथक Claude Code रनटाइम लॉन्च करें:

```bash
./scripts/devin-bridge/launch
```

`launch` कंटेनरीकृत Claude Code शुरू करने से पहले पृथक्करण, Devin प्रमाणीकरण और मॉडल खोज
की दोबारा जाँच करता है। यह कभी भी होस्ट के Claude निष्पादन योग्य को नहीं चलाता। मॉडल उपनाम
`.env.devin-bridge` में सेट किए जा सकते हैं; प्रत्येक कॉन्फ़िगर किए गए मान में
`devin-cli-agentic/` उपसर्ग बना रहना चाहिए।

## सत्यापन कमांड

पुनरुत्पाद्य ऑफ़लाइन पथ के लिए किसी Devin खाते की आवश्यकता नहीं होती और इसमें रनटाइम इंटरनेट नहीं होता:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणित, वैकल्पिक रूप से सक्षम किया जाने वाला लाइव पथ है:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

लाइव रनर ACP सत्रों को एक साथ बड़ी संख्या में खोलने से बचने के लिए परिदृश्यों के बीच प्रतीक्षा करता है और
पाठ्य दावों पर भरोसा करने के बजाय संरचित Claude स्ट्रीम इवेंट को सत्यापित करता है। इसके तीन
परिदृश्य निम्नलिखित सिद्ध करते हैं:

1. प्रत्यक्ष प्रोजेक्ट पठन और दोष विश्लेषण;
2. एक वास्तविक `Edit`, क्लाइंट-स्वामित्व वाला `Bash` `npm test` और एक अंतिम परिणाम;
3. `/bridge-check` के साथ `bridge-proof` खोज, प्रोजेक्ट पठन, एक और सफल
   क्लाइंट-स्वामित्व वाला `npm test` और किसी लंबित कार्य के बिना पूर्णता।

अंतिम गेट Devin नेटवर्क ऑडिट की भी जाँच करता है और यह आवश्यक करता है कि Claude आउटबाउंड ऑडिट
रिक्त बना रहे।

## पिन किए गए टूल्स को अपडेट करना

इमेज में Node, Claude Code और Devin CLI को
`docker/devin-bridge/Dockerfile` में पिन किया गया है। अपडेट करने के लिए:

1. स्पष्ट रूप से निर्दिष्ट संस्करण बदलें;
2. दोनों आर्किटेक्चर-विशिष्ट Devin आर्काइव चेकसम को आधिकारिक
   आर्टिफ़ैक्ट के मानों से बदलें;
3. पुनः बिल्ड करें और प्रत्येक ऑफ़लाइन सत्यापन कमांड चलाएँ;
4. इमेज के भीतर संस्करणों की पुष्टि करें;
5. प्रमाणीकृत तीन-परिदृश्य वाली लाइव सुइट को फिर से चलाएँ।

होस्ट पर किसी भी CLI को ग्लोबली इंस्टॉल न करें और चेकसम सत्यापन को किसी
असत्यापित डाउनलोड से न बदलें।

## निदान और क्लीनअप

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानीय रूटिंग और सैनिटाइज़ की गई एक्ज़ीक्यूटर त्रुटियाँ दिखाता है।
- `.sandbox/evidence/mock-acp.jsonl` निर्धारक मॉक ACP कार्रवाइयों को रिकॉर्ड करती है।
- `.sandbox/evidence/claude-stream.jsonl` वास्तविक Claude Code ऑफ़लाइन रन को रिकॉर्ड करती है।
- `.sandbox/evidence/live-*.jsonl` तीन सत्यापित लाइव स्ट्रीम को रिकॉर्ड करती हैं।
- `.sandbox/evidence/egress.jsonl` और `.sandbox/evidence/claude-egress.jsonl` गार्ड ऑडिट की सत्यापित,
  टोकन-मुक्त प्रतियाँ हैं।

लॉगिन/कॉन्फ़िग वॉल्यूम सुरक्षित रखते हुए स्वामित्व वाले कंटेनर और नेटवर्क रोकें:

```bash
./scripts/devin-bridge/clean
```

नामित वॉल्यूम सहित, ब्रिज के स्वामित्व वाला पूरा एनवायरनमेंट हटाएँ:

```bash
./scripts/devin-bridge/clean --all
```

## सीमाएँ

- ब्रिज निश्चित, बिना-टूल वाली `summarizer` भूमिका पर निर्भर है, क्योंकि Devin CLI `3000.2.17`
  किसी तटस्थ, बिना-टूल वाले ACP एजेंट को उपलब्ध नहीं कराता। अडैप्टर सारांश-जैसी
  मध्यवर्ती प्रतिक्रियाओं की भरपाई करता है, लेकिन एक सीमित रिपेयर फिर भी स्पष्ट रूप से विफल हो सकती है।
- लाइव ACP कॉल क्षणिक `502`/`504` प्रतिक्रियाएँ लौटा सकती हैं। हार्नेस परिदृश्यों के बीच अंतराल रखता है;
  लगातार विफलता की स्थिति में यह फेल-क्लोज़्ड रहता है और कभी भी किसी अन्य प्रोवाइडर का चयन नहीं करता।
- ACP कॉन्टेक्स्ट प्रत्येक Anthropic अनुरोध से पुनर्निर्मित किया जाता है; कोई प्रोसेस/सेशन
  एफ़िनिटी नहीं है।
- प्रत्येक मॉडल प्रतिक्रिया में एक टूल कॉल समर्थित है; समानांतर कॉल अस्वीकार की जाती हैं।
- इमेज स्पष्ट रूप से असमर्थित हैं। विज़न, थिंकिंग आउटपुट, एफ़र्ट कंट्रोल और 1M
  कॉन्टेक्स्ट विंडो को विज्ञापित नहीं किया जाता।
- SSE मान्य Anthropic लाइफ़साइकल इवेंट का उपयोग करता है, लेकिन इसे सीमित ACP टर्न
  एकत्र होने के बाद उत्सर्जित किया जाता है; ACP चंक क्रमिक रूप से फ़ॉरवर्ड नहीं किए जाते।
