`devin-cli-agentic` ช่วยให้รันไทม์ Claude Code จริงสามารถใช้ตำแหน่งข้อมูล Messages ของ Anthropic ภายในเครื่องของ OmniRoute ขณะที่ Devin CLI อย่างเป็นทางการส่งคำตอบของโมเดลผ่าน ACP stdio โดยไม่แก้ไขผู้ให้บริการ Anthropic, Claude OAuth, Claude Web หรือ `devin-cli` ที่มีอยู่

สำหรับการเรียกใช้เครื่องมือที่ไคลเอนต์เป็นผู้ควบคุม ให้กำหนดเส้นทางผ่าน `devin-cli-agentic` (นามแฝง `dva`) ซึ่งเป็นผู้ให้บริการที่รองรับเครื่องมือในรูปแบบ Claude ส่วนตัวดำเนินการ ACP แบบเดิม `devin-cli` (`dv`) รองรับเฉพาะข้อความ โดยจะเรียกใช้ตัวสรุปแบบไม่ใช้เครื่องมือของ Devin และไม่สามารถส่งคืนการเรียกใช้เครื่องมือได้ เมทาดาทาของโมเดลถูกทำเครื่องหมายไว้ตามนั้น เพื่อให้การกำหนดเส้นทางแบบคอมโบที่จำเป็นต้องใช้เครื่องมือหลีกเลี่ยงโมเดลนี้

> **สถานะปัจจุบัน: ปักหมุด Claude Code `2.1.258`; การตรวจสอบแบบออฟไลน์และแบบใช้งานจริงถูกบันทึกล่าสุด
> บน `2.1.220`** การปักหมุด `2.1.220` ทำสามสถานการณ์แบบแยกส่วนเสร็จสมบูรณ์ผ่าน Devin CLI
> `3000.2.17` และโมเดล `swe-1-7-lightning`; การรันจริงครั้งสุดท้ายนั้นยืนยันเทิร์น `Read`,
> `Edit` และ `Bash` ที่ไคลเอนต์เป็นผู้ควบคุม, ผลลัพธ์ `npm test` ที่สำเร็จ, การค้นหาคำสั่งและสกิล
> ของโปรเจกต์, การกำหนดเส้นทางผ่าน Devin เท่านั้น และไม่มีทราฟฟิกขาออกไปยัง Claude จากนั้นจึงเพิ่มการปักหมุดเป็น `2.1.258`
> (รุ่น CLI ที่การปลอมแปลงอัตลักษณ์ Claude ของ OmniRoute ใช้ และเป็นรุ่นแรกที่มาพร้อม
> ระดับ Fable 5.1 โดยตรง) สำหรับการปักหมุดใหม่นี้ ชั้นการติดตั้งและ `claude --version` ได้รับ
> การตรวจสอบบนอิมเมจฐานที่ปักหมุดแล้ว และชุดยูนิตเทสต์ของบริดจ์, `compose config` และ
> หลักฐานการแยกแบบสแตติกผ่านทั้งหมด — แต่สถานการณ์จำลองแบบออฟไลน์และชุดสถานการณ์จริงทั้งสาม
> ยังไม่ได้รันซ้ำ โปรดรันอีกครั้ง (ดู "การอัปเดตเครื่องมือที่ปักหมุด") ก่อนใช้งาน
> บริดจ์โดยอาศัยการปักหมุดนี้

## สถาปัตยกรรม

```text
Claude Code 2.1.258 (คอนเทนเนอร์ Linux แบบแยกส่วนที่ไม่ใช่ root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (รูปแบบ Claude, ผู้ให้บริการที่ไม่ต้องยืนยันตัวตน)
  -> devin acp --agent-type summarizer (ACP stdio อย่างเป็นทางการ, ไม่มีเครื่องมือ Devin)
  -> บัญชี Devin ในโวลุ่ม devin-auth โดยเฉพาะ
```

เอเจนต์ ACP เริ่มต้นของ CLI อย่างเป็นทางการสามารถเรียกใช้เครื่องมือของตัวเองได้ ดังนั้นบริดจ์นี้จึงไม่ใช้เอเจนต์ดังกล่าว แต่จะเริ่มเอเจนต์ ACP `summarizer` แบบคงที่ ซึ่งโหมด CLI อย่างเป็นทางการไม่มีเครื่องมือ และจัดกรอบคำขอ Anthropic ที่ซีเรียลไลซ์แล้วเป็นร่องรอยการดำเนินการ เมื่อต้องมีการดำเนินการอื่นที่ Claude เป็นผู้ควบคุม การตอบกลับต้องมีเอนเวโลปเครื่องมือฝั่งไคลเอนต์เพียงหนึ่งรายการเท่านั้น `tool_call` หรือ `tool_call_update` ใดๆ จาก ACP จะถูกปฏิเสธก่อนที่จะสามารถรายงานว่าการตอบกลับสำเร็จ

ซีเรียลไลเซอร์ใน `open-sse/executors/devin-agentic/serializer.ts` จะรักษา `system`, `text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` และเครื่องมือที่ Claude Code จัดเตรียมไว้ รูปภาพและบล็อกที่ไม่รู้จักจะล้มเหลวอย่างชัดเจน ผลลัพธ์เครื่องมือขนาดใหญ่จะใช้เครื่องหมายตัดทอนที่มองเห็นได้

พาร์เซอร์ยอมรับเอนเวโลป `<tool>{...}</tool>` แบบเดี่ยวที่แยกจากเนื้อหาอื่นได้หนึ่งรายการต่อเทิร์นของโมเดล โดยจะตรวจสอบชื่อเทียบกับรายการเครื่องมือของคำขอ ตรวจสอบอาร์กิวเมนต์เทียบกับ JSON Schema ของเครื่องมือนั้น ปฏิเสธการผสมข้อความบรรยายกับการดำเนินการ และอนุญาตให้ซ่อมแซมได้หนึ่งครั้งภายใต้ขอบเขตที่กำหนด จากนั้น Claude Code จะเรียกใช้ `tool_use` ของ Anthropic ที่ได้ภายในเครื่อง และส่ง `tool_result` กลับผ่าน OmniRoute

## การกำหนดเส้นทางอัตโนมัติ

ผู้ให้บริการนี้มีสิทธิ์อยู่ในพูลตัวเลือก `auto/*` ของ OmniRoute เมื่อไม่ได้ถูกบล็อก การมีสิทธิ์เป็นตัวเลือกไม่ได้รับประกันว่าจะถูกเลือก: กลยุทธ์การกำหนดเส้นทางของคอมโบ (ตัวอย่างเช่น last-known-good) อาจเลือกผู้ให้บริการรายอื่นก่อน ใช้ `dva/<model>` หรือคอมโบที่ให้ Devin มาก่อน เมื่อคุณต้องการให้ทุกคำขอผ่าน Devin

## การแยกสภาพแวดล้อมและแบบจำลองภัยคุกคาม

การติดตั้ง บัญชี และการกำหนดค่า Claude ของโฮสต์อยู่นอกขอบเขตและถือเป็นสิ่งต้องห้าม บริการ Compose:

- ทำงานด้วย UID/GID `10001:10001` โดยใช้ระบบไฟล์รากแบบอ่านอย่างเดียว ปลดความสามารถต่าง ๆ และใช้
  `no-new-privileges`;
- ใช้ `/home/bridge` แบบส่วนตัว, โวลุ่มการกำหนดค่า Claude โดยเฉพาะ, ข้อมูล OmniRoute ที่แยกออกจากกัน
  และโวลุ่ม `devin-auth` แยกต่างหาก;
- เมานต์เฉพาะพื้นที่ทำงาน/หลักฐาน `.sandbox` ที่ใช้แล้วทิ้งได้;
- ไม่เมานต์โฮมของโฮสต์, Keychain, ข้อมูลประจำตัว SSH, ข้อมูลประจำตัวระบบคลาวด์ หรือซ็อกเก็ต Docker;
- สร้างสภาพแวดล้อมอย่างชัดเจนและลบตัวแปร API/OAuth/การกำหนดเส้นทางของ Anthropic;
- กำหนดให้การอนุมานของ Claude Code ไปยัง `http://omniroute:20128` เท่านั้น โดยใช้คีย์เฉพาะภายในเครื่อง

โปรไฟล์ออฟไลน์ใช้เครือข่ายภายใน ในโปรไฟล์ไลฟ์ OmniRoute เชื่อมต่อไปยัง
เอ็นด์พอยต์อย่างเป็นทางการของ Devin ผ่าน `network-guard` เท่านั้น และปฏิเสธปลายทางอื่นที่ไม่เกี่ยวข้อง
Claude Code มีตัวป้องกันทราฟฟิกขาออกแบบปฏิเสธทั้งหมดแยกต่างหาก และสามารถเชื่อมต่อได้เฉพาะบริการ OmniRoute
ภายในเครื่องผ่าน `NO_PROXY` ไฟล์บันทึกการตรวจสอบของตัวป้องกันจะถูกเมานต์เฉพาะโดยโปรเซสตัวป้องกันของไฟล์นั้น
สคริปต์จะตรวจสอบความเป็นเจ้าของไฟล์ โหมด จำนวนลิงก์ และทุกการตัดสินใจก่อนส่งออก
หลักฐานที่ไม่มีโทเค็น

เรียกใช้การพิสูจน์การแยกสภาพแวดล้อมโดยอิสระ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

คำสั่งนี้ตรวจสอบโทโพโลยี เมานต์ที่มีชื่อ การตั้งค่าแบบไม่ใช้ root/อ่านอย่างเดียว การกำหนดเส้นทางภายในเครื่องอย่างชัดเจน
การไม่มีตัวแปรสภาพแวดล้อมที่ละเอียดอ่อน การไม่มีซ็อกเก็ต Docker การบล็อกการเข้าถึง
`api.anthropic.com` และ `claude.ai` การเลือกผู้ให้บริการเฉพาะ Devin และการล้มเหลวอย่างชัดเจนเมื่อ
แบ็กเอนด์ ACP ไม่พร้อมใช้งาน

## การตั้งค่าครั้งแรกและการใช้งานตามปกติ

สร้างอิมเมจที่ตรึงเวอร์ชันไว้:

```bash
./scripts/devin-bridge/build
```

ยืนยันตัวตนเฉพาะในโวลุ่ม Devin ที่แยกไว้:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

คำสั่งล็อกอินใช้ขั้นตอนโทเค็นแบบป้อนเองอย่างเป็นทางการ ซึ่งออกแบบมาสำหรับสภาพแวดล้อม
ระยะไกล/คอนเทนเนอร์ ค่าจะถูกป้อนลงในพรอมต์ CLI โดยตรง โดยไม่ถูกส่งเป็น
อาร์กิวเมนต์ของโปรเซส เขียนลงใน Git หรือคัดลอกจากโฮสต์

เปิดใช้รันไทม์ Claude Code ที่แยกสภาพแวดล้อม:

```bash
./scripts/devin-bridge/launch
```

`launch` จะตรวจสอบการแยกสภาพแวดล้อม การยืนยันตัวตน Devin และการค้นพบโมเดลอีกครั้งก่อนเริ่ม
Claude Code ภายในคอนเทนเนอร์ โดยจะไม่เรียกใช้ไฟล์ปฏิบัติการ Claude ของโฮสต์ สามารถกำหนดนามแฝงของโมเดล
ได้ใน `.env.devin-bridge`; ค่าที่กำหนดค่าทุกรายการต้องคงคำนำหน้า
`devin-cli-agentic/` ไว้

## คำสั่งตรวจสอบความถูกต้อง

เส้นทางออฟไลน์ที่ทำซ้ำได้ไม่ต้องใช้บัญชี Devin และไม่มีอินเทอร์เน็ตขณะรันไทม์:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

เส้นทางไลฟ์แบบเลือกใช้ซึ่งผ่านการยืนยันตัวตนคือ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ตัวรันไลฟ์จะรอระหว่างแต่ละสถานการณ์เพื่อหลีกเลี่ยงการเปิดเซสชัน ACP จำนวนมากพร้อมกัน และ
ตรวจสอบอีเวนต์สตรีม Claude แบบมีโครงสร้างแทนการเชื่อถือข้อความกล่าวอ้าง สถานการณ์ทั้งสาม
พิสูจน์ว่า:

1. สามารถอ่านโปรเจกต์โดยตรงและวิเคราะห์ข้อบกพร่องได้;
2. มีการใช้ `Edit` จริง, `Bash` `npm test` ที่ไคลเอนต์เป็นเจ้าของ และผลลัพธ์ปลายทาง;
3. มีการค้นพบ `/bridge-check` และ `bridge-proof`, การอ่านโปรเจกต์, การรัน
   `npm test` ที่ไคลเอนต์เป็นเจ้าของอีกครั้งจนสำเร็จ และเสร็จสิ้นโดยไม่มีงานค้าง

เกตสุดท้ายยังตรวจสอบบันทึกการตรวจสอบเครือข่ายของ Devin และกำหนดให้บันทึกการตรวจสอบทราฟฟิกขาออกของ Claude
ยังคงว่างเปล่า

## การอัปเดตเครื่องมือที่ตรึงเวอร์ชันไว้

อิมเมจตรึงเวอร์ชันของ Node, Claude Code และ Devin CLI ไว้ใน
`docker/devin-bridge/Dockerfile` เมื่อต้องการอัปเดต:

1. เปลี่ยนเวอร์ชันที่ระบุไว้อย่างชัดเจน;
2. แทนที่ checksum ของไฟล์เก็บถาวร Devin สำหรับแต่ละสถาปัตยกรรมทั้งสองรายการด้วยค่าของอาร์ติแฟกต์อย่างเป็นทางการ;
3. สร้างใหม่และเรียกใช้คำสั่งตรวจสอบแบบออฟไลน์ทั้งหมด;
4. ยืนยันเวอร์ชันภายในอิมเมจ;
5. เรียกใช้ชุดทดสอบแบบไลฟ์สามสถานการณ์ที่ผ่านการยืนยันตัวตนอีกครั้ง

อย่าติดตั้ง CLI ใดๆ จากทั้งสองรายการแบบโกลบอลบนโฮสต์ หรือแทนที่การตรวจสอบ checksum ด้วยการดาวน์โหลดที่ไม่ได้รับการตรวจสอบ

## การวินิจฉัยและการทำความสะอาด

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  แสดงการกำหนดเส้นทางภายในเครื่องและข้อผิดพลาดของตัวดำเนินการที่ผ่านการล้างข้อมูลละเอียดอ่อนแล้ว
- `.sandbox/evidence/mock-acp.jsonl` บันทึกการดำเนินการ ACP จำลองแบบให้ผลลัพธ์คงที่
- `.sandbox/evidence/claude-stream.jsonl` บันทึกการเรียกใช้ Claude Code แบบออฟไลน์จริง
- `.sandbox/evidence/live-*.jsonl` บันทึกสตรีมแบบไลฟ์ที่ผ่านการตรวจสอบแล้วทั้งสามรายการ
- `.sandbox/evidence/egress.jsonl` และ `.sandbox/evidence/claude-egress.jsonl` เป็นสำเนาบันทึกการตรวจสอบทราฟฟิกขาออกที่ผ่านการตรวจสอบแล้วและไม่มีโทเค็น

หยุดคอนเทนเนอร์และเครือข่ายที่ระบบเป็นเจ้าของ โดยคงโวลุ่มล็อกอิน/การกำหนดค่าไว้:

```bash
./scripts/devin-bridge/clean
```

ลบสภาพแวดล้อมทั้งหมดที่บริดจ์เป็นเจ้าของ รวมถึงโวลุ่มที่มีชื่อ:

```bash
./scripts/devin-bridge/clean --all
```

## ข้อจำกัด

- บริดจ์อาศัยบทบาท `summarizer` แบบไม่มีเครื่องมือที่กำหนดไว้ตายตัว เนื่องจาก Devin CLI `3000.2.17`
  ไม่มีเอเจนต์ ACP ที่เป็นกลางและไม่มีเครื่องมือ อะแดปเตอร์จะชดเชยการตอบกลับระหว่างทางที่มีรูปแบบคล้ายบทสรุป
  แต่การซ่อมแซมแบบจำกัดหนึ่งครั้งยังคงอาจล้มเหลวอย่างชัดเจนได้
- การเรียก ACP แบบไลฟ์อาจส่งคืนการตอบกลับชั่วคราว `502`/`504` ชุดทดสอบจะเว้นระยะระหว่างสถานการณ์ต่างๆ;
  ความล้มเหลวต่อเนื่องจะยังคงปิดระบบอย่างปลอดภัยและจะไม่เลือกผู้ให้บริการรายอื่น
- บริบท ACP จะถูกสร้างขึ้นใหม่จากคำขอ Anthropic แต่ละรายการ โดยไม่มีความผูกพันกับโปรเซส/เซสชัน
- รองรับการเรียกใช้เครื่องมือหนึ่งครั้งต่อการตอบกลับของโมเดล; การเรียกใช้แบบขนานจะถูกปฏิเสธ
- ไม่รองรับรูปภาพอย่างชัดเจน ไม่มีการประกาศรองรับวิชัน เอาต์พุตกระบวนการคิด การควบคุมระดับความพยายาม และหน้าต่างบริบท 1M
- SSE ใช้อีเวนต์วงจรชีวิตของ Anthropic ที่ถูกต้อง แต่จะส่งออกหลังจากรวบรวมรอบ ACP แบบจำกัดเรียบร้อยแล้ว;
  ส่วนข้อมูล ACP จะไม่ถูกส่งต่อแบบเพิ่มทีละส่วน
