`devin-cli-agentic` વાસ્તવિક Claude Code runtime ને OmniRoute ના સ્થાનિક Anthropic
Messages endpoint નો ઉપયોગ કરવાની મંજૂરી આપે છે, જ્યારે અધિકૃત Devin CLI ACP stdio પર મોડલ પ્રતિસાદો પૂરા પાડે છે. તે
હાલના Anthropic, Claude OAuth, Claude Web, અથવા `devin-cli` providers માં ફેરફાર કરતું નથી.

ક્લાયન્ટ-માલિકીના tool calls માટે, Claude-format tool-સક્ષમ provider એવા
`devin-cli-agentic` (ઉપનામ `dva`) મારફતે route કરો. લેગસી `devin-cli` (`dv`) ACP executor
માત્ર-text છે: તે Devin નું no-tools summarizer ચલાવે છે અને tool calls પરત કરી શકતું નથી. તેનું model
metadata તે મુજબ ચિહ્નિત છે, જેથી tool-આવશ્યક combo routing તેને ટાળશે.

> **વર્તમાન સ્થિતિ: Claude Code `2.1.258` પર pin કરેલું; offline અને live validation છેલ્લે
> `2.1.220` પર નોંધાયું હતું.** `2.1.220` pin એ Devin CLI
> `3000.2.17` અને model `swe-1-7-lightning` મારફતે ત્રણ અલગ scenarios પૂર્ણ કર્યા; તે અંતિમ live run એ ક્લાયન્ટ-માલિકીના `Read`,
> `Edit`, અને `Bash` turns, સફળ `npm test` પરિણામો, project command અને skill
> discovery, માત્ર-Devin routing, અને શૂન્ય Claude egress સાબિત કર્યા. ત્યારબાદ pin ને `2.1.258` સુધી વધારવામાં આવ્યું
> (OmniRoute ની Claude identity જે CLI generation નું પ્રતિરૂપણ કરે છે, અને Fable 5.1 tier ને
> મૂળભૂત રીતે સમાવતી પ્રથમ line). નવા pin પર pinned base image માં install layer અને `claude --version`
> ચકાસવામાં આવ્યા હતા, અને bridge unit suite, `compose config` તથા
> static isolation proof સફળ થાય છે — પરંતુ offline mock scenario અને live ત્રણ-scenario
> suite હજી ફરીથી ચલાવવામાં આવ્યા નથી. આ pin સાથે bridge પર આધાર રાખતા પહેલાં તેમને ફરીથી ચલાવો
> ("Updating pinned tools" જુઓ).

## આર્કિટેક્ચર

```text
Claude Code 2.1.258 (અલગ કરેલું non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (અધિકૃત ACP stdio, કોઈ Devin tools નહીં)
  -> સમર્પિત devin-auth volume માં Devin account
```

અધિકૃત CLI નો default ACP agent પોતાના tools ચલાવી શકે છે, તેથી આ bridge તેનો ઉપયોગ કરતું નથી.
તે નિશ્ચિત `summarizer` ACP agent શરૂ કરે છે, જેના અધિકૃત CLI mode માં કોઈ tools નથી, અને
serialized Anthropic request ને execution trace તરીકે frame કરે છે. જ્યારે Claude-માલિકીની બીજી
ક્રિયા જરૂરી હોય, ત્યારે પ્રતિસાદમાં ચોક્કસ એક client tool envelope હોવું આવશ્યક છે. કોઈપણ ACP
`tool_call` અથવા `tool_call_update` ને પ્રતિસાદ સફળ તરીકે નોંધાઈ શકે તે પહેલાં નકારવામાં આવે છે.

`open-sse/executors/devin-agentic/serializer.ts` માં રહેલું serializer `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, અને
Claude Code દ્વારા પૂરા પાડવામાં આવેલા tools ને જાળવી રાખે છે. Images અને અજ્ઞાત blocks સ્પષ્ટપણે નિષ્ફળ થાય છે. મોટા tool results
દૃશ્યમાન truncation marker નો ઉપયોગ કરે છે.

Parser દરેક model turn દીઠ એક સ્વતંત્ર `<tool>{...}</tool>` envelope સ્વીકારે છે. તે
request ની tool list સામે name તપાસે છે, તે tool ના JSON Schema સામે arguments ને validate કરે છે,
મિશ્ર narrative/actions ને નકારે છે, અને એક મર્યાદિત repair ની મંજૂરી આપે છે. ત્યારબાદ Claude Code
પરિણામી Anthropic `tool_use` ને સ્થાનિક રીતે ચલાવે છે અને `tool_result` ને OmniRoute મારફતે પાછું મોકલે છે.

## સ્વચાલિત routing

Provider અવરોધિત ન હોય ત્યારે તે OmniRoute ના `auto/*` candidate pools માં પાત્ર છે.
Candidate eligibility પસંદગીની ખાતરી આપતી નથી: combo ની routing strategy (ઉદાહરણ તરીકે,
last-known-good) અન્ય provider ને પ્રાધાન્ય આપી શકે છે. જ્યારે દરેક request Devin મારફતે જવી જરૂરી હોય ત્યારે
`dva/<model>` અથવા Devin-first combo નો ઉપયોગ કરો.

## આઇસોલેશન અને જોખમ મોડેલ

હોસ્ટનું Claude ઇન્સ્ટોલેશન, એકાઉન્ટ અને રૂપરેખાંકન કાર્યક્ષેત્રની બહાર છે અને તેને
પ્રતિબંધિત માનવામાં આવે છે. Compose સેવાઓ:

- UID/GID `10001:10001` તરીકે, ફક્ત-વાંચી શકાય તેવી રૂટ ફાઇલસિસ્ટમ, દૂર કરેલી ક્ષમતાઓ અને
  `no-new-privileges` સાથે ચાલે છે;
- ખાનગી `/home/bridge`, સમર્પિત Claude config વોલ્યુમ, અલગ રાખેલો OmniRoute ડેટા
  અને અલગ `devin-auth` વોલ્યુમ વાપરે છે;
- ફક્ત નિકાલ કરી શકાય તેવા `.sandbox` વર્કસ્પેસ/પુરાવા માઉન્ટ કરે છે;
- હોસ્ટનું હોમ, Keychain, SSH, ક્લાઉડ ઓળખપત્રો અથવા Docker socket માઉન્ટ કરતી નથી;
- સ્પષ્ટ એન્વાયર્નમેન્ટ બનાવે છે અને Anthropic API/OAuth/રાઉટિંગ વેરિએબલ દૂર કરે છે;
- Claude Code ઇન્ફરન્સને ફક્ત સ્થાનિક-ઉપયોગ માટેની કી સાથે `http://omniroute:20128` તરફ દોરે છે.

ઓફલાઇન પ્રોફાઇલ આંતરિક નેટવર્ક વાપરે છે. લાઇવ પ્રોફાઇલમાં, OmniRoute ફક્ત `network-guard`
દ્વારા અધિકૃત Devin એન્ડપોઇન્ટ સુધી પહોંચે છે; અસંબંધિત ગંતવ્યો નકારવામાં આવે છે.
Claude Code પાસે અલગ deny-all ઇગ્રેસ ગાર્ડ છે અને તે `NO_PROXY` દ્વારા ફક્ત સ્થાનિક
OmniRoute સેવા સુધી પહોંચી શકે છે. ગાર્ડ ઑડિટ ફાઇલો ફક્ત તેમની સંબંધિત ગાર્ડ પ્રક્રિયા
દ્વારા માઉન્ટ કરવામાં આવે છે. સ્ક્રિપ્ટ્સ ટોકન-મુક્ત પુરાવા નિકાસ કરતાં પહેલાં ફાઇલની
માલિકી, મોડ, લિંકની સંખ્યા અને દરેક નિર્ણય ચકાસે છે.

આઇસોલેશનનો પુરાવો સ્વતંત્ર રીતે ચલાવો:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

તે ટોપોલોજી, નામિત માઉન્ટ્સ, non-root/ફક્ત-વાંચી શકાય તેવી સેટિંગ્સ, સ્પષ્ટ સ્થાનિક રાઉટિંગ,
સંવેદનશીલ એન્વાયર્નમેન્ટ વેરિએબલ્સની ગેરહાજરી, Docker socketની ગેરહાજરી,
`api.anthropic.com` અને `claude.ai` સુધી અવરોધિત ઍક્સેસ, ફક્ત-Devin પ્રોવાઇડરની પસંદગી
અને ACP બૅકએન્ડ અનુપલબ્ધ હોય ત્યારે સ્પષ્ટ નિષ્ફળતાને માન્ય કરે છે.

## પ્રથમ વખતનું સેટઅપ અને સામાન્ય ઉપયોગ

પિન કરેલી ઇમેજ બિલ્ડ કરો:

```bash
./scripts/devin-bridge/build
```

ફક્ત અલગ રાખેલા Devin વોલ્યુમને પ્રમાણિત કરો:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

લૉગિન કમાન્ડ રિમોટ/કન્ટેનર એન્વાયર્નમેન્ટ માટે બનાવાયેલ અધિકૃત મેન્યુઅલ-ટોકન પ્રવાહનો
ઉપયોગ કરે છે. મૂલ્ય સીધું CLI પ્રોમ્પ્ટમાં દાખલ કરવામાં આવે છે; તેને પ્રોસેસ આર્ગ્યુમેન્ટ
તરીકે પાસ કરવામાં આવતું નથી, Gitમાં લખવામાં આવતું નથી અથવા હોસ્ટ પરથી કૉપી કરવામાં
આવતું નથી.

અલગ રાખેલ Claude Code રનટાઇમ લૉન્ચ કરો:

```bash
./scripts/devin-bridge/launch
```

કન્ટેનરાઇઝ્ડ Claude Code શરૂ કરતાં પહેલાં `launch` આઇસોલેશન, Devin પ્રમાણીકરણ અને
મોડેલ શોધની ફરી ચકાસણી કરે છે. તે ક્યારેય હોસ્ટનું Claude executable ચલાવતું નથી.
મોડેલ ઉપનામો `.env.devin-bridge`માં સેટ કરી શકાય છે; દરેક રૂપરેખાંકિત મૂલ્યમાં
`devin-cli-agentic/` પ્રીફિક્સ જાળવવો આવશ્યક છે.

## માન્યતા કમાન્ડ્સ

પુનરુત્પાદિત કરી શકાય તેવા ઓફલાઇન પાથ માટે Devin એકાઉન્ટની જરૂર નથી અને તેમાં રનટાઇમ
Internet નથી:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

પ્રમાણિત, સ્વૈચ્છિક રીતે સક્રિય કરાતો લાઇવ પાથ આ છે:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP સેશન્સ એકસાથે મોટી સંખ્યામાં ખોલવાનું ટાળવા માટે લાઇવ રનર દૃશ્યો વચ્ચે રાહ જુએ છે
અને ટેક્સ્ટ દાવાઓ પર વિશ્વાસ કરવાને બદલે સંરચિત Claude સ્ટ્રીમ ઇવેન્ટ્સને માન્ય કરે છે.
તેના ત્રણ દૃશ્યો આ બાબતો સાબિત કરે છે:

1. સીધું પ્રોજેક્ટ વાંચન અને ખામીનું વિશ્લેષણ;
2. વાસ્તવિક `Edit`, ક્લાયન્ટની માલિકીનું `Bash` `npm test` અને ટર્મિનલ પરિણામ;
3. `/bridge-check` સાથે `bridge-proof` શોધ, પ્રોજેક્ટ વાંચન, ક્લાયન્ટની માલિકીનું બીજું
   સફળ `npm test` અને કોઈ બાકી કાર્ય વિના પૂર્ણતા.

અંતિમ ગેટ Devin નેટવર્ક ઑડિટને પણ ચકાસે છે અને Claude ઇગ્રેસ ઑડિટ ખાલી રહે તે જરૂરી
બનાવે છે.

## પિન કરેલ ટૂલ્સ અપડેટ કરવા

ઇમેજમાં Node, Claude Code અને Devin CLI ને
`docker/devin-bridge/Dockerfile` માં પિન કરવામાં આવ્યા છે. અપડેટ કરવા માટે:

1. સ્પષ્ટ વર્ઝનો બદલો;
2. બંને આર્કિટેક્ચર-વિશિષ્ટ Devin આર્કાઇવ ચેકસમને અધિકૃત
   આર્ટિફેક્ટ માટેનાં મૂલ્યોથી બદલો;
3. ફરીથી બિલ્ડ કરો અને દરેક ઑફલાઇન માન્યતા કમાન્ડ ચલાવો;
4. ઇમેજની અંદરનાં વર્ઝનોની પુષ્ટિ કરો;
5. પ્રમાણીકૃત ત્રણ-પરિદૃશ્યવાળી લાઇવ સ્યુટ ફરીથી ચલાવો.

કોઈપણ CLI ને હોસ્ટ પર વૈશ્વિક રીતે ઇન્સ્ટૉલ કરશો નહીં અથવા ચેકસમ ચકાસણીને
ચકાસણી ન કરેલા ડાઉનલોડથી બદલશો નહીં.

  સ્થાનિક રાઉટિંગ અને સેનિટાઇઝ કરેલી એક્ઝિક્યુટર ભૂલો દર્શાવે છે.

- `.sandbox/evidence/claude-stream.jsonl` વાસ્તવિક Claude Code ઑફલાઇન રન રેકોર્ડ કરે છે.
- `.sandbox/evidence/live-*.jsonl` ચકાસેલી ત્રણ લાઇવ સ્ટ્રીમ રેકોર્ડ કરે છે.

લૉગિન/કન્ફિગ વૉલ્યુમ જાળવી રાખીને માલિકીવાળા કન્ટેનર અને નેટવર્ક બંધ કરો:

## મર્યાદાઓ

- બ્રિજ નિશ્ચિત, ટૂલ-રહિત `summarizer` ભૂમિકા પર આધાર રાખે છે, કારણ કે Devin CLI `3000.2.17`
  તટસ્થ, ટૂલ-રહિત ACP એજન્ટ ઉપલબ્ધ કરાવતું નથી. એડેપ્ટર સારાંશ-સ્વરૂપના
  મધ્યવર્તી પ્રતિસાદોની ભરપાઈ કરે છે, પરંતુ એક મર્યાદિત રિપેર હજુ પણ સ્પષ્ટ રીતે નિષ્ફળ થઈ શકે છે.
- લાઇવ ACP કૉલ્સ ક્ષણિક `502`/`504` પ્રતિસાદ આપી શકે છે. હાર્નેસ પરિદૃશ્યો વચ્ચે અંતર રાખે છે;
  સતત નિષ્ફળતાની સ્થિતિમાં તે ફેલ-ક્લોઝ્ડ રહે છે અને ક્યારેય અન્ય પ્રોવાઇડર પસંદ કરતું નથી.
- દરેક Anthropic વિનંતીમાંથી ACP કોન્ટેક્સ્ટનું પુનઃનિર્માણ થાય છે; કોઈ પ્રોસેસ/સેશન
  એફિનિટી નથી.
- દરેક મોડલ પ્રતિસાદ દીઠ એક ટૂલ કૉલ સમર્થિત છે; સમાંતર કૉલ્સ નકારવામાં આવે છે.
- ઇમેજ સ્પષ્ટ રીતે અસમર્થિત છે. વિઝન, થિંકિંગ આઉટપુટ, એફર્ટ કંટ્રોલ્સ અને 1M
  કોન્ટેક્સ્ટ વિન્ડોની જાહેરાત કરવામાં આવતી નથી.
- SSE માન્ય Anthropic લાઇફસાઇકલ ઇવેન્ટ્સનો ઉપયોગ કરે છે, પરંતુ મર્યાદિત ACP ટર્ન
  એકત્ર થયા પછી તે ઉત્સર્જિત થાય છે; ACP ચંક્સ તબક્કાવાર ફોરવર્ડ કરવામાં આવતા નથી.
