> Vykdymo laiko perjungikliai, kurie keičia OmniRoute elgseną **be pakartotinio diegimo**.
> Kiekviena čia išvardyta vėliavėlė yra apibrėžta faile
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> – vieninteliame tiesos šaltinyje. Prietaisų skydelis ir REST API abu skaito iš
> to failo, todėl žemiau esanti lentelė yra sugeneruota taip, kad atitiktų jį 1:1.

---

## Kas yra funkcijų vėliavėlės

Funkcijų vėliavėlė yra pavadintas perjungiklis (loginis arba išvardijimo tipo), kurio reikšmę galima keisti vykdymo metu ir išsaugoti duomenų bazėje, nereikalaujant pakartotinio proceso diegimo. Kiekviena vėliavėlė aprašoma `FeatureFlagDefinition` su `key`, `label`, `description`, `category`, `defaultValue`, `type` ir `requiresRestart` užuomina.

### Išsprendimo tvarka

**Efektyvioji vėliavėlės reikšmė** išsprendžiama naudojant
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) su šia
prioritetų tvarka (didžiausias laimi):

1.  **DB perrašymas** – reikšmė, saugoma `key_value` lentelėje `feature_flags` vardų srityje (nustatyta per prietaisų skydelį arba REST API).
2.  **Aplinkos kintamasis** – `process.env[<KEY>]`, jei nustatytas ir ne tuščias.
3.  **Apibrėžimo numatytoji reikšmė** – `defaultValue` iš `featureFlagDefinitions.ts`.

Loginė vėliavėlė laikoma **įjungta**, kai jos efektyvioji reikšmė yra `"true"`,
`"1"` arba `"yes"` (žr. `isFeatureFlagEnabled()`).

> [!NOTE]
> Dauguma vėliavėlių taip pat turi atitinkamą aplinkos kintamąjį **tokiu pačiu pavadinimu**,
> aprašytą [`ENVIRONMENT.md`](./ENVIRONMENT.md). Vėliavėlės DB perrašymas
> turi pirmenybę prieš tą aplinkos kintamąjį. Vėliavėlė su
> `requiresRestart: true` išsaugoma iš karto, bet iš naujo nuskaitoma tik paleidus procesą – ją perjungus prietaisų skydelyje pasirodo **"Perkrauti serverį"** pranešimas.

| `CREDENTIAL_GATE_AUTH_DIAGNOSES_ONLY`     | boolean | `false`            | Susiaurina jungtinį prisijungimo duomenų filtrą, kad talpykloje saugomas nepavykęs prisijungimo duomenų patikrinimas blokuotų ryšį tik tada, kai jo diagnozė patvirtina netinkamus prisijungimo duomenis (`upstream_auth_error`, `auth_missing`, `token_expired`, `token_refresh_failed`, `reauth_required`, `account_deactivated`, `auth_required`). Neįtikinami sutrikimai (skirtojo laiko viršijimai, užklausų dažnio apribojimai, paslaugų sutrikimai, nepalaikomi patikrinimai ir netipizuotos planuoklio klaidos) tuomet laikomi nežinomais, o ryšys ir toliau gauna srautą. Pagal numatytuosius nustatymus išjungta: bet kokia talpykloje saugoma patikrinimo klaida blokuoja ryšį visą talpyklos TTL laikotarpį (5 minutes). |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` ir jo senasis pseudonimas
> `INJECTION_GUARD_BLOCK_THRESHOLD` reguliuoja `INJECTION_GUARD_MODE`
> režimą `block`, tačiau tai yra paprasti aplinkos kintamieji, kuriuos nuskaito
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts),
> o ne funkcijų vėliavėlės: jų negalima perrašyti DB ir jiems nėra valdymo skydelio jungiklio. Žr.
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> Stulpelyje `Restart` pažymėtos vėliavėlės, turinčios `requiresRestart: true` — reikšmė
> išsaugoma iš karto, tačiau įsigalioja tik iš naujo įkėlus procesą. Išvardijimo
> vėliavėlės atmeta bet kokią reikšmę, nepatenkančią į leidžiamą rinkinį (serverio pusėje tikrinama
> ir `setFeatureFlagOverride()`, ir REST `PUT` apdorojimo programoje).

## Funkcijų vėliavėlių perjungimas

### Valdymo skydas

Eikite į **Valdymo skydas → Nustatymai → Funkcijų vėliavėlės**
(`/dashboard/settings/feature-flags`). Tinklelis
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
leidžia:

- **Ieškoti** pagal raktą arba aprašą ir **filtruoti** pagal kategoriją (taip pat yra sintetinė
  **Reikia paleisti iš naujo** peržiūra).
- Naudoti **perjungiklį** loginėms vėliavėlėms ir **išskleidžiamąjį sąrašą** išvardijimo vėliavėlėms
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Matyti kiekvienos vėliavėlės **šaltinio ženklelį** — `DB`, `ENV` arba `DEF` — nurodantį, iš kur
  gauta galiojanti reikšmė.
- Naudoti mygtuką **Atkurti** (rodomą tik vėliavėlėms, kurių šaltinis yra `DB`) perrašymui pašalinti
  ir apačioje esantį mygtuką **Atkurti visus perrašymus**.
- Matyti reklamjuostę **Paleisti serverį iš naujo**, kai pakeičiama `requiresRestart` vėliavėlė.

### REST API

Visos operacijos atliekamos per vieną maršrutą:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Kiekvienam metodui reikalinga autentifikuota valdymo skydo sesija (kitu atveju grąžinama `401`).

#### `GET /api/settings/feature-flags`

Grąžina visas vėliavėles su jų galiojančia reikšme, šaltiniu ir suvestine.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Reikalauti API rakto",
      "description": "Reikalauti API rakto visoms gaunamoms užklausoms",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... visos 108 vėliavėlės
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Nustato arba pašalina vieną perrašymą. Turinys: `{ key: string; value?: string }`.
Praleidus `value`, perrašymas pašalinamas (atkuriama aplinkos kintamojo / numatytoji reikšmė).

```bash
# Nustatyti DB perrašymą
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Pašalinti perrašymą (be "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Atsakyme pakartojamos naujos `effectiveValue`/`source`, ankstesnės `previousValue`/
`previousSource` ir `requiresRestart` reikšmės. Nežinomi raktai ir į diapazoną nepatenkančios išvardijimo
reikšmės atmetamos grąžinant `400`.

#### `DELETE /api/settings/feature-flags`

Vienu metu pašalina **visus** DB perrašymus, atkuriant kiekvienos vėliavėlės aplinkos kintamojo / numatytąją
reikšmę. Grąžina `{ cleared: <kiekis>, message: "..." }`.

> [!NOTE]
> Vėliavėlės, kurių `requiresRestart: true`, įsigalioja tik iš naujo įkėlus procesą.
> Valdymo skydo paleidimo iš naujo eiga iškviečia `POST /api/restart`, o tada periodiškai siunčia užklausą
> `GET /api/health/ping`, kol serveris vėl pradeda veikti.

## Avarinis biudžeto atsarginis mechanizmas

`OMNIROUTE_EMERGENCY_FALLBACK` (kategorija `runtime`, numatytoji reikšmė `true`) valdo
avarinį nemokamo atsarginio maršruto mechanizmą faile
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kai jis įjungtas, užklausos, išnaudojusios savo biudžetą, nukreipiamos į nemokamą
atsarginį teikėją / modelį, užuot iš karto baigiamos klaida. Nustatykite reikšmę
`false` (arba `0`) — naudodami valdymo skydelio jungiklį, DB perrašą arba
`OMNIROUTE_EMERGENCY_FALLBACK` aplinkos kintamąjį — kad išjungtumėte šią elgseną ir
leistumėte išnaudojus biudžetą užklausas baigti klaida. (Valdymo skydelio jungiklis
pridėtas PR #3741 / #3752.)

Naudojant šį atsarginį mechanizmą pateiktame atsakyme yra
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, todėl
klientas gali nustatyti, kad užklausa buvo nukreipta iš naujo, nelygindamas
`X-OmniRoute-Provider` su savo užklausa. Visuose kituose atsakymuose šios antraštės
nėra.
