`devin-cli-agentic` haqiqiy Claude Code ish muhitiga OmniRoute’ning mahalliy Anthropic
Messages endpointidan foydalanish imkonini beradi, bunda rasmiy Devin CLI model javoblarini ACP stdio orqali taqdim etadi. U
mavjud Anthropic, Claude OAuth, Claude Web yoki `devin-cli` provayderlarini o‘zgartirmaydi.

Mijozga tegishli vosita chaqiruvlari uchun Claude formatidagi, vositalarni qo‘llab-quvvatlaydigan
`devin-cli-agentic` (taxallusi `dva`) provayderi orqali yo‘naltiring. Eski `devin-cli` (`dv`) ACP ijrochisi
faqat matn bilan ishlaydi: u Devin’ning vositalarsiz xulosalovchisini ishga tushiradi va vosita chaqiruvlarini qaytara olmaydi. Uning model
metama’lumotlari shunga mos belgilangan, shu sababli vositalarni talab qiladigan kombinatsiyalangan yo‘naltirish undan foydalanmaydi.

> **Joriy holat: Claude Code `2.1.258` versiyasiga mahkamlangan; oflayn va jonli tekshiruv oxirgi marta
> `2.1.220` versiyasida qayd etilgan.** `2.1.220` versiyasiga mahkamlash Devin CLI
> `3000.2.17` va `swe-1-7-lightning` modeli orqali uchta izolyatsiyalangan ssenariyni yakunladi; o‘sha yakuniy jonli ishga tushirish mijozga tegishli `Read`,
> `Edit` va `Bash` bosqichlarini, muvaffaqiyatli `npm test` natijalarini, loyiha buyruqlari va ko‘nikmalarining
> aniqlanishini, faqat Devin orqali yo‘naltirishni hamda Claude’ga hech qanday tashqi trafik yo‘qligini tasdiqladi. Keyin mahkamlangan versiya `2.1.258` ga
> ko‘tarildi (OmniRoute’ning Claude identifikatori taqlid qiladigan CLI avlodi va
> Fable 5.1 darajasini mahalliy tarzda taqdim etadigan birinchi liniya). Yangi mahkamlangan versiyada o‘rnatish qatlami va `claude --version`
> mahkamlangan asosiy tasvirda tekshirildi, shuningdek, ko‘prikning modul testlari, `compose config` va
> statik izolyatsiya isboti muvaffaqiyatli o‘tadi — biroq oflayn soxta ssenariy va jonli uch ssenariyli
> testlar to‘plami hali qayta ishga tushirilmagan. Ushbu mahkamlangan versiyali ko‘prikka tayanishdan oldin ularni qayta ishga tushiring
> ("Mahkamlangan vositalarni yangilash" bo‘limiga qarang).

## Arxitektura

```text
Claude Code 2.1.258 (izolyatsiyalangan, root bo‘lmagan Linux konteyneri)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude formati, autentifikatsiyasiz provayder)
  -> devin acp --agent-type summarizer (rasmiy ACP stdio, Devin vositalarisiz)
  -> maxsus devin-auth jildidagi Devin hisobi
```

Rasmiy CLI’ning standart ACP agenti o‘z vositalarini bajara oladi, shuning uchun ushbu ko‘prik undan
foydalanmaydi. U rasmiy CLI rejimida vositalarga ega bo‘lmagan, belgilangan `summarizer` ACP agentini ishga tushiradi va
ketma-ketlashtirilgan Anthropic so‘rovini bajarilish trassasi sifatida formatlaydi. Claude’ga tegishli boshqa
amal kerak bo‘lganda, javob aynan bitta mijoz vositasi konvertini o‘z ichiga olishi shart. Har qanday ACP
`tool_call` yoki `tool_call_update` javob muvaffaqiyatli deb xabar qilinishidan oldin rad etiladi.

`open-sse/executors/devin-agentic/serializer.ts` faylidagi serializator `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` va
Claude Code taqdim etgan vositalarni saqlab qoladi. Tasvirlar va noma’lum bloklar aniq xato bilan yakunlanadi. Katta vosita natijalarida
ko‘rinadigan qisqartirish belgisi ishlatiladi.

Tahlil qiluvchi har bir model bosqichida bitta alohida `<tool>{...}</tool>` konvertini qabul qiladi. U nomni
so‘rovdagi vositalar ro‘yxatiga nisbatan tekshiradi, argumentlarni ushbu vositaning JSON
Schema’siga muvofiq tekshiradi, bayon va amallar aralashmasini rad etadi hamda bitta cheklangan tuzatishga ruxsat beradi. Keyin Claude Code
hosil bo‘lgan Anthropic `tool_use` amalini mahalliy tarzda bajaradi va `tool_result` natijasini OmniRoute orqali
qayta yuboradi.

## Avtomatik yo‘naltirish

Provayder bloklanmaganida OmniRoute’ning `auto/*` nomzodlar havzalariga kiritilishi mumkin.
Nomzod sifatida mos kelish tanlanishni kafolatlamaydi: kombinatsiyaning yo‘naltirish strategiyasi (masalan,
oxirgi muvaffaqiyatli variant) boshqa provayderni afzal ko‘rishi mumkin. Har bir so‘rov Devin orqali o‘tishi
shart bo‘lsa, `dva/<model>` yoki Devin’ni birinchi o‘ringa qo‘yadigan kombinatsiyadan foydalaning.

## Izolyatsiya va tahdid modeli

Hostdagi Claude o‘rnatmasi, hisobi va konfiguratsiyasi qamrov doirasidan tashqarida bo‘lib, ulardan foydalanish taqiqlangan deb hisoblanadi. Compose xizmatlari:

- UID/GID `10001:10001` bilan, faqat o‘qish uchun mo‘ljallangan ildiz fayl tizimi, olib tashlangan imkoniyatlar va `no-new-privileges` bilan ishlaydi;
- shaxsiy `/home/bridge`, maxsus Claude konfiguratsiya jildi, izolyatsiya qilingan OmniRoute ma’lumotlari va alohida `devin-auth` jildidan foydalanadi;
- faqat bir martalik `.sandbox` ish maydonlari/dalillarini ulaydi;
- hostning bosh katalogi, Keychain, SSH, bulut hisob ma’lumotlari yoki Docker soketini ulamaydi;
- aniq muhitlarni yaratadi hamda Anthropic API/OAuth/marshrutlash o‘zgaruvchilarini olib tashlaydi;
- Claude Code inferensiyasini faqat mahalliy kalit bilan `http://omniroute:20128` manziliga yo‘naltiradi.

Oflayn profil ichki tarmoqdan foydalanadi. Jonli profilda OmniRoute rasmiy Devin endpointlariga faqat `network-guard` orqali ulanadi; aloqasiz manzillarga kirish rad etiladi. Claude Code alohida, barcha tashqi ulanishlarni rad etuvchi himoyaga ega va `NO_PROXY` orqali faqat mahalliy OmniRoute xizmatiga ulana oladi. Himoya audit fayllari faqat tegishli himoya jarayoni tomonidan ulanadi. Skriptlar tokensiz dalillarni eksport qilishdan oldin fayl egaligi, rejimi, havolalar soni va har bir qarorni tekshiradi.

Izolyatsiya isbotini mustaqil ravishda ishga tushiring:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

U topologiya, nomlangan ulanishlar, root bo‘lmagan/faqat o‘qish sozlamalari, aniq mahalliy marshrutlash, maxfiy muhit o‘zgaruvchilarining yo‘qligi, Docker soketining yo‘qligi, `api.anthropic.com` va `claude.ai` manzillariga kirish bloklanganligi, faqat Devin provayderi tanlangani hamda ACP backend mavjud bo‘lmaganda aniq xatolik yuz berishini tekshiradi.

## Dastlabki sozlash va odatiy foydalanish

Qayd etilgan versiyadagi tasvirni yarating:

```bash
./scripts/devin-bridge/build
```

Faqat izolyatsiya qilingan Devin jildida autentifikatsiyadan o‘ting:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Kirish buyrug‘i masofaviy/konteyner muhitlari uchun mo‘ljallangan rasmiy qo‘lda token kiritish jarayonidan foydalanadi. Qiymat to‘g‘ridan-to‘g‘ri CLI so‘roviga kiritiladi; u jarayon argumenti sifatida uzatilmaydi, Git’ga yozilmaydi yoki hostdan nusxalanmaydi.

Izolyatsiya qilingan Claude Code bajarilish muhitini ishga tushiring:

```bash
./scripts/devin-bridge/launch
```

`launch` konteynerlashtirilgan Claude Code’ni ishga tushirishdan oldin izolyatsiya, Devin autentifikatsiyasi va modellar aniqlanganini qayta tekshiradi. U hech qachon hostdagi Claude bajariluvchi faylini ishga tushirmaydi. Model taxalluslarini `.env.devin-bridge` faylida belgilash mumkin; sozlangan har bir qiymat `devin-cli-agentic/` prefiksini saqlashi kerak.

## Tekshirish buyruqlari

Takrorlanadigan oflayn yo‘l Devin hisobini talab qilmaydi va bajarilish vaqtida Internetga ulanmaydi:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Autentifikatsiya qilingan, ixtiyoriy ravishda yoqiladigan jonli yo‘l:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Jonli sinov vositasi ACP seanslarini birdaniga ochmaslik uchun ssenariylar orasida kutadi va matnli da’volarga ishonish o‘rniga tuzilmali Claude oqim hodisalarini tekshiradi. Uning uchta ssenariysi quyidagilarni isbotlaydi:

1. loyiha fayllarini to‘g‘ridan-to‘g‘ri o‘qish va nuqsonlarni tahlil qilish;
2. haqiqiy `Edit`, mijoz boshqaruvidagi `Bash` `npm test` va yakuniy natija;
3. `/bridge-check` hamda `bridge-proof` aniqlanishi, loyiha fayllarini o‘qish, mijoz boshqaruvidagi yana bir muvaffaqiyatli `npm test` va kutilayotgan ish qolmasdan yakunlash.

Yakuniy nazorat Devin tarmoq auditini ham tekshiradi va Claude tashqi ulanish auditining bo‘sh qolishini talab qiladi.

## Biriktirilgan vositalarni yangilash

Tasvirda Node, Claude Code va Devin CLI versiyalari
`docker/devin-bridge/Dockerfile` faylida biriktirilgan. Yangilash uchun:

1. aniq ko‘rsatilgan versiyalarni o‘zgartiring;
2. arxitekturaga xos har ikkala Devin arxivi nazorat summasini rasmiy
   artefakt qiymatlari bilan almashtiring;
3. qayta yig‘ing va barcha oflayn tekshiruv buyruqlarini bajaring;
4. tasvir ichidagi versiyalarni tasdiqlang;
5. autentifikatsiya qilingan uch ssenariyli jonli testlar to‘plamini qayta ishga tushiring.

Har ikkala CLI vositasini ham xostga global tarzda o‘rnatmang va nazorat summasi bilan tekshirishni
tekshirilmagan yuklab olish bilan almashtirmang.

## Tashxis va tozalash

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  mahalliy marshrutlash va maxfiy ma’lumotlardan tozalangan bajaruvchi xatolarini ko‘rsatadi.
- `.sandbox/evidence/mock-acp.jsonl` deterministik soxta ACP amallarini qayd etadi.
- `.sandbox/evidence/claude-stream.jsonl` haqiqiy Claude Code oflayn ishga tushirilishini qayd etadi.
- `.sandbox/evidence/live-*.jsonl` tekshirilgan uchta jonli oqimni qayd etadi.
- `.sandbox/evidence/egress.jsonl` va `.sandbox/evidence/claude-egress.jsonl` qo‘riqlash auditlarining tekshirilgan,
  tokenlardan xoli nusxalaridir.

Kirish/konfiguratsiya jildlarini saqlagan holda tegishli konteynerlar va tarmoqlarni to‘xtating:

```bash
./scripts/devin-bridge/clean
```

Nomlangan jildlarni ham o‘z ichiga olgan holda bridge’ga tegishli muhitni to‘liq olib tashlang:

```bash
./scripts/devin-bridge/clean --all
```

## Cheklovlar

- Bridge qat’iy belgilangan, vositalarsiz `summarizer` roliga tayanadi, chunki Devin CLI `3000.2.17`
  neytral, vositalarsiz ACP agentini taqdim etmaydi. Adapter xulosa shaklidagi
  oraliq javoblarni kompensatsiya qiladi, biroq bitta chegaralangan tuzatish hali ham aniq xatolik bilan yakunlanishi mumkin.
- Jonli ACP chaqiruvlari vaqtinchalik `502`/`504` javoblarini qaytarishi mumkin. Sinov vositasi ssenariylarni vaqt oralig‘i bilan bajaradi;
  doimiy nosozlik yopiq holatda rad etiladi va hech qachon boshqa provayderni tanlamaydi.
- ACP konteksti har bir Anthropic so‘rovidan qayta tiklanadi; jarayon/seansga
  bog‘liqlik yo‘q.
- Har bir model javobida bitta vosita chaqiruvi qo‘llab-quvvatlanadi; parallel chaqiruvlar rad etiladi.
- Tasvirlar aniq ravishda qo‘llab-quvvatlanmaydi. Ko‘rish, fikrlash natijasi, sa’y-harakat boshqaruvlari va 1M
  kontekst oynasi e’lon qilinmaydi.
- SSE yaroqli Anthropic hayot sikli hodisalaridan foydalanadi, ammo chegaralangan ACP bosqichi
  yig‘ib bo‘lingandan keyin chiqariladi; ACP bo‘laklari bosqichma-bosqich uzatilmaydi.
