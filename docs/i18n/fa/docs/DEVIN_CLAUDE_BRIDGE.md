`devin-cli-agentic` به محیط اجرای واقعی Claude Code اجازه میدهد از نقطه پایانی محلی Anthropic
Messages متعلق به OmniRoute استفاده کند، درحالیکه CLI رسمی Devin پاسخهای مدل را از طریق ACP stdio ارائه میکند. این
ارائهدهندههای موجود Anthropic، Claude OAuth، Claude Web یا `devin-cli` را تغییر نمیدهد.

برای فراخوانی ابزارهایی که در اختیار کلاینت هستند، درخواستها را از طریق `devin-cli-agentic` (نام مستعار `dva`)، یعنی
ارائهدهنده دارای قابلیت ابزار با قالب Claude، مسیریابی کنید. اجراکننده قدیمی ACP یعنی `devin-cli` (`dv`)
فقط متنی است: خلاصهساز بدون ابزار Devin را اجرا میکند و نمیتواند فراخوانی ابزار برگرداند. فراداده مدل آن
نیز بر همین اساس علامتگذاری شده است تا مسیریابی ترکیبیِ نیازمند ابزار از آن اجتناب کند.

> **وضعیت فعلی: Claude Code روی نسخه `2.1.258` پین شده است؛ آخرین اعتبارسنجی آفلاین و زنده
> روی `2.1.220` ثبت شده است.** پین `2.1.220` سه سناریوی ایزوله را از طریق Devin CLI
> `3000.2.17` و مدل `swe-1-7-lightning` تکمیل کرد؛ آن اجرای زنده نهایی، نوبتهای `Read`،
> `Edit` و `Bash` متعلق به کلاینت، نتایج موفق `npm test`، کشف فرمانها و مهارتهای
> پروژه، مسیریابی صرفاً از طریق Devin و عدم خروج هیچ ترافیکی به Claude را اثبات کرد. سپس پین به `2.1.258`
> ارتقا یافت (نسلی از CLI که هویت Claude در OmniRoute جعل میکند و نخستین شاخهای که
> رده Fable 5.1 را بهصورت بومی عرضه میکند). روی پین جدید، لایه نصب و `claude --version`
> در ایمیج پایه پینشده بررسی شدند و مجموعه تست واحد پل، `compose config` و
> اثبات ایزولاسیون ایستا موفق هستند — اما سناریوی ماک آفلاین و مجموعه سهسناریویی زنده
> هنوز دوباره اجرا نشدهاند. پیش از اتکا به پل با این پین، آنها را دوباره اجرا کنید
> (به بخش «بهروزرسانی ابزارهای پینشده» مراجعه کنید).

## معماری

```text
Claude Code 2.1.258 (کانتینر لینوکس ایزوله غیرریشه)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (ارائهدهنده با قالب Claude و بدون احراز هویت)
  -> devin acp --agent-type summarizer (ACP stdio رسمی، بدون ابزارهای Devin)
  -> حساب Devin در volume اختصاصی devin-auth
```

عامل پیشفرض ACP در CLI رسمی میتواند ابزارهای خودش را اجرا کند، بنابراین این پل از
آن استفاده نمیکند. پل عامل ثابت `summarizer` در ACP را راهاندازی میکند که حالت رسمی CLI آن فاقد ابزار است و
درخواست سریالسازیشده Anthropic را در قالب یک رد اجرای عملیات چارچوببندی میکند. هرگاه اقدام دیگری متعلق به Claude
لازم باشد، پاسخ باید دقیقاً شامل یک پوشش ابزار کلاینت باشد. هرگونه
`tool_call` یا `tool_call_update` مربوط به ACP پیش از آنکه پاسخی موفق گزارش شود، رد میشود.

سریالساز موجود در `open-sse/executors/devin-agentic/serializer.ts` موارد `system`،
`text`، `tool_use`، `tool_result`، `thinking`، `redacted_thinking`، `tool_choice` و
ابزارهای ارائهشده توسط Claude Code را حفظ میکند. تصاویر و بلوکهای ناشناخته صراحتاً با شکست مواجه میشوند. نتایج بزرگ ابزار
از یک نشانگر قابلمشاهده برای کوتاهسازی استفاده میکنند.

تجزیهگر در هر نوبت مدل، یک پوشش مستقل `<tool>{...}</tool>` را میپذیرد. این تجزیهگر
نام را با فهرست ابزارهای درخواست تطبیق میدهد، آرگومانها را با JSON
Schema همان ابزار اعتبارسنجی میکند، ترکیب روایت و عملیات را رد میکند و یک تلاش اصلاحی محدود را مجاز میداند. سپس Claude Code
فراخوانی Anthropic `tool_use` حاصل را بهصورت محلی اجرا میکند و `tool_result` را از طریق
OmniRoute بازمیفرستد.

## مسیریابی خودکار

این ارائهدهنده، درصورتیکه مسدود نشده باشد، واجد شرایط حضور در مجموعه نامزدهای `auto/*` متعلق به OmniRoute است.
واجد شرایط بودن یک نامزد، انتخاب آن را تضمین نمیکند: راهبرد مسیریابی ترکیب (برای مثال،
آخرین گزینه موفق شناختهشده) ممکن است ارائهدهنده دیگری را ترجیح دهد. وقتی لازم است
هر درخواست از طریق Devin عبور کند، از `dva/<model>` یا یک ترکیب با اولویت Devin استفاده کنید.

## ایزولهسازی و مدل تهدید

نصب، حساب و پیکربندی Claude روی میزبان خارج از محدوده هستند و ممنوع تلقی میشوند. سرویسهای Compose:

- با UID/GID برابر با `10001:10001`، سیستم فایل ریشهٔ فقطخواندنی، قابلیتهای حذفشده و
  `no-new-privileges` اجرا میشوند؛
- از یک `/home/bridge` خصوصی، یک volume اختصاصی برای پیکربندی Claude، دادههای ایزولهٔ OmniRoute
  و یک volume جداگانهٔ `devin-auth` استفاده میکنند؛
- فقط workspaceها/شواهد یکبارمصرف `.sandbox` را mount میکنند؛
- پوشهٔ home میزبان، Keychain، اعتبارنامههای SSH و سرویسهای ابری یا socket داکر را mount نمیکنند؛
- محیطها را بهصورت صریح میسازند و متغیرهای API/OAuth/مسیریابی Anthropic را حذف میکنند؛
- استنتاج Claude Code را فقط با یک کلید صرفاً محلی به `http://omniroute:20128` هدایت میکنند.

پروفایل آفلاین از یک شبکهٔ داخلی استفاده میکند. در پروفایل زنده، OmniRoute فقط از طریق
`network-guard` به endpointهای رسمی Devin دسترسی پیدا میکند؛ مقصدهای نامرتبط رد میشوند.
Claude Code دارای یک محافظ خروجی جداگانه با سیاست رد همه است و فقط میتواند از طریق
`NO_PROXY` به سرویس محلی OmniRoute دسترسی پیدا کند. فایلهای ممیزی محافظها فقط توسط
فرایند محافظ مربوط به خودشان mount میشوند. اسکریپتها پیش از export کردن شواهد بدون token،
مالکیت فایل، mode، تعداد linkها و تکتک تصمیمها را بررسی میکنند.

اثبات ایزولهسازی را بهطور مستقل اجرا کنید:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

این دستور توپولوژی، mountهای نامگذاریشده، تنظیمات non-root/فقطخواندنی، مسیریابی محلی صریح،
نبود متغیرهای محیطی حساس، نبود socket داکر، مسدود بودن دسترسی به
`api.anthropic.com` و `claude.ai`، انتخاب provider فقط از Devin و شکست صریح در صورت
در دسترس نبودن backend مربوط به ACP را اعتبارسنجی میکند.

## راهاندازی اولیه و استفادهٔ عادی

image سنجاقشده را build کنید:

```bash
./scripts/devin-bridge/build
```

فقط volume ایزولهٔ Devin را احراز هویت کنید:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

دستور ورود از جریان رسمی token دستی که برای محیطهای راهدور/container طراحی شده است استفاده
میکند. مقدار مستقیماً در prompt ابزار CLI وارد میشود؛ بهعنوان آرگومان فرایند ارسال نمیشود،
در Git نوشته نمیشود و از میزبان کپی نمیشود.

محیط اجرای ایزولهٔ Claude Code را راهاندازی کنید:

```bash
./scripts/devin-bridge/launch
```

`launch` پیش از راهاندازی Claude Code کانتینریشده، ایزولهسازی، احراز هویت Devin و کشف model
را دوباره بررسی میکند. این دستور هرگز فایل اجرایی Claude میزبان را اجرا نمیکند. aliasهای model
را میتوان در `.env.devin-bridge` تنظیم کرد؛ تمام مقادیر پیکربندیشده باید پیشوند
`devin-cli-agentic/` را حفظ کنند.

## دستورهای اعتبارسنجی

مسیر آفلاینِ قابلبازتولید به حساب Devin نیاز ندارد و در زمان اجرا به اینترنت دسترسی ندارد:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

مسیر زندهٔ نیازمند احراز هویت و با فعالسازی اختیاری به این صورت است:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

اجراکنندهٔ زنده بین سناریوها منتظر میماند تا از باز کردن ناگهانی چندین session مربوط به ACP
جلوگیری کند و بهجای اعتماد به ادعاهای متنی، eventهای ساختیافتهٔ stream مربوط به Claude را
اعتبارسنجی میکند. سه سناریوی آن موارد زیر را اثبات میکنند:

1. خواندن مستقیم پروژه و تحلیل نقص؛
2. یک `Edit` واقعی، اجرای `npm test` از نوع `Bash` و تحت مالکیت client، و یک نتیجهٔ نهایی؛
3. کشف `/bridge-check` بههمراه `bridge-proof`، خواندن پروژه، یک اجرای موفق دیگر از
   `npm test` تحت مالکیت client، و تکمیل بدون کار در انتظار.

دروازهٔ نهایی همچنین ممیزی شبکهٔ Devin را بررسی میکند و ایجاب میکند که ممیزی خروجی Claude
خالی باقی بماند.

## بهروزرسانی ابزارهای پینشده

ایمیج، نسخههای Node، Claude Code و Devin CLI را در
`docker/devin-bridge/Dockerfile` پین میکند. برای بهروزرسانی:

1. نسخههای صریح را تغییر دهید؛
2. هر دو checksum آرشیو Devin مختص معماری را با مقادیر artifact رسمی جایگزین کنید؛
3. ایمیج را دوباره بسازید و همه فرمانهای اعتبارسنجی آفلاین را اجرا کنید؛
4. نسخهها را داخل ایمیج تأیید کنید؛
5. مجموعه زنده احراز هویتشده شامل سه سناریو را دوباره اجرا کنید.

هیچیک از CLIها را بهصورت سراسری روی میزبان نصب نکنید و تأیید checksum را با یک
دانلود تأییدنشده جایگزین نکنید.

## عیبیابی و پاکسازی

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  مسیریابی محلی و خطاهای پاکسازیشده اجراکننده را نشان میدهد.
- `.sandbox/evidence/mock-acp.jsonl` کنشهای قطعی ACP آزمایشی را ثبت میکند.
- `.sandbox/evidence/claude-stream.jsonl` اجرای آفلاین واقعی Claude Code را ثبت میکند.
- `.sandbox/evidence/live-*.jsonl` سه جریان زنده اعتبارسنجیشده را ثبت میکند.
- `.sandbox/evidence/egress.jsonl` و `.sandbox/evidence/claude-egress.jsonl` نسخههای اعتبارسنجیشده و بدون توکن از ممیزیهای خروجی هستند.

کانتینرها و شبکههای تحت مالکیت را متوقف کنید، درحالیکه volumeهای ورود/پیکربندی حفظ میشوند:

```bash
./scripts/devin-bridge/clean
```

کل محیط تحت مالکیت bridge، از جمله volumeهای نامگذاریشده، را حذف کنید:

```bash
./scripts/devin-bridge/clean --all
```

## محدودیتها

- bridge به نقش ثابت و بدون ابزار `summarizer` متکی است، زیرا Devin CLI `3000.2.17`
  یک عامل خنثی ACP بدون ابزار ارائه نمیکند. adapter پاسخهای میانی با ساختار خلاصهمانند
  را جبران میکند، اما یک ترمیم محدودشده همچنان ممکن است صراحتاً با شکست مواجه شود.
- فراخوانیهای زنده ACP ممکن است پاسخهای موقت `502`/`504` برگردانند. harness بین سناریوها
  فاصله ایجاد میکند؛ شکست مداوم همچنان بهصورت fail-closed مدیریت میشود و هرگز ارائهدهنده دیگری انتخاب نمیشود.
- context مربوط به ACP از هر درخواست Anthropic بازسازی میشود؛ هیچ وابستگی
  process/session وجود ندارد.
- در هر پاسخ مدل، یک فراخوانی ابزار پشتیبانی میشود؛ فراخوانیهای موازی رد میشوند.
- تصاویر صراحتاً پشتیبانی نمیشوند. قابلیت بینایی، خروجی تفکر، کنترلهای effort و پنجره
  context یکمیلیونی اعلام نمیشوند.
- SSE از رویدادهای معتبر چرخه حیات Anthropic استفاده میکند، اما پس از جمعآوری نوبت محدودشده
  ACP منتشر میشود؛ chunkهای ACP بهصورت تدریجی ارسال نمیشوند.
