`devin-cli-agentic` საშუალებას აძლევს ნამდვილ Claude Code-ის runtime-ს გამოიყენოს OmniRoute-ის ლოკალური Anthropic
Messages endpoint, მაშინ როცა ოფიციალური Devin CLI მოდელის პასუხებს ACP stdio-ის მეშვეობით აწვდის. ის
არ ცვლის არსებულ Anthropic, Claude OAuth, Claude Web ან `devin-cli` პროვაიდერებს.

კლიენტის მიერ მართულ ხელსაწყოთა გამოძახებებისთვის მარშრუტი გაატარეთ `devin-cli-agentic`-ის (ალიასი `dva`) —
Claude-ის ფორმატის, ხელსაწყოების მხარდაჭერის მქონე პროვაიდერის — გავლით. ძველი `devin-cli` (`dv`) ACP შემსრულებელი
მხოლოდ ტექსტურია: ის უშვებს Devin-ის ხელსაწყოების არმქონე შემაჯამებელს და ხელსაწყოთა გამოძახებებს ვერ აბრუნებს. მისი მოდელის
მეტამონაცემები შესაბამისადაა მონიშნული, რათა ხელსაწყოს მომთხოვნმა კომბინირებულმა მარშრუტიზაციამ მას გვერდი აუაროს.

> **მიმდინარე სტატუსი: დაფიქსირებულია Claude Code `2.1.258`; ოფლაინ და ცოცხალი ვალიდაცია ბოლოს
> `2.1.220`-ზე დაფიქსირდა.** `2.1.220`-ის ფიქსაციამ Devin CLI
> `3000.2.17`-ისა და მოდელ `swe-1-7-lightning`-ის მეშვეობით სამი იზოლირებული სცენარი დაასრულა; ამ საბოლოო ცოცხალმა გაშვებამ დაადასტურა კლიენტის მიერ მართული `Read`,
> `Edit` და `Bash` ნაბიჯები, `npm test`-ის წარმატებული შედეგები, პროექტის ბრძანებებისა და უნარების
> აღმოჩენა, მხოლოდ Devin-ზე მარშრუტიზაცია და Claude-ისკენ ნულოვანი გამავალი ტრაფიკი. შემდეგ ფიქსირებული ვერსია `2.1.258`-მდე
> გაიზარდა (CLI-ის თაობა, რომლის Claude-იდენტობასაც OmniRoute განასახიერებს, და პირველი ხაზი, რომელსაც
> Fable 5.1 დონე ნატიურად მოჰყვება). ახალ ფიქსირებულ ვერსიაზე ინსტალაციის ფენა და `claude --version`
> ფიქსირებულ საბაზისო image-ზე შემოწმდა, ხოლო ხიდის unit-ტესტების ნაკრები, `compose config` და
> სტატიკური იზოლაციის მტკიცებულება წარმატებით სრულდება — თუმცა ოფლაინ mock-სცენარი და ცოცხალი სამსცენარიანი
> ნაკრები ჯერ ხელახლა არ გაშვებულა. ამ ფიქსირებულ ვერსიაზე ხიდის გამოყენებამდე ხელახლა გაუშვით ისინი (იხილეთ „ფიქსირებული ხელსაწყოების განახლება“).

## არქიტექტურა

```text
Claude Code 2.1.258 (იზოლირებული არა-root Linux-კონტეინერი)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ის ფორმატი, ავტორიზაციის არმომთხოვნი პროვაიდერი)
  -> devin acp --agent-type summarizer (ოფიციალური ACP stdio, Devin-ის ხელსაწყოების გარეშე)
  -> Devin-ის ანგარიში გამოყოფილ devin-auth volume-ში
```

ოფიციალური CLI-ის ნაგულისხმევ ACP აგენტს საკუთარი ხელსაწყოების შესრულება შეუძლია, ამიტომ ეს ხიდი
მას არ იყენებს. ის უშვებს ფიქსირებულ `summarizer` ACP აგენტს, რომლის ოფიციალურ CLI-რეჟიმსაც ხელსაწყოები არ აქვს, და
სერიალიზებულ Anthropic-მოთხოვნას შესრულების კვალის სახით აფორმებს. როდესაც Claude-ის მიერ მართული კიდევ ერთი
მოქმედებაა საჭირო, პასუხი ზუსტად ერთ კლიენტის ხელსაწყოს envelope-ს უნდა შეიცავდეს. ნებისმიერი ACP
`tool_call` ან `tool_call_update` უარყოფილია, სანამ პასუხი
წარმატებულად გამოცხადდება.

`open-sse/executors/devin-agentic/serializer.ts`-ში არსებული სერიალიზატორი ინარჩუნებს `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`-სა და
Claude Code-ის მიერ მოწოდებულ ხელსაწყოებს. სურათები და უცნობი ბლოკები აშკარა შეცდომით სრულდება. ხელსაწყოების დიდი შედეგები
იყენებს ხილულ შეკვეცის მარკერს.

პარსერი მოდელის თითო ნაბიჯზე ერთ დამოუკიდებელ `<tool>{...}</tool>` envelope-ს იღებს. ის სახელს
მოთხოვნის ხელსაწყოთა სიასთან ამოწმებს, არგუმენტებს ამ ხელსაწყოს JSON
Schema-ს მიხედვით ამოწმებს, შერეულ ნარატივსა და მოქმედებებს უარყოფს და ერთ შეზღუდულ შესწორებას უშვებს. შემდეგ Claude Code
მიღებულ Anthropic `tool_use`-ს ლოკალურად ასრულებს და `tool_result`-ს OmniRoute-ის გავლით
უკან აგზავნის.

## ავტომატური მარშრუტიზაცია

როდესაც პროვაიდერი დაბლოკილი არ არის, მას შეუძლია OmniRoute-ის `auto/*` კანდიდატთა პულებში მონაწილეობა.
კანდიდატად დაშვება არჩევას არ უზრუნველყოფს: კომბინაციის მარშრუტიზაციის სტრატეგიამ (მაგალითად,
ბოლო ცნობილმა წარმატებულმა) შეიძლება სხვა პროვაიდერს მიანიჭოს უპირატესობა. გამოიყენეთ `dva/<model>` ან Devin-ისთვის პრიორიტეტის მიმნიჭებელი კომბინაცია, როდესაც
გჭირდებათ, რომ ყველა მოთხოვნა Devin-ის გავლით გაიგზავნოს.

## იზოლაცია და საფრთხეების მოდელი

ჰოსტის Claude-ის ინსტალაცია, ანგარიში და კონფიგურაცია განხილვის ფარგლებს სცდება და აკრძალულად მიიჩნევა. Compose-ის სერვისები:

- მუშაობს UID/GID `10001:10001`-ით, მხოლოდ წასაკითხი root ფაილური სისტემით, გაუქმებული შესაძლებლობებითა და
  `no-new-privileges`-ით;
- იყენებს კერძო `/home/bridge`-ს, Claude-ის კონფიგურაციის გამოყოფილ ტომს, იზოლირებულ OmniRoute-ის მონაცემებსა
  და ცალკე `devin-auth` ტომს;
- ამონტაჟებს მხოლოდ ერთჯერად `.sandbox` სამუშაო სივრცეებს/მტკიცებულებებს;
- არ ამონტაჟებს ჰოსტის home-ს, Keychain-ს, SSH-ს, ღრუბლოვანი სერვისების ავტორიზაციის მონაცემებს ან Docker-ის სოკეტს;
- ქმნის ცალსახად განსაზღვრულ გარემოებს და შლის Anthropic-ის API/OAuth/მარშრუტიზაციის ცვლადებს;
- Claude Code-ის ინფერენციას მიმართავს მხოლოდ `http://omniroute:20128`-ზე, მხოლოდ ლოკალურად მოქმედი გასაღებით.

ოფლაინ-პროფილი შიდა ქსელს იყენებს. აქტიურ პროფილში OmniRoute ოფიციალურ Devin-ის საბოლოო წერტილებს მხოლოდ `network-guard`-ის გავლით უკავშირდება; სხვა დანიშნულების მისამართები უარყოფილია.
Claude Code-ს აქვს ცალკე, ყველა გამავალი კავშირის ამკრძალავი დამცავი და `NO_PROXY`-ის მეშვეობით მხოლოდ ლოკალურ OmniRoute სერვისთან დაკავშირება შეუძლია. დამცავების აუდიტის ფაილები მხოლოდ შესაბამისი დამცავი პროცესების მიერ არის დამონტაჟებული. სკრიპტები ამოწმებს ფაილის მფლობელობას, რეჟიმს, ბმულების რაოდენობასა და თითოეულ გადაწყვეტილებას, სანამ ტოკენებისგან თავისუფალ მტკიცებულებას გაიტანს.

იზოლაციის დამადასტურებელი შემოწმება დამოუკიდებლად გაუშვით:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ის ამოწმებს ტოპოლოგიას, სახელდებულ მონტაჟებს, non-root/მხოლოდ წასაკითხ პარამეტრებს, ცალსახად განსაზღვრულ ლოკალურ მარშრუტიზაციას, სენსიტიური გარემოს ცვლადების არარსებობას, Docker-ის სოკეტის არარსებობას, `api.anthropic.com`-სა და `claude.ai`-ზე დაბლოკილ წვდომას, მხოლოდ Devin-ის პროვაიდერის არჩევას და ცალსახა შეცდომას, როდესაც ACP ბეკენდი მიუწვდომელია.

## პირველადი გამართვა და ჩვეულებრივი გამოყენება

ააგეთ დაფიქსირებულ ვერსიაზე მიბმული იმიჯი:

```bash
./scripts/devin-bridge/build
```

ავტორიზაცია გაიარეთ მხოლოდ იზოლირებულ Devin-ის ტომში:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

შესვლის ბრძანება იყენებს ოფიციალურ, ხელით შეყვანილი ტოკენის ნაკადს, რომელიც დისტანციური/კონტეინერული გარემოებისთვისაა განკუთვნილი. მნიშვნელობა პირდაპირ CLI-ის მოთხოვნაში შეიყვანება; ის არ გადაეცემა პროცესის არგუმენტად, არ იწერება Git-ში და არ კოპირდება ჰოსტიდან.

გაუშვით იზოლირებული Claude Code-ის გაშვების გარემო:

```bash
./scripts/devin-bridge/launch
```

`launch` კონტეინერიზებული Claude Code-ის დაწყებამდე ხელახლა ამოწმებს იზოლაციას, Devin-ის ავტორიზაციასა და მოდელების აღმოჩენას. ის არასოდეს უშვებს ჰოსტზე არსებულ Claude-ის შესრულებად ფაილს. მოდელების ფსევდონიმები შეიძლება განისაზღვროს `.env.devin-bridge`-ში; ყველა კონფიგურირებულმა მნიშვნელობამ უნდა შეინარჩუნოს
`devin-cli-agentic/` პრეფიქსი.

## ვალიდაციის ბრძანებები

კვლავწარმოებად ოფლაინ-გზას Devin-ის ანგარიში არ სჭირდება და შესრულებისას ინტერნეტს არ იყენებს:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ავტორიზებული, სურვილისამებრ ჩასართავი აქტიური გზა არის:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

აქტიური გამშვები სცენარებს შორის იცდის, რათა ACP სესიები ერთბაშად არ გახსნას, და ტექსტური მტკიცებების ნდობის ნაცვლად Claude-ის ნაკადის სტრუქტურირებულ მოვლენებს ამოწმებს. მისი სამი სცენარი ადასტურებს:

1. პროექტის პირდაპირ წაკითხვასა და დეფექტების ანალიზს;
2. რეალურ `Edit`-ს, კლიენტის მიერ მართულ `Bash` `npm test`-ს და ტერმინალურ შედეგს;
3. `/bridge-check`-ს `bridge-proof`-ის აღმოჩენასთან ერთად, პროექტის წაკითხვას, კლიენტის მიერ მართულ კიდევ ერთ წარმატებულ `npm test`-ს და დასრულებას მომლოდინე სამუშაოს გარეშე.

საბოლოო საკონტროლო ეტაპი ასევე ამოწმებს Devin-ის ქსელის აუდიტს და მოითხოვს, რომ Claude-ის გამავალი კავშირების აუდიტი ცარიელი დარჩეს.

## მიბმული ინსტრუმენტების განახლება

იმიჯში Node, Claude Code და Devin CLI მიბმულია
`docker/devin-bridge/Dockerfile`-ში. განახლებისთვის:

1. შეცვალეთ ცხადად მითითებული ვერსიები;
2. არქიტექტურისთვის სპეციფიკური Devin-ის არქივის ორივე საკონტროლო ჯამი ჩაანაცვლეთ ოფიციალური
   არტეფაქტის მნიშვნელობებით;
3. ხელახლა ააგეთ და გაუშვით ყველა ოფლაინ ვალიდაციის ბრძანება;
4. დაადასტურეთ ვერსიები იმიჯის შიგნით;
5. ხელახლა გაუშვით ავტორიზებული, სამი სცენარისგან შემდგარი რეალური ნაკრები.

არცერთი CLI არ დააყენოთ გლობალურად ჰოსტზე და საკონტროლო ჯამის შემოწმება არ ჩაანაცვლოთ
შეუმოწმებელი ჩამოტვირთვით.
