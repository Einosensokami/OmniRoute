`devin-cli-agentic` ನಿಜವಾದ Claude Code ರನ್ಟೈಮ್ಗೆ OmniRoute ನ ಸ್ಥಳೀಯ Anthropic
Messages ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಬಳಸಲು ಅನುವು ಮಾಡಿಕೊಡುತ್ತದೆ, ಇದೇ ವೇಳೆ ಅಧಿಕೃತ Devin CLI ಮಾದರಿ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ACP stdio ಮೂಲಕ ಒದಗಿಸುತ್ತದೆ. ಇದು
ಈಗಿರುವ Anthropic, Claude OAuth, Claude Web, ಅಥವಾ `devin-cli` ಪೂರೈಕೆದಾರಗಳನ್ನು ಮಾರ್ಪಡಿಸುವುದಿಲ್ಲ.

ಕ್ಲೈಂಟ್-ಸ್ವಾಮ್ಯದ ಟೂಲ್ ಕರೆಗಳಿಗಾಗಿ, Claude-ಫಾರ್ಮ್ಯಾಟ್ನ ಟೂಲ್-ಸಾಮರ್ಥ್ಯವುಳ್ಳ ಪೂರೈಕೆದಾರವಾದ
`devin-cli-agentic` (ಅಲಿಯಾಸ್ `dva`) ಮೂಲಕ ರೂಟ್ ಮಾಡಿ. ಹಳೆಯ `devin-cli` (`dv`) ACP ಎಕ್ಸಿಕ್ಯೂಟರ್
ಪಠ್ಯ-ಮಾತ್ರವಾಗಿದೆ: ಇದು Devin ನ ಟೂಲ್ಗಳಿಲ್ಲದ ಸಾರಾಂಶಕಾರವನ್ನು ಚಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಟೂಲ್ ಕರೆಗಳನ್ನು ಹಿಂತಿರುಗಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ಟೂಲ್ ಅಗತ್ಯವಿರುವ ಕಾಂಬೊ ರೂಟಿಂಗ್ ಇದನ್ನು ತಪ್ಪಿಸುವಂತೆ ಇದರ ಮಾದರಿ
ಮೆಟಾಡೇಟಾವನ್ನು ಗುರುತಿಸಲಾಗಿದೆ.

> **ಪ್ರಸ್ತುತ ಸ್ಥಿತಿ: Claude Code `2.1.258` ಗೆ ಪಿನ್ ಮಾಡಲಾಗಿದೆ; ಆಫ್ಲೈನ್ ಮತ್ತು ಲೈವ್ ಮೌಲ್ಯೀಕರಣವನ್ನು ಕೊನೆಯದಾಗಿ
> `2.1.220` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ.** `2.1.220` ಪಿನ್ Devin CLI

> `Edit`, ಮತ್ತು `Bash` ಟರ್ನ್ಗಳು, ಯಶಸ್ವಿ `npm test` ಫಲಿತಾಂಶಗಳು, ಪ್ರಾಜೆಕ್ಟ್ ಕಮಾಂಡ್ ಮತ್ತು ಸ್ಕಿಲ್
> ಪತ್ತೆ, Devin-ಮಾತ್ರ ರೂಟಿಂಗ್, ಮತ್ತು ಶೂನ್ಯ Claude ಎಗ್ರೆಸ್ ಅನ್ನು ಸಾಬೀತುಪಡಿಸಿತು. ನಂತರ ಪಿನ್ ಅನ್ನು `2.1.258` ಗೆ
> ಏರಿಸಲಾಯಿತು (OmniRoute ನ Claude ಗುರುತು ಅನುಕರಿಸುವ CLI ತಲೆಮಾರು ಮತ್ತು
> Fable 5.1 ಟಿಯರ್ ಅನ್ನು ಮೂಲತಃ ಒದಗಿಸುವ ಮೊದಲ ಲೈನ್). ಹೊಸ ಪಿನ್ನಲ್ಲಿ ಪಿನ್ ಮಾಡಿದ ಬೇಸ್ ಇಮೇಜ್ ಮೇಲೆ ಇನ್ಸ್ಟಾಲ್ ಲೇಯರ್ ಮತ್ತು `claude --version` ಅನ್ನು
> ಪರಿಶೀಲಿಸಲಾಗಿದೆ, ಮತ್ತು ಬ್ರಿಡ್ಜ್ ಯೂನಿಟ್ ಸೂಟ್, `compose config` ಹಾಗೂ
> ಸ್ಥಿರ ಐಸೊಲೇಶನ್ ಪುರಾವೆ ಪಾಸ್ ಆಗಿವೆ — ಆದರೆ ಆಫ್ಲೈನ್ ಮಾಕ್ ಸನ್ನಿವೇಶ ಮತ್ತು ಲೈವ್ ಮೂರು-ಸನ್ನಿವೇಶಗಳ

> ("ಪಿನ್ ಮಾಡಿದ ಟೂಲ್ಗಳನ್ನು ನವೀಕರಿಸುವುದು" ನೋಡಿ).

## ಆರ್ಕಿಟೆಕ್ಚರ್

```text
Claude Code 2.1.258 (ಪ್ರತ್ಯೇಕಿಸಲಾದ ರೂಟ್-ಅಲ್ಲದ Linux ಕಂಟೇನರ್)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ಫಾರ್ಮ್ಯಾಟ್, ದೃಢೀಕರಣವಿಲ್ಲದ ಪೂರೈಕೆದಾರ)
  -> devin acp --agent-type summarizer (ಅಧಿಕೃತ ACP stdio, Devin ಟೂಲ್ಗಳಿಲ್ಲ)
  -> ಮೀಸಲಾದ devin-auth ವಾಲ್ಯೂಮ್ನಲ್ಲಿರುವ Devin ಖಾತೆ
```

ಅಧಿಕೃತ CLI ಯ ಡೀಫಾಲ್ಟ್ ACP ಏಜೆಂಟ್ ತನ್ನದೇ ಟೂಲ್ಗಳನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸಬಲ್ಲದು, ಆದ್ದರಿಂದ ಈ ಬ್ರಿಡ್ಜ್ ಅದನ್ನು ಬಳಸುವುದಿಲ್ಲ.
ಇದು ಟೂಲ್ಗಳಿಲ್ಲದ ಅಧಿಕೃತ CLI ಮೋಡ್ ಹೊಂದಿರುವ ಸ್ಥಿರ `summarizer` ACP ಏಜೆಂಟ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ ಮತ್ತು
ಸೀರಿಯಲೈಸ್ ಮಾಡಿದ Anthropic ವಿನಂತಿಯನ್ನು ಎಕ್ಸಿಕ್ಯೂಷನ್ ಟ್ರೇಸ್ ಆಗಿ ಫ್ರೇಮ್ ಮಾಡುತ್ತದೆ. Claude-ಸ್ವಾಮ್ಯದ ಮತ್ತೊಂದು
ಕ್ರಿಯೆ ಅಗತ್ಯವಿದ್ದಾಗ, ಪ್ರತಿಕ್ರಿಯೆಯು ನಿಖರವಾಗಿ ಒಂದು ಕ್ಲೈಂಟ್ ಟೂಲ್ ಎನ್ವೆಲಪ್ ಅನ್ನು ಹೊಂದಿರಬೇಕು. ಯಾವುದೇ ACP
`tool_call` ಅಥವಾ `tool_call_update` ಅನ್ನು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಯಶಸ್ವಿಯೆಂದು ವರದಿ ಮಾಡುವ ಮೊದಲು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

`open-sse/executors/devin-agentic/serializer.ts` ನಲ್ಲಿರುವ ಸೀರಿಯಲೈಸರ್ `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, ಮತ್ತು
Claude Code ಒದಗಿಸಿದ ಟೂಲ್ಗಳನ್ನು ಉಳಿಸುತ್ತದೆ. ಇಮೇಜ್ಗಳು ಮತ್ತು ಅಜ್ಞಾತ ಬ್ಲಾಕ್ಗಳು ಸ್ಪಷ್ಟವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತವೆ. ದೊಡ್ಡ ಟೂಲ್ ಫಲಿತಾಂಶಗಳು
ಗೋಚರಿಸುವ ಕಡಿತ ಗುರುತನ್ನು ಬಳಸುತ್ತವೆ.

ಪಾರ್ಸರ್ ಪ್ರತಿ ಮಾದರಿ ಟರ್ನ್ಗೆ ಒಂದು ಸ್ವತಂತ್ರ `<tool>{...}</tool>` ಎನ್ವೆಲಪ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಇದು
ವಿನಂತಿಯ ಟೂಲ್ ಪಟ್ಟಿಯ ವಿರುದ್ಧ ಹೆಸರನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಆ ಟೂಲ್ನ JSON
Schema ವಿರುದ್ಧ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ, ಮಿಶ್ರ ನಿರೂಪಣೆ/ಕ್ರಿಯೆಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ ಮತ್ತು ಒಂದು ಮಿತಿಗೊಳಿಸಿದ ದುರಸ್ತಿಗೆ ಅನುಮತಿಸುತ್ತದೆ. ನಂತರ Claude Code
ಪರಿಣಾಮವಾಗಿ ದೊರೆಯುವ Anthropic `tool_use` ಅನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಕಾರ್ಯಗತಗೊಳಿಸಿ, `tool_result` ಅನ್ನು OmniRoute ಮೂಲಕ
ಮತ್ತೆ ಕಳುಹಿಸುತ್ತದೆ.

## ಸ್ವಯಂ-ರೂಟಿಂಗ್

ಪೂರೈಕೆದಾರನನ್ನು ನಿರ್ಬಂಧಿಸದಿದ್ದಾಗ, ಅದು OmniRoute ನ `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ಗಳಲ್ಲಿ ಅರ್ಹವಾಗಿರುತ್ತದೆ.
ಅಭ್ಯರ್ಥಿ ಅರ್ಹತೆಯು ಆಯ್ಕೆಯನ್ನು ಖಾತರಿಪಡಿಸುವುದಿಲ್ಲ: ಕಾಂಬೊದ ರೂಟಿಂಗ್ ಕಾರ್ಯತಂತ್ರವು (ಉದಾಹರಣೆಗೆ,
ಕೊನೆಯದಾಗಿ-ತಿಳಿದ-ಉತ್ತಮ) ಮತ್ತೊಂದು ಪೂರೈಕೆದಾರನಿಗೆ ಆದ್ಯತೆ ನೀಡಬಹುದು. ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯೂ Devin ಮೂಲಕವೇ ಹೋಗಬೇಕೆಂದಿದ್ದರೆ
`dva/<model>` ಅಥವಾ Devin-ಪ್ರಥಮ ಕಾಂಬೊವನ್ನು ಬಳಸಿ.

## ಪ್ರತ್ಯೇಕೀಕರಣ ಮತ್ತು ಬೆದರಿಕೆ ಮಾದರಿ

ಹೋಸ್ಟ್ನ Claude ಸ್ಥಾಪನೆ, ಖಾತೆ ಮತ್ತು ಸಂರಚನೆ ವ್ಯಾಪ್ತಿಯಿಂದ ಹೊರಗಿದ್ದು, ಅವುಗಳನ್ನು
ನಿಷೇಧಿತವೆಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ. Compose ಸೇವೆಗಳು:

- UID/GID `10001:10001` ಆಗಿ, ಓದಲು-ಮಾತ್ರವಾದ ರೂಟ್ ಫೈಲ್ಸಿಸ್ಟಮ್, ತೆಗೆದುಹಾಕಲಾದ ಸಾಮರ್ಥ್ಯಗಳು ಮತ್ತು
  `no-new-privileges` ಜೊತೆಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ;
- ಖಾಸಗಿ `/home/bridge`, ಮೀಸಲಾದ Claude ಸಂರಚನಾ ವಾಲ್ಯೂಮ್, ಪ್ರತ್ಯೇಕಿಸಲಾದ OmniRoute ಡೇಟಾ
  ಮತ್ತು ಪ್ರತ್ಯೇಕ `devin-auth` ವಾಲ್ಯೂಮ್ ಅನ್ನು ಬಳಸುತ್ತವೆ;
- ತಾತ್ಕಾಲಿಕ `.sandbox` ಕಾರ್ಯಕ್ಷೇತ್ರಗಳು/ಪುರಾವೆಗಳನ್ನು ಮಾತ್ರ ಮೌಂಟ್ ಮಾಡುತ್ತವೆ;
- ಹೋಸ್ಟ್ ಹೋಮ್, Keychain, SSH, ಕ್ಲೌಡ್ ರುಜುವಾತುಗಳು ಅಥವಾ Docker ಸಾಕೆಟ್ ಅನ್ನು ಮೌಂಟ್ ಮಾಡುವುದಿಲ್ಲ;
- ಸ್ಪಷ್ಟವಾದ ಪರಿಸರಗಳನ್ನು ನಿರ್ಮಿಸಿ Anthropic API/OAuth/ರೂಟಿಂಗ್ ವೇರಿಯೇಬಲ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತವೆ;
- ಸ್ಥಳೀಯವಾಗಿ ಮಾತ್ರ ಬಳಸುವ ಕೀಲಿಯೊಂದಿಗೆ Claude Code ನಿರ್ಣಯವನ್ನು `http://omniroute:20128` ಗೆ ಮಾತ್ರ ನಿರ್ದೇಶಿಸುತ್ತವೆ.

ಆಫ್ಲೈನ್ ಪ್ರೊಫೈಲ್ ಆಂತರಿಕ ನೆಟ್ವರ್ಕ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಲೈವ್ ಪ್ರೊಫೈಲ್ನಲ್ಲಿ, OmniRoute ಅಧಿಕೃತ
Devin ಎಂಡ್ಪಾಯಿಂಟ್ಗಳನ್ನು `network-guard` ಮೂಲಕ ಮಾತ್ರ ತಲುಪುತ್ತದೆ; ಸಂಬಂಧವಿಲ್ಲದ ಗಮ್ಯಸ್ಥಾನಗಳನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.
Claude Code ಪ್ರತ್ಯೇಕವಾದ ಎಲ್ಲ ಹೊರಹರಿವು-ನಿರಾಕರಿಸುವ ಗಾರ್ಡ್ ಅನ್ನು ಹೊಂದಿದ್ದು, `NO_PROXY` ಮೂಲಕ ಸ್ಥಳೀಯ OmniRoute
ಸೇವೆಯನ್ನು ಮಾತ್ರ ತಲುಪಬಲ್ಲದು. ಗಾರ್ಡ್ ಆಡಿಟ್ ಫೈಲ್ಗಳನ್ನು ಅವುಗಳ ಗಾರ್ಡ್ ಪ್ರಕ್ರಿಯೆ ಮಾತ್ರ ಮೌಂಟ್ ಮಾಡುತ್ತದೆ.
ಸ್ಕ್ರಿಪ್ಟ್ಗಳು ಟೋಕನ್-ರಹಿತ ಪುರಾವೆಯನ್ನು ರಫ್ತು ಮಾಡುವ ಮೊದಲು ಫೈಲ್ ಮಾಲೀಕತ್ವ, ಮೋಡ್, ಲಿಂಕ್ ಎಣಿಕೆ ಮತ್ತು
ಪ್ರತಿಯೊಂದು ನಿರ್ಧಾರವನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ.

ಪ್ರತ್ಯೇಕೀಕರಣದ ಪುರಾವೆಯನ್ನು ಸ್ವತಂತ್ರವಾಗಿ ಚಲಾಯಿಸಿ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ಇದು ಟೊಪಾಲಜಿ, ಹೆಸರಿಸಲಾದ ಮೌಂಟ್ಗಳು, ರೂಟ್ ಅಲ್ಲದ/ಓದಲು-ಮಾತ್ರ ಸೆಟ್ಟಿಂಗ್ಗಳು, ಸ್ಪಷ್ಟ ಸ್ಥಳೀಯ ರೂಟಿಂಗ್,
ಸೂಕ್ಷ್ಮ ಪರಿಸರ ವೇರಿಯೇಬಲ್ಗಳ ಅನುಪಸ್ಥಿತಿ, Docker ಸಾಕೆಟ್ನ ಅನುಪಸ್ಥಿತಿ, `api.anthropic.com` ಮತ್ತು
`claude.ai` ಗೆ ನಿರ್ಬಂಧಿತ ಪ್ರವೇಶ, Devin-ಮಾತ್ರ ಪ್ರೊವೈಡರ್ ಆಯ್ಕೆ ಮತ್ತು ACP ಬ್ಯಾಕ್ಎಂಡ್ ಲಭ್ಯವಿಲ್ಲದಿದ್ದಾಗ
ಸ್ಪಷ್ಟ ವೈಫಲ್ಯವನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

## ಮೊದಲ ಬಾರಿಯ ಸೆಟಪ್ ಮತ್ತು ಸಾಮಾನ್ಯ ಬಳಕೆ

ಪಿನ್ ಮಾಡಲಾದ ಇಮೇಜ್ ಅನ್ನು ಬಿಲ್ಡ್ ಮಾಡಿ:

```bash
./scripts/devin-bridge/build
```

ಪ್ರತ್ಯೇಕಿಸಲಾದ Devin ವಾಲ್ಯೂಮ್ ಅನ್ನು ಮಾತ್ರ ದೃಢೀಕರಿಸಿ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

ಲಾಗಿನ್ ಕಮಾಂಡ್ ದೂರಸ್ಥ/ಕಂಟೇನರ್ ಪರಿಸರಗಳಿಗಾಗಿ ಉದ್ದೇಶಿಸಲಾದ ಅಧಿಕೃತ ಮ್ಯಾನುಯಲ್-ಟೋಕನ್ ಹರಿವನ್ನು ಬಳಸುತ್ತದೆ.
ಮೌಲ್ಯವನ್ನು ನೇರವಾಗಿ CLI ಪ್ರಾಂಪ್ಟ್ನಲ್ಲಿ ನಮೂದಿಸಲಾಗುತ್ತದೆ; ಅದನ್ನು ಪ್ರಕ್ರಿಯೆಯ ಆರ್ಗ್ಯುಮೆಂಟ್ ಆಗಿ ರವಾನಿಸುವುದಿಲ್ಲ,
Git ಗೆ ಬರೆಯುವುದಿಲ್ಲ ಅಥವಾ ಹೋಸ್ಟ್ನಿಂದ ನಕಲಿಸುವುದಿಲ್ಲ.

ಪ್ರತ್ಯೇಕಿಸಲಾದ Claude Code ರನ್ಟೈಮ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ:

```bash
./scripts/devin-bridge/launch
```

ಕಂಟೇನರೀಕರಿಸಿದ Claude Code ಅನ್ನು ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು `launch` ಪ್ರತ್ಯೇಕೀಕರಣ, Devin ದೃಢೀಕರಣ ಮತ್ತು
ಮಾದರಿ ಅನ್ವೇಷಣೆಯನ್ನು ಮರುಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದು ಹೋಸ್ಟ್ನ Claude ಎಕ್ಸಿಕ್ಯೂಟಬಲ್ ಅನ್ನು ಎಂದಿಗೂ ಚಲಾಯಿಸುವುದಿಲ್ಲ.
ಮಾದರಿ ಅಲಿಯಾಸ್ಗಳನ್ನು `.env.devin-bridge` ನಲ್ಲಿ ಹೊಂದಿಸಬಹುದು; ಸಂರಚಿಸಲಾದ ಪ್ರತಿಯೊಂದು ಮೌಲ್ಯವೂ
`devin-cli-agentic/` ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಉಳಿಸಿಕೊಳ್ಳಬೇಕು.

## ಮೌಲ್ಯೀಕರಣ ಕಮಾಂಡ್ಗಳು

ಪುನರುತ್ಪಾದಿಸಬಹುದಾದ ಆಫ್ಲೈನ್ ಮಾರ್ಗಕ್ಕೆ Devin ಖಾತೆ ಅಗತ್ಯವಿಲ್ಲ ಮತ್ತು ರನ್ಟೈಮ್ ಇಂಟರ್ನೆಟ್ ಇರುವುದಿಲ್ಲ:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ದೃಢೀಕರಿಸಲಾದ, ಆಯ್ಕೆಯ ಮೇರೆಗೆ ಬಳಸುವ ಲೈವ್ ಮಾರ್ಗ ಹೀಗಿದೆ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP ಸೆಷನ್ಗಳನ್ನು ಏಕಾಏಕಿ ತೆರೆಯುವುದನ್ನು ತಪ್ಪಿಸಲು ಲೈವ್ ರನ್ನರ್ ಸನ್ನಿವೇಶಗಳ ನಡುವೆ ಕಾಯುತ್ತದೆ ಮತ್ತು ಪಠ್ಯರೂಪದ
ಹೇಳಿಕೆಗಳನ್ನು ನಂಬುವ ಬದಲು ರಚನಾತ್ಮಕ Claude ಸ್ಟ್ರೀಮ್ ಈವೆಂಟ್ಗಳನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ. ಅದರ ಮೂರು
ಸನ್ನಿವೇಶಗಳು ಇವುಗಳನ್ನು ಸಾಬೀತುಪಡಿಸುತ್ತವೆ:

1. ನೇರ ಪ್ರಾಜೆಕ್ಟ್ ಓದುವಿಕೆಗಳು ಮತ್ತು ದೋಷ ವಿಶ್ಲೇಷಣೆ;
2. ನೈಜ `Edit`, ಕ್ಲೈಂಟ್-ಮಾಲೀಕತ್ವದ `Bash` `npm test` ಮತ್ತು ಟರ್ಮಿನಲ್ ಫಲಿತಾಂಶ;
3. `/bridge-check` ಜೊತೆಗೆ `bridge-proof` ಅನ್ವೇಷಣೆ, ಪ್ರಾಜೆಕ್ಟ್ ಓದುವಿಕೆಗಳು, ಮತ್ತೊಂದು ಯಶಸ್ವಿ
   ಕ್ಲೈಂಟ್-ಮಾಲೀಕತ್ವದ `npm test` ಮತ್ತು ಬಾಕಿ ಕೆಲಸವಿಲ್ಲದೆ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ.

ಅಂತಿಮ ಗೇಟ್ Devin ನೆಟ್ವರ್ಕ್ ಆಡಿಟ್ ಅನ್ನೂ ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು Claude ಹೊರಹರಿವು ಆಡಿಟ್
ಖಾಲಿಯಾಗಿಯೇ ಉಳಿಯಬೇಕೆಂದು ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ.

## ಪಿನ್ ಮಾಡಲಾದ ಪರಿಕರಗಳನ್ನು ನವೀಕರಿಸುವುದು

ಇಮೇಜ್ನಲ್ಲಿ Node, Claude Code ಮತ್ತು Devin CLI ಅನ್ನು
`docker/devin-bridge/Dockerfile` ನಲ್ಲಿ ಪಿನ್ ಮಾಡಲಾಗಿದೆ. ನವೀಕರಿಸಲು:

1. ಸ್ಪಷ್ಟವಾಗಿ ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಆವೃತ್ತಿಗಳನ್ನು ಬದಲಾಯಿಸಿ;
2. ಆರ್ಕಿಟೆಕ್ಚರ್-ನಿರ್ದಿಷ್ಟವಾದ ಎರಡೂ Devin ಆರ್ಕೈವ್ ಚೆಕ್ಸಮ್ಗಳನ್ನು ಅಧಿಕೃತ
   ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ನ ಮೌಲ್ಯಗಳಿಂದ ಬದಲಾಯಿಸಿ;
3. ಮರುನಿರ್ಮಿಸಿ ಮತ್ತು ಪ್ರತಿಯೊಂದು ಆಫ್ಲೈನ್ ಮೌಲ್ಯಮಾಪನ ಕಮಾಂಡ್ ಅನ್ನು ಚಲಾಯಿಸಿ;
4. ಇಮೇಜ್ನೊಳಗಿನ ಆವೃತ್ತಿಗಳನ್ನು ದೃಢೀಕರಿಸಿ;
5. ದೃಢೀಕರಣಗೊಂಡ ಮೂರು-ಸನ್ನಿವೇಶಗಳ ಲೈವ್ ಸೂಟ್ ಅನ್ನು ಮರುಚಲಾಯಿಸಿ.

ಹೋಸ್ಟ್ನಲ್ಲಿ ಯಾವುದೇ CLI ಅನ್ನು ಜಾಗತಿಕವಾಗಿ ಸ್ಥಾಪಿಸಬೇಡಿ ಅಥವಾ ಚೆಕ್ಸಮ್ ಪರಿಶೀಲನೆಯನ್ನು
ಪರಿಶೀಲಿಸದ ಡೌನ್ಲೋಡ್ನಿಂದ ಬದಲಾಯಿಸಬೇಡಿ.
