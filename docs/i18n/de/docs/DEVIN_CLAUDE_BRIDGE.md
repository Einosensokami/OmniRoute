`devin-cli-agentic` ermöglicht es der echten Claude-Code-Laufzeit, OmniRoutes lokalen Anthropic-
Messages-Endpunkt zu verwenden, während die offizielle Devin CLI Modellantworten über ACP stdio bereitstellt. Es
ändert die bestehenden Anbieter Anthropic, Claude OAuth, Claude Web oder `devin-cli` nicht.

Leiten Sie vom Client verwaltete Tool-Aufrufe über `devin-cli-agentic` (Alias `dva`), den
Tool-fähigen Anbieter im Claude-Format. Der bisherige `devin-cli` (`dv`) ACP-Executor unterstützt
nur Text: Er führt Devins No-Tools-Summarizer aus und kann keine Tool-Aufrufe zurückgeben. Seine
Modellmetadaten sind entsprechend gekennzeichnet, sodass Combo-Routing, das Tools voraussetzt, ihn meidet.

> für `2.1.220` protokolliert.** Mit der angehefteten Version `2.1.220` wurden drei isolierte Szenarien über Devin CLI
> `3000.2.17` und das Modell `swe-1-7-lightning` abgeschlossen; dieser abschließende Live-Durchlauf bestätigte vom Client verwaltete `Read`-,
> `Edit`- und `Bash`-Interaktionen, erfolgreiche Ergebnisse von `npm test`, die Erkennung von Projektbefehlen und Skills,
> ausschließliches Routing über Devin und keinerlei ausgehenden Claude-Datenverkehr. Anschließend wurde die angeheftete Version auf `2.1.258`
> angehoben (die CLI-Generation, die OmniRoutes Claude-Identität imitiert, und die erste Versionslinie, die
> die Fable-5.1-Stufe nativ enthält). Mit der neuen angehefteten Version wurden die Installationsschicht und `claude --version`
> auf dem angehefteten Basis-Image überprüft, und die Bridge-Unit-Test-Suite, `compose config` sowie der
> statische Isolationsnachweis sind erfolgreich — das Offline-Mock-Szenario und die Live-Suite mit drei Szenarien
> wurden jedoch noch nicht erneut ausgeführt. Führen Sie sie erneut aus (siehe „Aktualisieren angehefteter Tools“), bevor Sie sich
> bei dieser angehefteten Version auf die Bridge verlassen.

## Architektur

```text
Claude Code 2.1.258 (isolierter Nicht-Root-Linux-Container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-Format, Anbieter ohne Authentifizierung)
  -> devin acp --agent-type summarizer (offizielles ACP stdio, keine Devin-Tools)
  -> Devin-Konto im dedizierten devin-auth-Volume
```

Der standardmäßige ACP-Agent der offiziellen CLI kann seine eigenen Tools ausführen, daher verwendet diese Bridge
ihn nicht. Sie startet den festen ACP-Agenten `summarizer`, dessen offizieller CLI-Modus keine Tools besitzt, und
rahmt die serialisierte Anthropic-Anfrage als Ausführungsspur ein. Wenn eine weitere von Claude verwaltete
Aktion erforderlich ist, muss die Antwort genau einen Client-Tool-Umschlag enthalten. Jedes ACP-
`tool_call` oder `tool_call_update` wird abgelehnt, bevor eine Antwort als
erfolgreich gemeldet werden kann.

Der Serializer in `open-sse/executors/devin-agentic/serializer.ts` bewahrt `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` und die
von Claude Code bereitgestellten Tools. Bilder und unbekannte Blöcke führen explizit zu einem Fehler. Große Tool-Ergebnisse
verwenden eine sichtbare Kürzungsmarkierung.

Der Parser akzeptiert pro Modellinteraktion einen eigenständigen `<tool>{...}</tool>`-Umschlag. Er gleicht
den Namen mit der Tool-Liste der Anfrage ab, validiert Argumente anhand des JSON-Schemas
dieses Tools, lehnt Mischungen aus Erläuterungen und Aktionen ab und gestattet einen begrenzten Korrekturversuch. Claude Code führt
anschließend den resultierenden Anthropic-`tool_use` lokal aus und sendet das `tool_result` über
OmniRoute zurück.

## Automatisches Routing

Der Anbieter kann in OmniRoutes `auto/*`-Kandidatenpools aufgenommen werden, sofern er nicht blockiert ist.
Die Eignung als Kandidat garantiert keine Auswahl: Die Routing-Strategie der Combo (beispielsweise
„last-known-good“) kann einen anderen Anbieter bevorzugen. Verwenden Sie `dva/<model>` oder eine Devin-priorisierende Combo, wenn
jede Anfrage zwingend über Devin geleitet werden soll.

## Isolations- und Bedrohungsmodell

Die Claude-Installation, das Konto und die Konfiguration des Hosts liegen außerhalb des Geltungsbereichs und werden als unzulässig behandelt. Die Compose-Dienste:

- werden mit UID/GID `10001:10001`, einem schreibgeschützten Root-Dateisystem, verworfenen Berechtigungen und `no-new-privileges` ausgeführt;
- verwenden ein privates `/home/bridge`, ein dediziertes Claude-Konfigurations-Volume, isolierte OmniRoute-Daten und ein separates `devin-auth`-Volume;
- binden ausschließlich flüchtige `.sandbox`-Arbeitsbereiche/-Nachweise ein;
- binden weder das Home-Verzeichnis des Hosts noch Keychain, SSH- oder Cloud-Anmeldedaten oder den Docker-Socket ein;
- erstellen explizite Umgebungen und entfernen Anthropic-API-/OAuth-/Routing-Variablen;
- leiten Claude-Code-Inferenz ausschließlich mit einem nur lokal gültigen Schlüssel an `http://omniroute:20128` weiter.

Das Offline-Profil verwendet ein internes Netzwerk. Im Live-Profil erreicht OmniRoute die offiziellen Devin-Endpunkte ausschließlich über `network-guard`; andere Ziele werden abgewiesen. Claude Code verfügt über eine separate Egress-Sperre, die sämtlichen ausgehenden Datenverkehr verweigert, und kann über `NO_PROXY` ausschließlich den lokalen OmniRoute-Dienst erreichen. Guard-Auditdateien werden ausschließlich in den jeweiligen Guard-Prozess eingebunden. Die Skripte überprüfen Dateieigentümer, Modus, Link-Anzahl und jede Entscheidung, bevor sie tokenfreie Nachweise exportieren.

Führen Sie den Isolationsnachweis unabhängig aus:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Er validiert die Topologie, benannte Einbindungen, Nicht-Root-/Schreibschutz-Einstellungen, explizites lokales Routing, das Fehlen sensibler Umgebungsvariablen und des Docker-Sockets, den blockierten Zugriff auf `api.anthropic.com` und `claude.ai`, die ausschließliche Auswahl von Devin als Anbieter sowie einen expliziten Fehler, wenn das ACP-Backend nicht verfügbar ist.

## Ersteinrichtung und normale Verwendung

Erstellen Sie das auf feste Versionen gesetzte Image:

```bash
./scripts/devin-bridge/build
```

Authentifizieren Sie ausschließlich das isolierte Devin-Volume:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Der Anmeldebefehl verwendet den offiziellen manuellen Token-Ablauf für Remote-/Container-Umgebungen. Der Wert wird direkt in die CLI-Eingabeaufforderung eingegeben; er wird weder als Prozessargument übergeben, in Git geschrieben noch vom Host kopiert.

Starten Sie die isolierte Claude-Code-Laufzeit:

```bash
./scripts/devin-bridge/launch
```

`launch` überprüft Isolation, Devin-Authentifizierung und Modellerkennung erneut, bevor das containerisierte Claude Code gestartet wird. Die ausführbare Claude-Datei des Hosts wird niemals ausgeführt. Modellaliase können in `.env.devin-bridge` festgelegt werden; jeder konfigurierte Wert muss das Präfix `devin-cli-agentic/` beibehalten.

## Validierungsbefehle

Der reproduzierbare Offline-Pfad benötigt kein Devin-Konto und hat zur Laufzeit keinen Internetzugriff:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Der authentifizierte, explizit zu aktivierende Live-Pfad lautet:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Der Live-Runner wartet zwischen den Szenarien, um ACP-Sitzungen nicht stoßweise zu öffnen, und validiert strukturierte Claude-Stream-Ereignisse, anstatt textuellen Behauptungen zu vertrauen. Seine drei Szenarien belegen:

1. direkte Projektzugriffe und Fehleranalyse;
2. eine echte `Edit`-Operation, einen clientseitig ausgeführten `Bash`-Befehl `npm test` und ein abschließendes Ergebnis;
3. `/bridge-check` zusammen mit der Erkennung von `bridge-proof`, Projektzugriffe, einen weiteren erfolgreichen clientseitig ausgeführten `npm test`-Befehl und den Abschluss ohne ausstehende Arbeiten.

Die abschließende Prüfung kontrolliert außerdem das Devin-Netzwerk-Audit und verlangt, dass das Claude-Egress-Audit leer bleibt.

## Aktualisieren angehefteter Tools

Das Image legt Node, Claude Code und Devin CLI in
`docker/devin-bridge/Dockerfile` auf feste Versionen fest. So aktualisieren Sie diese:

1. Ändern Sie die expliziten Versionen;
2. ersetzen Sie beide architekturspezifischen Prüfsummen des Devin-Archivs durch die Werte für das offizielle
   Artefakt;
3. erstellen Sie das Image neu und führen Sie jeden Offline-Validierungsbefehl aus;
4. überprüfen Sie die Versionen innerhalb des Images;
5. führen Sie die authentifizierte Live-Suite mit drei Szenarien erneut aus.

Installieren Sie keines der beiden CLIs global auf dem Host und ersetzen Sie die Prüfsummenverifizierung nicht durch einen
nicht verifizierten Download.

## Diagnose und Bereinigung

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  zeigt lokales Routing und bereinigte Executor-Fehler.
- `.sandbox/evidence/mock-acp.jsonl` zeichnet deterministische Mock-ACP-Aktionen auf.
- `.sandbox/evidence/claude-stream.jsonl` zeichnet den echten Offline-Lauf von Claude Code auf.
- `.sandbox/evidence/live-*.jsonl` zeichnet die drei validierten Live-Streams auf.
- `.sandbox/evidence/egress.jsonl` und `.sandbox/evidence/claude-egress.jsonl` sind validierte,
  tokenfreie Kopien der Guard-Audits.

Beenden Sie die zugehörigen Container und Netzwerke, während die Login-/Konfigurations-Volumes erhalten bleiben:

```bash
./scripts/devin-bridge/clean
```

Entfernen Sie die vollständige zur Bridge gehörende Umgebung einschließlich benannter Volumes:

```bash
./scripts/devin-bridge/clean --all
```

## Einschränkungen

- Die Bridge ist auf die feste werkzeuglose Rolle `summarizer` angewiesen, da Devin CLI `3000.2.17`
  keinen neutralen werkzeuglosen ACP-Agenten bereitstellt. Der Adapter kompensiert zusammenfassungsartige
  Zwischenantworten, aber eine einzelne begrenzte Korrektur kann weiterhin explizit fehlschlagen.
- Live-ACP-Aufrufe können vorübergehend `502`-/`504`-Antworten zurückgeben. Das Testsystem verteilt die Szenarien zeitlich;
  ein anhaltender Fehler bleibt Fail-Closed und wählt niemals einen anderen Anbieter aus.
- Der ACP-Kontext wird aus jeder Anthropic-Anfrage rekonstruiert; es gibt keine Prozess-/Sitzungsaffinität.
- Pro Modellantwort wird ein Tool-Aufruf unterstützt; parallele Aufrufe werden abgelehnt.
- Bilder werden ausdrücklich nicht unterstützt. Bildverarbeitung, Thinking-Ausgaben, Aufwandssteuerungen und ein
  Kontextfenster von 1M werden nicht angeboten.
- SSE verwendet gültige Anthropic-Lebenszyklusereignisse, wird jedoch erst ausgegeben, nachdem der begrenzte ACP-Turn
  vollständig erfasst wurde; ACP-Chunks werden nicht inkrementell weitergeleitet.
