يتيح `devin-cli-agentic` لبيئة تشغيل Claude Code الفعلية استخدام نقطة نهاية Anthropic
Messages المحلية الخاصة بـ OmniRoute، بينما توفّر واجهة Devin CLI الرسمية استجابات النموذج عبر ACP stdio. وهو
لا يعدّل موفّري Anthropic أو Claude OAuth أو Claude Web أو `devin-cli` الحاليين.

بالنسبة إلى استدعاءات الأدوات التي يديرها العميل، وجّه الطلبات عبر `devin-cli-agentic` (الاسم المستعار `dva`)، وهو
الموفّر القادر على استخدام الأدوات بتنسيق Claude. أما منفّذ ACP القديم `devin-cli` (`dv`) فهو
نصي فقط: إذ يشغّل ملخّص Devin من دون أدوات ولا يمكنه إرجاع استدعاءات أدوات. وقد وُسِمت
بيانات النموذج الوصفية وفقًا لذلك، بحيث يتجنبه توجيه التركيبات التي تتطلب أدوات.

> **الحالة الحالية: تم تثبيت Claude Code على `2.1.258`؛ وآخر تحقق مسجّل في وضعي عدم الاتصال
> والاتصال المباشر كان على `2.1.220`.** أكمل التثبيت على `2.1.220` ثلاثة سيناريوهات معزولة عبر Devin CLI
> `3000.2.17` والنموذج `swe-1-7-lightning`؛ وقد أثبت ذلك التشغيل المباشر النهائي نجاح دورات `Read`
> و`Edit` و`Bash` التي يديرها العميل، ونجاح نتائج `npm test`، واكتشاف أوامر المشروع ومهاراته،
> والتوجيه الحصري عبر Devin، وعدم حدوث أي خروج للبيانات إلى Claude. ثم رُفع الإصدار المثبّت إلى `2.1.258`
> (وهو إصدار CLI الذي تنتحل هوية Claude الخاصة بـ OmniRoute صفته، وأول إصدار يوفّر
> فئة Fable 5.1 بشكل أصلي). وعلى الإصدار المثبّت الجديد، تم التحقق من طبقة التثبيت و`claude --version`
> على صورة الأساس المثبّتة، كما نجحت حزمة اختبارات الوحدة للجسر و`compose config`
> وإثبات العزل الساكن — لكن سيناريو المحاكاة دون اتصال وحزمة السيناريوهات الثلاثة المباشرة
> لم يُعاد تشغيلهما بعد. أعد تشغيلهما (راجع "تحديث الأدوات المثبّتة") قبل الاعتماد على
> الجسر بهذا الإصدار المثبّت.

## البنية

```text
Claude Code 2.1.258 (حاوية Linux معزولة لمستخدم غير جذري)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (بتنسيق Claude، موفّر بلا مصادقة)
  -> devin acp --agent-type summarizer (واجهة ACP stdio الرسمية، بلا أدوات Devin)
  -> حساب Devin في وحدة التخزين المخصصة devin-auth
```

يمكن لوكيل ACP الافتراضي لواجهة CLI الرسمية تنفيذ أدواته الخاصة، لذلك لا يستخدمه هذا الجسر.
بل يشغّل وكيل ACP الثابت `summarizer`، الذي لا يحتوي وضع CLI الرسمي الخاص به على أدوات، ويؤطّر
طلب Anthropic المتسلسل باعتباره تتبع تنفيذ. وعند الحاجة إلى إجراء آخر يديره Claude،
يجب أن تحتوي الاستجابة على مغلف أداة عميل واحد فقط. ويُرفض أي
`tool_call` أو `tool_call_update` صادر عن ACP قبل إمكان الإبلاغ عن نجاح
الاستجابة.

يحافظ المسلسِل في `open-sse/executors/devin-agentic/serializer.ts` على `system`
و`text` و`tool_use` و`tool_result` و`thinking` و`redacted_thinking` و`tool_choice`، وعلى
الأدوات التي يوفّرها Claude Code. وتفشل الصور والكتل غير المعروفة صراحةً. وتستخدم نتائج الأدوات
الكبيرة علامة اقتطاع مرئية.

يقبل المحلّل مغلف `<tool>{...}</tool>` مستقلًا واحدًا لكل دورة نموذج. ويتحقق
من الاسم بمقارنته بقائمة أدوات الطلب، ويتحقق من صحة الوسائط وفق مخطط JSON
الخاص بتلك الأداة، ويرفض خلط السرد بالإجراءات، ويسمح بمحاولة إصلاح محدودة واحدة. ثم
ينفّذ Claude Code ناتج Anthropic `tool_use` محليًا ويرسل `tool_result` مجددًا عبر
OmniRoute.

## التوجيه التلقائي

يكون الموفّر مؤهلًا للإدراج في مجموعات المرشحين `auto/*` الخاصة بـ OmniRoute عندما لا يكون محظورًا.
ولا تضمن أهلية المرشح اختياره: فقد تفضّل استراتيجية توجيه التركيبة (على سبيل المثال،
آخر خيار معروف بأنه سليم) موفّرًا آخر. استخدم `dva/<model>` أو تركيبة تمنح Devin الأولوية عندما
تحتاج إلى تمرير كل طلب عبر Devin.

## العزل ونموذج التهديدات

يُعد تثبيت Claude على المضيف وحسابه وإعداداته خارج النطاق، ويُعامل على أنه
محظور. خدمات Compose:

- تعمل بالمعرّفَين UID/GID‏ `10001:10001`، مع نظام ملفات جذري للقراءة فقط، وإسقاط الصلاحيات،
  و`no-new-privileges`؛
- تستخدم `/home/bridge` خاصًا، ووحدة تخزين مخصصة لإعدادات Claude، وبيانات OmniRoute معزولة،
  ووحدة تخزين `devin-auth` منفصلة؛
- تركّب فقط مساحات عمل/أدلة `.sandbox` القابلة للتخلص منها؛
- لا تركّب المجلد الرئيسي للمضيف، أو Keychain، أو بيانات اعتماد SSH أو الخدمات السحابية، أو مقبس Docker؛
- تنشئ بيئات صريحة وتزيل متغيرات API/OAuth/التوجيه الخاصة بـ Anthropic؛
- توجّه استدلال Claude Code فقط إلى `http://omniroute:20128` باستخدام مفتاح محلي فقط.

يستخدم ملف التعريف غير المتصل شبكة داخلية. وفي ملف التعريف المباشر، يصل OmniRoute إلى
نقاط نهاية Devin الرسمية فقط عبر `network-guard`؛ وتُرفض الوجهات غير ذات الصلة.
لدى Claude Code حارس خروج منفصل يرفض الكل، ولا يمكنه الوصول إلا إلى خدمة OmniRoute
المحلية عبر `NO_PROXY`. لا تُركّب ملفات تدقيق الحارس إلا بواسطة عملية الحارس الخاصة بها.
تتحقق البرامج النصية من ملكية الملف ووضعه وعدد روابطه وكل قرار قبل تصدير
أدلة خالية من الرموز المميزة.

شغّل إثبات العزل بشكل مستقل:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

يتحقق هذا من البنية، ووحدات التركيب المسماة، وإعدادات المستخدم غير الجذر/القراءة فقط، والتوجيه المحلي
الصريح، وغياب متغيرات البيئة الحساسة، وغياب مقبس Docker، وحظر الوصول إلى
`api.anthropic.com` و`claude.ai`، واختيار موفر Devin فقط، والفشل الصريح عندما
لا تكون الواجهة الخلفية لـ ACP متاحة.

## الإعداد لأول مرة والاستخدام العادي

أنشئ الصورة المثبتة الإصدار:

```bash
./scripts/devin-bridge/build
```

صادِق فقط على وحدة تخزين Devin المعزولة:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

يستخدم أمر تسجيل الدخول تدفق الرمز المميز اليدوي الرسمي المخصص لبيئات الحاويات/البيئات
البعيدة. تُدخل القيمة مباشرة في مطالبة CLI؛ ولا تُمرر كوسيطة
للعملية، ولا تُكتب إلى Git، ولا تُنسخ من المضيف.

شغّل بيئة تشغيل Claude Code المعزولة:

```bash
./scripts/devin-bridge/launch
```

يعيد `launch` التحقق من العزل ومصادقة Devin واكتشاف النماذج قبل بدء
Claude Code داخل الحاوية. ولا يشغّل مطلقًا ملف Claude التنفيذي الخاص بالمضيف. يمكن تعيين الأسماء
البديلة للنماذج في `.env.devin-bridge`؛ ويجب أن تحتفظ كل قيمة مهيأة
بالبادئة `devin-cli-agentic/`.

## أوامر التحقق

لا يتطلب المسار غير المتصل القابل لإعادة الإنتاج حساب Devin، ولا يتوفر له اتصال بالإنترنت في وقت التشغيل:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

المسار المباشر الاختياري الذي يتطلب المصادقة هو:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ينتظر مشغّل الاختبارات المباشرة بين السيناريوهات لتجنب فتح جلسات ACP دفعة واحدة،
ويتحقق من أحداث تدفق Claude المهيكلة بدلًا من الوثوق بالادعاءات النصية. تثبت سيناريوهاته
الثلاثة ما يلي:

1. القراءة المباشرة للمشروع وتحليل العيوب؛
2. عملية `Edit` حقيقية، وأمر `Bash`‏ `npm test` مملوك للعميل، ونتيجة نهائية؛
3. اكتشاف `/bridge-check` و`bridge-proof`، وقراءة المشروع، وعملية `npm test` ناجحة أخرى
   مملوكة للعميل، والإكمال دون أعمال معلقة.

تتحقق البوابة النهائية أيضًا من تدقيق شبكة Devin، وتشترط أن يظل تدقيق خروج Claude
فارغًا.

## تحديث الأدوات المثبّتة بإصدارات محددة

تُثبّت الصورة Node وClaude Code وDevin CLI بإصدارات محددة في
`docker/devin-bridge/Dockerfile`. للتحديث:

1. غيّر الإصدارات المحددة صراحةً؛
2. استبدل قيمتي المجموع الاختباري لأرشيف Devin الخاصتين بكل معمارية بقيم الأثر الرسمي؛
3. أعد البناء وشغّل جميع أوامر التحقق دون اتصال؛
4. تأكد من الإصدارات داخل الصورة؛
5. أعد تشغيل مجموعة الاختبارات الحية الموثّقة ذات السيناريوهات الثلاثة.

لا تثبّت أيًا من أداتي CLI بصورة عامة على المضيف، ولا تستبدل التحقق من المجموع الاختباري بتنزيل
غير متحقق منه.

## التشخيص والتنظيف

- يعرض `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  التوجيه المحلي وأخطاء المنفّذ المنقّحة.
- يسجّل `.sandbox/evidence/mock-acp.jsonl` إجراءات ACP الوهمية الحتمية.
- يسجّل `.sandbox/evidence/claude-stream.jsonl` تشغيل Claude Code الحقيقي دون اتصال.
- تسجّل `.sandbox/evidence/live-*.jsonl` التدفقات الحية الثلاثة التي تم التحقق منها.
- يمثّل `.sandbox/evidence/egress.jsonl` و`.sandbox/evidence/claude-egress.jsonl` نسخًا متحققًا منها
  وخالية من الرموز المميزة لعمليات تدقيق الحماية.

أوقف الحاويات والشبكات المملوكة مع الحفاظ على وحدات تخزين تسجيل الدخول/الإعدادات:

```bash
./scripts/devin-bridge/clean
```

أزل البيئة الكاملة المملوكة للجسر، بما في ذلك وحدات التخزين المسماة:

```bash
./scripts/devin-bridge/clean --all
```

## القيود

- يعتمد الجسر على دور `summarizer` الثابت والخالي من الأدوات لأن Devin CLI `3000.2.17`
  لا يوفّر وكيل ACP محايدًا بلا أدوات. يعوّض المحوّل عن الاستجابات الوسيطة المصاغة كملخصات،
  لكن قد تظل محاولة إصلاح واحدة محدودة عرضة للفشل الصريح.
- قد تعيد استدعاءات ACP الحية استجابات `502`/`504` عابرة. تفصل أداة الاختبار بين السيناريوهات؛
  ويظل الفشل المستمر مغلقًا بصورة آمنة ولا يختار موفّرًا آخر أبدًا.
- يُعاد إنشاء سياق ACP من كل طلب Anthropic؛ ولا يوجد ارتباط بالعملية/الجلسة.
- يُدعَم استدعاء أداة واحد لكل استجابة من النموذج؛ وتُرفض الاستدعاءات المتوازية.
- الصور غير مدعومة صراحةً. ولا يُعلن عن الرؤية، أو مخرجات التفكير، أو عناصر التحكم في الجهد، أو نافذة سياق بحجم 1M.
- يستخدم SSE أحداث دورة حياة Anthropic صالحة، لكنه يُرسَل بعد جمع دورة ACP المحدودة؛
  ولا تُمرَّر أجزاء ACP تدريجيًا.
