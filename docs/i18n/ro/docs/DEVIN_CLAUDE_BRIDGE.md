`devin-cli-agentic` permite mediului de execuție real Claude Code să utilizeze endpointul local Anthropic
Messages al OmniRoute, în timp ce CLI-ul oficial Devin furnizează răspunsurile modelului prin ACP stdio. Acesta
nu modifică furnizorii existenți Anthropic, Claude OAuth, Claude Web sau `devin-cli`.

Pentru apelurile de instrumente gestionate de client, rutați prin `devin-cli-agentic` (alias `dva`),
furnizorul compatibil cu instrumente în format Claude. Executorul ACP moștenit `devin-cli` (`dv`) este
doar pentru text: acesta rulează rezumatorul Devin fără instrumente și nu poate returna apeluri de instrumente. Metadatele
modelului său sunt marcate corespunzător, astfel încât rutarea combo care necesită instrumente să îl evite.

> **Starea actuală: Claude Code fixat la `2.1.258`; validarea offline și live a fost înregistrată ultima dată
> pe `2.1.220`.** Versiunea fixată `2.1.220` a finalizat trei scenarii izolate prin Devin CLI
> `3000.2.17` și modelul `swe-1-7-lightning`; acea ultimă rulare live a demonstrat pași `Read`,
> `Edit` și `Bash` gestionați de client, rezultate `npm test` reușite, descoperirea comenzilor și a abilităților
> proiectului, rutare exclusiv prin Devin și zero trafic de ieșire către Claude. Versiunea fixată a fost apoi actualizată la `2.1.258`
> (generația CLI pe care o imită identitatea Claude a OmniRoute și prima linie care include
> nativ nivelul Fable 5.1). Pentru noua versiune fixată, stratul de instalare și `claude --version` au fost
> verificate pe imaginea de bază fixată, iar suita de teste unitare a punții, `compose config` și
> demonstrația statică de izolare trec — însă scenariul mock offline și suita live cu trei scenarii
> nu au fost rulate din nou încă. Rulați-le din nou (consultați „Actualizarea instrumentelor fixate”) înainte de a vă baza pe
> punte cu această versiune fixată.

## Arhitectură

```text
Claude Code 2.1.258 (container Linux izolat, fără privilegii root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (format Claude, furnizor fără autentificare)
  -> devin acp --agent-type summarizer (ACP stdio oficial, fără instrumente Devin)
  -> cont Devin în volumul dedicat devin-auth
```

Agentul ACP implicit al CLI-ului oficial își poate executa propriile instrumente, astfel încât această punte nu îl utilizează.
Aceasta pornește agentul ACP fix `summarizer`, al cărui mod CLI oficial nu are instrumente, și
încadrează cererea Anthropic serializată ca urmă de execuție. Când este necesară o altă
acțiune gestionată de Claude, răspunsul trebuie să conțină exact un plic de instrument al clientului. Orice
`tool_call` sau `tool_call_update` ACP este respins înainte ca un răspuns să poată fi raportat drept
reușit.

Serializatorul din `open-sse/executors/devin-agentic/serializer.ts` păstrează `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` și
instrumentele furnizate de Claude Code. Imaginile și blocurile necunoscute eșuează explicit. Rezultatele mari ale instrumentelor
utilizează un marcaj vizibil de trunchiere.

Parserul acceptă câte un singur plic autonom `<tool>{...}</tool>` pentru fiecare pas al modelului. Acesta verifică
numele în raport cu lista de instrumente a cererii, validează argumentele în raport cu JSON Schema al instrumentului,
respinge combinațiile de narațiune și acțiuni și permite o singură încercare limitată de remediere. Claude Code execută apoi
local rezultatul Anthropic `tool_use` și trimite `tool_result` înapoi prin
OmniRoute.

## Rutare automată

Furnizorul este eligibil în grupurile de candidați `auto/*` ale OmniRoute atunci când nu este blocat.
Eligibilitatea drept candidat nu garantează selectarea: strategia de rutare a combinației (de exemplu,
ultima variantă funcțională cunoscută) poate prefera un alt furnizor. Utilizați `dva/<model>` sau o combinație cu
Devin pe primul loc atunci când aveți nevoie ca fiecare cerere să treacă prin Devin.

## Izolarea și modelul de amenințări

Instalarea, contul și configurația Claude de pe gazdă sunt în afara domeniului de aplicare și sunt tratate ca
interzise. Serviciile Compose:

- rulează cu UID/GID `10001:10001`, cu un sistem de fișiere rădăcină doar în citire, capabilități eliminate și
  `no-new-privileges`;
- utilizează un `/home/bridge` privat, un volum dedicat pentru configurația Claude, date OmniRoute izolate
  și un volum `devin-auth` separat;
- montează doar spațiile de lucru/dovezile `.sandbox` de unică folosință;
- nu montează directorul personal al gazdei, Keychain, credențialele SSH, credențialele cloud sau socketul Docker;
- construiesc medii explicite și elimină variabilele API/OAuth/de rutare Anthropic;
- direcționează inferența Claude Code exclusiv către `http://omniroute:20128`, cu o cheie exclusiv locală.

Profilul offline utilizează o rețea internă. În profilul live, OmniRoute accesează
endpointurile oficiale Devin numai prin `network-guard`; destinațiile fără legătură sunt refuzate.
Claude Code are o protecție separată care interzice complet traficul de ieșire și poate accesa numai serviciul OmniRoute
local prin `NO_PROXY`. Fișierele de audit ale protecțiilor sunt montate numai de procesele lor de protecție. Scripturile
verifică proprietarul fișierelor, modul, numărul de legături și fiecare decizie înainte de a exporta
dovezi fără tokenuri.

Rulați independent demonstrația izolării:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Aceasta validează topologia, montările denumite, setările pentru utilizator non-root/doar în citire, rutarea locală explicită,
absența variabilelor de mediu sensibile, absența socketului Docker, accesul blocat la
`api.anthropic.com` și `claude.ai`, selectarea exclusivă a furnizorului Devin și eșecul explicit atunci când
backendul ACP nu este disponibil.

## Configurarea inițială și utilizarea normală

Construiți imaginea cu versiuni fixate:

```bash
./scripts/devin-bridge/build
```

Autentificați numai volumul Devin izolat:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Comanda de autentificare utilizează fluxul oficial cu token manual, destinat mediilor
la distanță/containerizate. Valoarea este introdusă direct în promptul CLI; nu este transmisă ca
argument al procesului, scrisă în Git sau copiată de pe gazdă.

Lansați mediul de execuție Claude Code izolat:

```bash
./scripts/devin-bridge/launch
```

`launch` reverifică izolarea, autentificarea Devin și descoperirea modelelor înainte de a porni
Claude Code containerizat. Nu rulează niciodată executabilul Claude al gazdei. Aliasurile modelelor pot fi
setate în `.env.devin-bridge`; fiecare valoare configurată trebuie să păstreze prefixul
`devin-cli-agentic/`.

## Comenzi de validare

Fluxul offline reproductibil nu necesită niciun cont Devin și nu are acces la Internet în timpul execuției:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Fluxul live autentificat, activat explicit, este:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Procesul de rulare live așteaptă între scenarii pentru a evita deschiderea în rafală a sesiunilor ACP și
validează evenimentele structurate din fluxul Claude în loc să acorde încredere afirmațiilor textuale. Cele trei
scenarii ale sale demonstrează:

1. citirea directă a proiectului și analiza defectelor;
2. o operațiune `Edit` reală, un `Bash` `npm test` deținut de client și un rezultat final;
3. `/bridge-check` împreună cu descoperirea `bridge-proof`, citirea proiectului, încă un
   `npm test` deținut de client și reușit și finalizarea fără activități în așteptare.

Verificarea finală controlează și auditul de rețea Devin și impune ca auditul traficului de ieșire Claude să
rămână gol.

## Actualizarea instrumentelor fixate

Imaginea fixează versiunile pentru Node, Claude Code și Devin CLI în
`docker/devin-bridge/Dockerfile`. Pentru actualizare:

1. modificați versiunile explicite;
2. înlocuiți ambele sume de control pentru arhivele Devin specifice arhitecturii cu valorile artefactului
   oficial;
3. reconstruiți și executați fiecare comandă de validare offline;
4. confirmați versiunile din imagine;
5. executați din nou suita live autentificată cu trei scenarii.

Nu instalați niciunul dintre cele două CLI-uri global pe gazdă și nu înlocuiți verificarea sumelor de control cu o
descărcare neverificată.

## Diagnosticare și curățare

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  afișează rutarea locală și erorile igienizate ale executorului.
- `.sandbox/evidence/mock-acp.jsonl` înregistrează acțiunile ACP simulate determinist.
- `.sandbox/evidence/claude-stream.jsonl` înregistrează rularea offline reală a Claude Code.
- `.sandbox/evidence/live-*.jsonl` înregistrează cele trei fluxuri live validate.
- `.sandbox/evidence/egress.jsonl` și `.sandbox/evidence/claude-egress.jsonl` sunt copii validate,
  fără tokenuri, ale auditurilor traficului de ieșire.

Opriți containerele și rețelele proprii, păstrând volumele de autentificare/configurare:

```bash
./scripts/devin-bridge/clean
```

Eliminați întregul mediu propriu punții, inclusiv volumele denumite:

```bash
./scripts/devin-bridge/clean --all
```

## Limitări

- Puntea se bazează pe rolul fix fără instrumente `summarizer`, deoarece Devin CLI `3000.2.17`
  nu expune un agent ACP neutru, fără instrumente. Adaptorul compensează răspunsurile intermediare
  sub formă de rezumat, dar o singură remediere limitată poate totuși eșua explicit.
- Apelurile ACP live pot returna răspunsuri tranzitorii `502`/`504`. Cadrul de testare spațiază scenariile;
  o eroare persistentă rămâne închisă în mod sigur și nu selectează niciodată alt furnizor.
- Contextul ACP este reconstruit din fiecare cerere Anthropic; nu există afinitate de proces/sesiune.
- Este acceptat un singur apel de instrument per răspuns al modelului; apelurile paralele sunt respinse.
- Imaginile nu sunt acceptate în mod explicit. Capabilitățile de vedere, rezultatul raționamentului, controalele de efort și o
  fereastră de context de 1M nu sunt prezentate ca fiind disponibile.
- SSE utilizează evenimente valide din ciclul de viață Anthropic, dar acestea sunt emise după colectarea
  schimbului ACP limitat; fragmentele ACP nu sunt redirecționate incremental.
