OmniRoute ਸ਼ੁਰੂਆਤ ਵੇਲੇ 5-ਪੜਾਅ ਵਾਲੀ ਫਾਲਬੈਕ ਲੜੀ ਰਾਹੀਂ ਆਪਣੇ SQLite ਡਰਾਈਵਰ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ:

1. **ਬੰਡਲ ਕੀਤਾ `better-sqlite3`** (`package.json` ਵਿੱਚ `dependencies` ਰਾਹੀਂ)
   — ਸਭ ਤੋਂ ਤੇਜ਼, ਨੇਟਿਵ ਬਾਈਨਰੀ, ਜਦੋਂ ਬਿਲਡ ਟੂਲ ਉਪਲਬਧ ਹੋਣ ਤਾਂ `npm install` ਦੁਆਰਾ ਇੰਸਟਾਲ ਹੁੰਦੀ ਹੈ।

2. **ਰਨਟਾਈਮ ਉੱਤੇ ਇੰਸਟਾਲ ਕੀਤਾ `better-sqlite3`** (`~/.omniroute/runtime/` ਵਿੱਚ)
   — ਪਹਿਲੀ ਵਾਰ ਚਲਾਉਣ ਵੇਲੇ ਲੋੜ ਅਨੁਸਾਰ **ਜਾਂ** `scripts/build/postinstall.mjs → scripts/postinstall.mjs` ਦੁਆਰਾ ਇੰਸਟਾਲ ਹੁੰਦਾ ਹੈ।
   ਖਰਾਬ ਜਾਂ ਗਲਤ ਪਲੇਟਫਾਰਮ ਵਾਲੀਆਂ ਬਾਈਨਰੀਆਂ ਤੋਂ ਬਚਾਅ ਲਈ ਲੋਡ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ
   ਨੇਟਿਵ `.node` ਮੈਜਿਕ ਬਾਈਟਾਂ (ELF / Mach-O / PE) ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ।

3. **`node:sqlite`** (Node ≥22.5 stdlib) — ਕਿਸੇ ਨੇਟਿਵ ਬਿਲਡ ਦੀ ਲੋੜ ਨਹੀਂ; ਜਦੋਂ
   better-sqlite3 ਦੇ ਦੋਵੇਂ ਪਾਥ ਅਸਫਲ ਹੋ ਜਾਣ ਤਾਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ। ਸੀਮਿਤ ਫੀਚਰ ਸੈੱਟ।

4. **`sql.js`** (WASM) — ਆਖਰੀ ਫਾਲਬੈਕ। ਹਰ ਥਾਂ ਕੰਮ ਕਰਦਾ ਹੈ, ਪਰ ਹੌਲੀ ਹੈ
   ਅਤੇ ਡਾਟਾ ਸਮਕਾਲੀ ਤੌਰ 'ਤੇ ਲਿਖਣ ਦੀ ਬਜਾਏ ਨਿਰਧਾਰਤ ਅੰਤਰਾਲ 'ਤੇ ਲਿਖਦਾ ਹੈ।

## ਇਹ ਜਟਿਲਤਾ ਕਿਉਂ ਹੈ?

- **Windows EBUSY**: ਜੇ ਪਿਛਲੇ ਵਰਜਨ ਦੀ `better_sqlite3.node` ਕਿਸੇ ਚੱਲ ਰਹੀ
  ਪ੍ਰਕਿਰਿਆ ਦੁਆਰਾ ਲਾਕ ਕੀਤੀ ਹੋਵੇ, ਤਾਂ `npm install -g omniroute@latest` ਅਸਫਲ ਹੋ ਸਕਦਾ ਹੈ।
  `~/.omniroute/runtime/` ਵਿੱਚ ਰਨਟਾਈਮ ਇੰਸਟਾਲ ਗਲੋਬਲ npm ਕੈਸ਼ ਨੂੰ ਬਾਈਪਾਸ ਕਰ ਦਿੰਦਾ ਹੈ।
- **ਬਿਲਡ ਟੂਲ ਨਾ ਹੋਣਾ**: ਕੁਝ ਵਾਤਾਵਰਣ (`VS Build Tools` ਤੋਂ ਬਿਨਾਂ ਕਾਰਪੋਰੇਟ Windows,
  ਘੱਟੋ-ਘੱਟ Docker ਇਮੇਜਾਂ) `better-sqlite3` ਨੂੰ ਕੰਪਾਇਲ ਨਹੀਂ ਕਰ ਸਕਦੇ। ਰਨਟਾਈਮ
  ਇੰਸਟਾਲਰ npm ਰਜਿਸਟਰੀ ਤੋਂ ਪਹਿਲਾਂ ਤੋਂ ਬਿਲਡ ਕੀਤੀ ਬਾਈਨਰੀ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ; ਜੇ ਇਹ ਵੀ
  ਅਸਫਲ ਹੋ ਜਾਵੇ, ਤਾਂ ਫਾਲਬੈਕ ਡਰਾਈਵਰ ਯਕੀਨੀ ਬਣਾਉਂਦੇ ਹਨ ਕਿ OmniRoute ਫਿਰ ਵੀ ਸ਼ੁਰੂ ਹੋਵੇ।
- **ਏਅਰ-ਗੈਪਡ ਸਿਸਟਮ**: ਜੇ npm ਰਜਿਸਟਰੀ ਤੱਕ ਪਹੁੰਚ ਨਾ ਹੋਵੇ, ਤਾਂ `node:sqlite`
  ਜਾਂ `sql.js` ਮੂਲ ਕਾਰਜਸ਼ੀਲਤਾ ਦੀ ਗਾਰੰਟੀ ਦਿੰਦੇ ਹਨ।

## ਮੈਜਿਕ-ਬਾਈਟ ਪੁਸ਼ਟੀ

ਰਨਟਾਈਮ ਉੱਤੇ ਇੰਸਟਾਲ ਕੀਤੀ `.node` ਫਾਈਲ ਲੋਡ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ, OmniRoute ਪਹਿਲੀਆਂ 8
ਬਾਈਟਾਂ ਪੜ੍ਹਦਾ ਹੈ ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਜਾਣੀਆਂ-ਪਛਾਣੀਆਂ ਪਲੇਟਫਾਰਮ ਮੈਜਿਕਾਂ ਨਾਲ ਮਿਲਾਉਂਦਾ ਹੈ:

| ਪਲੇਟਫਾਰਮ              | ਬਾਈਟਾਂ (hex)  | ਲੇਬਲ        |
| --------------------- | ------------- | ----------- |
| Linux                 | `7F 45 4C 46` | `elf`       |
| macOS 64-bit BE       | `FE ED FA CF` | `macho`     |
| macOS 64-bit LE       | `CF FA ED FE` | `macho-le`  |
| macOS fat (universal) | `CA FE BA BE` | `macho-fat` |
| Windows               | `4D 5A` (MZ)  | `pe`        |

ਮੈਜਿਕ ਦਾ ਮੇਲ ਨਾ ਹੋਣ 'ਤੇ → ਫਾਈਲ ਨੂੰ ਅਣਡਿੱਠਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਫਾਲਬੈਕ ਅਗਲੇ ਪੜਾਅ ਵੱਲ ਜਾਰੀ ਰਹਿੰਦਾ ਹੈ।

```bash
rm -rf ~/.omniroute/runtime
omniroute  # ਅਗਲੀ ਸ਼ੁਰੂਆਤ ਵੇਲੇ ਮੁੜ ਇੰਸਟਾਲ ਕਰੇਗਾ

# ਜਾਂਚੋ ਕਿ ਕਿਹੜਾ ਡਰਾਈਵਰ ਸਰਗਰਮ ਹੈ

```

## ਸਮਕਾਲੀ ਰੁਕਾਵਟਾਂ ਦੀ ਜਾਂਚ

`better-sqlite3` ਨਾਲ, ਸਮਕਾਲੀ ਅਡੈਪਟਰ ਟਾਈਮਿੰਗ ਨੂੰ ਚਾਲੂ ਕਰਨ ਲਈ ਸ਼ੁਰੂਆਤ ਤੋਂ ਪਹਿਲਾਂ
`OMNIROUTE_SQLITE_SLOW_MS=200` ਸੈੱਟ ਕਰੋ। ਮੂਲ ਰੂਪ ਵਿੱਚ ਇਹ ਬੰਦ ਹੁੰਦੀ ਹੈ। ਘੱਟੋ-ਘੱਟ
ਇੰਨੇ ਮਿਲੀਸਕਿੰਟ ਲੈਣ ਵਾਲੀ ਪੂਰੀ ਹੋਈ ਕਾਰਵਾਈ ਇੱਕ `[SQLITE-SLOW]` ਚੇਤਾਵਨੀ ਜਾਰੀ ਕਰਦੀ ਹੈ,
ਹਰੇਕ ਅਡੈਪਟਰ ਲਈ ਵੱਧ ਤੋਂ ਵੱਧ ਹਰ ਦਸ ਸਕਿੰਟ ਵਿੱਚ ਇੱਕ ਵਾਰ। ਚੇਤਾਵਨੀ ਵਿੱਚ ਸਿਰਫ਼ ਡਰਾਈਵਰ,
ਕਾਰਵਾਈ ਵਰਗ (`prepare`, `get`, `all`, `run`, `exec`, `pragma`, ਟ੍ਰਾਂਜ਼ੈਕਸ਼ਨ ਜਾਂ
ਰੱਖ-ਰਖਾਅ), ਅਤੇ ਬੀਤੇ ਮਿਲੀਸਕਿੰਟ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ: ਕੋਈ SQL, ਬਾਈਂਡਿੰਗਾਂ, ਕਤਾਰਾਂ, ਪਾਥ
ਜਾਂ ਅਪਵਾਦ ਟੈਕਸਟ ਨਹੀਂ।

ਇਹ ਇੱਕ ਨਿਦਾਨ ਸਹਾਇਤਾ ਹੈ, ਟਾਈਮਆਉਟ ਜਾਂ ਕਵੇਰੀ ਓਪਟੀਮਾਈਜ਼ੇਸ਼ਨ ਨਹੀਂ। ਇਹ ਅਜਿਹੀ ਕਾਰਵਾਈ
ਦੀ ਰਿਪੋਰਟ ਨਹੀਂ ਕਰ ਸਕਦੀ ਜੋ ਕਦੇ ਵਾਪਸ ਨਾ ਆਵੇ, CPU ਕੰਮ ਨੂੰ ਡਿਸਕ ਉਡੀਕਾਂ ਤੋਂ ਵੱਖ ਨਹੀਂ
ਕਰ ਸਕਦੀ, ਸਟੀਕ SQL ਦੀ ਪਛਾਣ ਨਹੀਂ ਕਰ ਸਕਦੀ, ਜਾਂ ਕੱਚੇ ਡਰਾਈਵਰ ਹੈਂਡਲ ਰਾਹੀਂ ਕੀਤੀਆਂ
ਕਾਰਵਾਈਆਂ ਨੂੰ ਨਹੀਂ ਦੇਖ ਸਕਦੀ। ਅਸਿੰਕ੍ਰੋਨਸ ਬੈਕਅੱਪ ਦੀ ਮਿਆਦ ਜਾਣਬੁੱਝ ਕੇ ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤੀ
ਗਈ; ਹੋਰ SQLite ਡਰਾਈਵਰ ਇਸ ਚੋਣਵੀਂ ਇੰਸਟਰੂਮੈਂਟੇਸ਼ਨ ਦੇ ਅਧੀਨ ਨਹੀਂ ਹਨ। ਵੇਰੀਏਬਲ ਨੂੰ
ਅਯੋਗ ਕਰਨ ਨਾਲ ਟਾਈਮਿੰਗ ਰੈਪਰਾਂ ਤੋਂ ਬਿਨਾਂ ਮੂਲ ਅਡੈਪਟਰ ਮੁੜ ਬਹਾਲ ਹੋ ਜਾਂਦਾ ਹੈ। ਡਾਟਾਬੇਸ
ਸਕੀਮਾ ਜਾਂ ਸਟੋਰ ਕੀਤੀ ਸੰਰਚਨਾ ਵਿੱਚ ਕੋਈ ਬਦਲਾਅ ਨਹੀਂ ਹੁੰਦਾ।

`/healthz` ਲੈਗ ਚੇਤਾਵਨੀ ਪਿਛਲੇ ਨਮੂਨੇ ਤੋਂ ਬਾਅਦ ਦਾ ਇਵੈਂਟ-ਲੂਪ ਸਿਖਰ ਦਰਸਾਉਂਦੀ ਹੈ,
ਪੂਰੇ ਜੀਵਨਕਾਲ ਦੀ ਔਸਤ ਨਹੀਂ। ਕਿਸੇ ਰੁਕਾਵਟ ਨੂੰ SQLite ਜਾਂ ਡਿਸਕ ਅਸਫਲਤਾ ਨਾਲ ਜੋੜਨ ਤੋਂ
ਪਹਿਲਾਂ ਇਸ ਦੇ ਟਾਈਮਸਟੈਂਪਾਂ ਨੂੰ ਹੌਲੀ-ਕਾਰਵਾਈ ਚੇਤਾਵਨੀਆਂ ਅਤੇ ਹੋਸਟ/ਸਟੋਰੇਜ ਮੈਟ੍ਰਿਕਾਂ
ਨਾਲ ਮਿਲਾਓ।

## ਹਵਾਲਾ

ਲਾਗੂਕਰਨ:

- `bin/cli/runtime/magicBytes.mjs` — ਬਾਈਨਰੀ ਮੈਜਿਕ-ਬਾਈਟ ਪੁਸ਼ਟੀ ਸਹਾਇਕ
- `bin/cli/runtime/sqliteRuntime.mjs` — 5-ਪੜਾਅ ਰਨਟਾਈਮ ਰਿਜ਼ਾਲਵਰ + ਲੋੜ ਅਨੁਸਾਰ ਇੰਸਟਾਲਰ
- `bin/cli/runtime/index.mjs` — ਸ਼ੁਰੂਆਤੀ ਆਰਕੈਸਟਰੇਟਰ (`warmUpRuntimes()`)
- `scripts/postinstall.mjs` — npm ਪੋਸਟ-ਇੰਸਟਾਲ ਹੁੱਕ (ਗੈਰ-ਘਾਤਕ ਵਾਰਮ-ਅੱਪ)
- `src/lib/db/core.ts` — `ensureDbInitialized()` / `getDriverInfo()` ਐਕਸਪੋਰਟ

## ਇਕਹਿਰਾ-ਰਾਈਟਰ ਟੋਪੋਲੋਜੀ (HA ਅਸਮਰਥਿਤ)

ਉਪਰੋਕਤ ਡਰਾਈਵਰ ਫਾਲਬੈਕ ਲੜੀ ਫਿਰ ਵੀ **ਇੱਕ ਪ੍ਰਕਿਰਿਆ** ਵਿੱਚ ਚੱਲਦੀ ਹੈ। ਮੂਲ SQLite
OmniRoute ਇੱਕ **ਇਕਹਿਰਾ ਰਾਈਟਰ** ਹੈ:

- ਦੋ OmniRoute ਰੈਪਲਿਕਾਵਾਂ ਨੂੰ ਇੱਕੋ `storage.sqlite` ਫਾਈਲ ਨਾਲ ਨਾ ਜੋੜੋ।
- ਕੰਟੇਨਰ ਰੀਸਟਾਰਟ, Recreate ਡਿਪਲੋਇ, OOM kill, ਜਾਂ HEALTHCHECK ਰੀਸਟਾਰਟ ਹਰ
  ਚੱਲ ਰਹੇ SSE ਸੈਸ਼ਨ ਨੂੰ ਖਤਮ ਕਰ ਦਿੰਦਾ ਹੈ। ਮਿਆਰੀ ਪਾਥ ਉੱਤੇ ਕੋਈ ਸੈਸ਼ਨ ਡਰੇਨ ਨਹੀਂ ਹੈ।
