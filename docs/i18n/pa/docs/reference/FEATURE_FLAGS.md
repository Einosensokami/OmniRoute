> ਉਸ ਫਾਈਲ ਤੋਂ ਪੜ੍ਹਦੇ ਹਨ, ਇਸਲਈ ਹੇਠਾਂ ਦਿੱਤੀ ਸਾਰਣੀ ਇਸ ਨਾਲ 1:1 ਮੇਲ ਕਰਨ ਲਈ ਤਿਆਰ ਕੀਤੀ
> ਗਈ ਹੈ।

## ਫੀਚਰ ਫਲੈਗ ਕੀ ਹਨ

ਇੱਕ ਫੀਚਰ ਫਲੈਗ ਇੱਕ ਨਾਮੀ ਟੌਗਲ (ਬੂਲੀਅਨ ਜਾਂ ਐਨਮ) ਹੈ ਜਿਸਦਾ ਮੁੱਲ ਰਨਟਾਈਮ 'ਤੇ ਬਦਲਿਆ
ਜਾ ਸਕਦਾ ਹੈ ਅਤੇ ਡੇਟਾਬੇਸ ਵਿੱਚ ਸਥਾਈ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ, ਜਿਸ ਲਈ ਕਿਸੇ ਪ੍ਰਕਿਰਿਆ ਨੂੰ
ਮੁੜ-ਤੈਨਾਤ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ। ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਇੱਕ `FeatureFlagDefinition` ਦੁਆਰਾ
ਵਰਣਨ ਕੀਤਾ ਗਿਆ ਹੈ ਜਿਸ ਵਿੱਚ ਇੱਕ `key`, `label`, `description`, `category`,
`defaultValue`, `type`, ਅਤੇ ਇੱਕ `requiresRestart` ਸੰਕੇਤ ਸ਼ਾਮਲ ਹਨ।

### ਰੈਜ਼ੋਲੂਸ਼ਨ ਆਰਡਰ

ਇੱਕ ਫਲੈਗ ਦਾ **ਪ੍ਰਭਾਵੀ ਮੁੱਲ** [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)
ਦੁਆਰਾ ਇਸ ਤਰਜੀਹ (ਸਭ ਤੋਂ ਉੱਚਾ ਜਿੱਤਦਾ ਹੈ) ਨਾਲ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

1. **DB ਓਵਰਰਾਈਡ** — `key_value` ਸਾਰਣੀ ਵਿੱਚ `feature_flags` ਨਾਮਸਪੇਸ ਦੇ ਅਧੀਨ
   ਸਟੋਰ ਕੀਤਾ ਗਿਆ ਇੱਕ ਮੁੱਲ (ਡੈਸ਼ਬੋਰਡ ਜਾਂ REST API ਰਾਹੀਂ ਸੈੱਟ ਕੀਤਾ ਗਿਆ)।
2. **ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ** — `process.env[<KEY>]`, ਜੇਕਰ ਸੈੱਟ ਕੀਤਾ ਗਿਆ ਹੈ ਅਤੇ ਖਾਲੀ
   ਨਹੀਂ ਹੈ।
3. **ਪਰਿਭਾਸ਼ਾ ਡਿਫੌਲਟ** — `featureFlagDefinitions.ts` ਤੋਂ `defaultValue`।

ਇੱਕ ਬੂਲੀਅਨ ਫਲੈਗ ਨੂੰ **ਸਮਰੱਥ** ਮੰਨਿਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਇਸਦਾ ਪ੍ਰਭਾਵੀ ਮੁੱਲ `"true"`,
`"1"`, ਜਾਂ `"yes"` ਹੁੰਦਾ ਹੈ (ਦੇਖੋ `isFeatureFlagEnabled()`)।

> [!NOTE]
> ਜ਼ਿਆਦਾਤਰ ਫਲੈਗਾਂ ਵਿੱਚ [`ENVIRONMENT.md`](./ENVIRONMENT.md) ਵਿੱਚ ਦਸਤਾਵੇਜ਼ੀ
> **ਉਸੇ ਨਾਮ** ਦਾ ਇੱਕ ਮੇਲ ਖਾਂਦਾ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਵੀ ਹੁੰਦਾ ਹੈ। ਫਲੈਗ ਦਾ DB
> ਓਵਰਰਾਈਡ ਉਸ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ 'ਤੇ ਤਰਜੀਹ ਲੈਂਦਾ ਹੈ। `requiresRestart: true` ਵਾਲਾ
> ਇੱਕ ਫਲੈਗ ਤੁਰੰਤ ਸਥਾਈ ਹੋ ਜਾਂਦਾ ਹੈ ਪਰ ਸਿਰਫ ਪ੍ਰਕਿਰਿਆ ਸ਼ੁਰੂ ਹੋਣ 'ਤੇ ਮੁੜ-ਪੜ੍ਹਿਆ
> ਜਾਂਦਾ ਹੈ — ਇਸਨੂੰ ਟੌਗਲ ਕਰਨ ਨਾਲ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਇੱਕ **"ਸਰਵਰ ਮੁੜ-ਚਾਲੂ ਕਰੋ"** ਬੈਨਰ
> ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ।

## ਫਲੈਗ ਟੌਗਲ ਕਰਨਾ

### ਡੈਸ਼ਬੋਰਡ

**Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`) 'ਤੇ ਜਾਓ। ਗ੍ਰਿਡ
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ਇਹਨਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

- ਕੁੰਜੀ ਜਾਂ ਵਰਣਨ ਦੁਆਰਾ **ਖੋਜ**, ਅਤੇ ਸ਼੍ਰੇਣੀ ਦੁਆਰਾ **ਫਿਲਟਰ** (ਨਾਲ ਹੀ ਇੱਕ ਕ੍ਰਿਤ੍ਰਿਮ
  **Requires Restart** ਦ੍ਰਿਸ਼)।
- ਬੂਲੀਅਨ ਫਲੈਗਾਂ ਲਈ ਇੱਕ **ਟੌਗਲ** ਅਤੇ enum ਫਲੈਗਾਂ ਲਈ ਇੱਕ **ਡ੍ਰੌਪਡਾਊਨ**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- ਹਰੇਕ ਫਲੈਗ ਲਈ ਇੱਕ **ਸਰੋਤ ਬੈਜ** — `DB`, `ENV`, ਜਾਂ `DEF` — ਜੋ ਦਿਖਾਉਂਦਾ ਹੈ ਕਿ
  ਪ੍ਰਭਾਵੀ ਮੁੱਲ ਕਿੱਥੋਂ ਆਇਆ ਹੈ।
- ਓਵਰਰਾਈਡ ਹਟਾਉਣ ਲਈ ਇੱਕ **Reset** ਬਟਨ (ਕੇਵਲ `DB` ਤੋਂ ਪ੍ਰਾਪਤ ਫਲੈਗਾਂ ਲਈ ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ),
  ਅਤੇ ਹੇਠਾਂ ਇੱਕ **Reset All Overrides** ਬਟਨ।
- ਜਦੋਂ `requiresRestart` ਫਲੈਗ ਬਦਲਿਆ ਜਾਂਦਾ ਹੈ ਤਾਂ ਇੱਕ **Restart Server** ਬੈਨਰ।

### REST API

ਸਾਰੀਆਂ ਕਾਰਵਾਈਆਂ ਇੱਕੋ ਰੂਟ ਰਾਹੀਂ ਹੁੰਦੀਆਂ ਹਨ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
ਹਰੇਕ ਵਿਧੀ ਲਈ ਪ੍ਰਮਾਣਿਤ ਡੈਸ਼ਬੋਰਡ ਸੈਸ਼ਨ ਲੋੜੀਂਦਾ ਹੈ (ਨਹੀਂ ਤਾਂ `401`)।

#### `GET /api/settings/feature-flags`

ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਉਸਦੇ ਪ੍ਰਭਾਵੀ ਮੁੱਲ, ਸਰੋਤ ਅਤੇ ਸਾਰ ਸਮੇਤ ਵਾਪਸ ਕਰਦਾ ਹੈ।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... ਸਾਰੇ 108 ਫਲੈਗ
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ਇੱਕ ਓਵਰਰਾਈਡ ਸੈੱਟ ਕਰੋ ਜਾਂ ਹਟਾਓ। ਬੌਡੀ: `{ key: string; value?: string }`।
`value` ਨੂੰ ਛੱਡਣ ਨਾਲ ਓਵਰਰਾਈਡ ਹਟ ਜਾਂਦਾ ਹੈ (env / ਡਿਫੌਲਟ ਨੂੰ ਮੁੜ ਬਹਾਲ ਕਰਦਿਆਂ)।

```bash
# ਇੱਕ DB ਓਵਰਰਾਈਡ ਸੈੱਟ ਕਰੋ
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ਓਵਰਰਾਈਡ ਹਟਾਓ (ਕੋਈ "value" ਨਹੀਂ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ਜਵਾਬ ਨਵੇਂ `effectiveValue`/`source`, `previousValue`/
`previousSource`, ਅਤੇ `requiresRestart` ਨੂੰ ਵਾਪਸ ਦਰਸਾਉਂਦਾ ਹੈ। ਅਣਜਾਣ ਕੁੰਜੀਆਂ ਅਤੇ ਸੀਮਾ ਤੋਂ ਬਾਹਰਲੇ enum
ਮੁੱਲਾਂ ਨੂੰ `400` ਨਾਲ ਅਸਵੀਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

#### `DELETE /api/settings/feature-flags`

ਸਾਰੇ DB ਓਵਰਰਾਈਡ ਇੱਕੋ ਵਾਰ ਸਾਫ਼ ਕਰਦਾ ਹੈ ਅਤੇ ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਉਸਦੇ env / ਡਿਫੌਲਟ
ਮੁੱਲ 'ਤੇ ਮੁੜ ਬਹਾਲ ਕਰਦਾ ਹੈ। `{ cleared: <count>, message: "..." }` ਵਾਪਸ ਕਰਦਾ ਹੈ।

> [!NOTE]
> `requiresRestart: true` ਵਾਲੇ ਫਲੈਗ ਸਿਰਫ਼ ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਮੁੜ ਲੋਡ ਕਰਨ ਤੋਂ ਬਾਅਦ ਹੀ ਪ੍ਰਭਾਵੀ ਹੁੰਦੇ ਹਨ।
> ਡੈਸ਼ਬੋਰਡ ਦਾ ਰੀਸਟਾਰਟ ਪ੍ਰਵਾਹ `POST /api/restart` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ ਅਤੇ ਫਿਰ ਸਰਵਰ ਦੇ ਮੁੜ ਚਾਲੂ ਹੋਣ ਤੱਕ
> `GET /api/health/ping` ਨੂੰ ਪੋਲ ਕਰਦਾ ਹੈ।

## ਐਮਰਜੈਂਸੀ ਬਜਟ ਫਾਲਬੈਕ

`OMNIROUTE_EMERGENCY_FALLBACK` (ਸ਼੍ਰੇਣੀ `runtime`, ਡਿਫਾਲਟ `true`)  
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts) ਵਿੱਚ ਐਮਰਜੈਂਸੀ ਮੁਫ਼ਤ-ਫਾਲਬੈਕ ਮਾਰਗ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ।
ਸਮਰੱਥ ਹੋਣ 'ਤੇ, ਜਿਹੜੀਆਂ ਬੇਨਤੀਆਂ ਆਪਣਾ ਬਜਟ ਖ਼ਤਮ ਕਰ ਲੈਂਦੀਆਂ ਹਨ, ਉਹਨਾਂ ਨੂੰ ਸਿੱਧੇ ਅਸਫਲ ਕਰਨ ਦੀ ਬਜਾਏ ਕਿਸੇ ਮੁਫ਼ਤ ਫਾਲਬੈਕ ਪ੍ਰਦਾਤਾ/ਮਾਡਲ ਵੱਲ ਰੂਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇਸ ਵਿਹਾਰ ਨੂੰ ਅਸਮਰੱਥ ਕਰਨ ਅਤੇ ਬਜਟ ਖ਼ਤਮ ਕਰ ਚੁੱਕੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਅਸਫਲ ਹੋਣ ਦੇਣ ਲਈ—ਡੈਸ਼ਬੋਰਡ ਟੌਗਲ, DB ਓਵਰਰਾਈਡ, ਜਾਂ `OMNIROUTE_EMERGENCY_FALLBACK` ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਰਾਹੀਂ—ਇਸਨੂੰ `false` (ਜਾਂ `0`) 'ਤੇ ਸੈੱਟ ਕਰੋ। (PRs #3741 / #3752 ਵਿੱਚ ਡੈਸ਼ਬੋਰਡ ਟੌਗਲ ਵਜੋਂ ਉਪਲਬਧ ਕਰਵਾਇਆ ਗਿਆ।)

ਇਸ ਫਾਲਬੈਕ ਰਾਹੀਂ ਦਿੱਤੇ ਗਏ ਜਵਾਬ ਵਿੱਚ
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ਹੁੰਦਾ ਹੈ, ਤਾਂ ਜੋ ਕਲਾਇੰਟ ਆਪਣੀ ਬੇਨਤੀ ਨਾਲ `X-OmniRoute-Provider` ਦੀ ਤੁਲਨਾ ਕੀਤੇ ਬਿਨਾਂ ਇਹ ਜਾਣ ਸਕੇ ਕਿ ਇਸਨੂੰ ਮੁੜ ਰੂਟ ਕੀਤਾ ਗਿਆ ਸੀ। ਹਰ ਹੋਰ ਜਵਾਬ ਵਿੱਚ ਇਹ ਹੈਡਰ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦਾ।
